Executive Summary

四种架构，四种“怎么记住上下文”

它们的主要差异不在参数规模，而在于精确 token 寻址与压缩状态记忆如何分工。

01 · INTER-LAYER

Jamba‑1.5

Transformer、Mamba 与 MoE 三者组合；大部分层用固定状态处理序列，少数全注意力层负责精确读取。

7× Mamba → 1× Attention
02 · INTRA-LAYER

Falcon‑H1

每个 block 中 Attention heads 与 Mamba‑2 heads 并行工作，以可调头数控制精确寻址与状态记忆的比例。

Attention ∥ Mamba‑2
03 · RECURRENT

RWKV‑7 Goose

完全取消 Attention 和 KV cache，把上下文写入固定大小的矩阵状态，形成随 token 动态更新的 fast weights。

stateₜ = update(stateₜ₋₁, xₜ)
04 · LINEAR HYBRID

MiniMax‑Text‑01

7× Lightning → 1× Softmax

Inter-layer Hybrid

Jamba‑1.5：三种稀疏同时出现

把时间维压缩、精确检索和参数容量分别交给 Mamba、Attention 与 MoE。

01

Jamba‑1.5 Large 由 9 个 block 组成，每个 block 8 层；Attention 与 Mamba 的层数比例为 1:7。每两层用一次 MoE 代替普通 MLP，配置为 16 个专家、Top‑2 路由。

[ Mamba × 7 → Full Attention × 1 ] × 9 └─ 每 2 层：16 Experts / Top‑2 MoE

模型把三类成本拆开：Mamba 以固定状态连续处理历史；全注意力层保留原始 token 的精确寻址；MoE 在不同比例增加单 token 计算的前提下扩大知识容量。

关键观察官方消融中，纯 Mamba‑2 优于纯 Mamba‑1，但放进混合架构后，Mamba‑1 + Attention 反而更好。局部最优算子并不保证系统组合最优。
它与 Kimi / Qwen 混合架构的关系

Jamba 更接近“SSM + Transformer”的早期成熟范式，可以作为 KDA、Gated DeltaNet 等混合线性架构的前史：都依赖少量全注意力层弥补固定状态模型的精确检索损失。

  • 层组织9 blocks × 8 layers
  • Attention : Mamba1 : 7
  • MoE16 experts / Top‑2，每 2 层一次
  • 参数398B 总参数 / 94B 激活
  • 上下文256K
  • KV cache只在少量 Attention 层增长

Intra-layer Hybrid

Falcon‑H1：同层并行的 Hybrid Heads

Attention 和 Mamba‑2 不再轮流出现，而是在同一 block 内并行处理输入。

02

Falcon‑H1 将完整注意力头与 Mamba‑2 头放在同一个 mixer block 中，两路输出融合后进入输出投影。两类头的数量可独立调节，因此“注意力预算”从层比例变成了头比例。

┌─ Full Attention heads ─┐ Input → RMSNorm ─┤ ├→ Fuse / O-Proj → FFN └─ Mamba‑2 heads ───────┘

以 34B 版本为例，每层有 20 个 Attention Q 头和 32 个 Mamba‑2 头。它不像 Jamba 那样周期性“刷新”全局信息，而是让精确寻址和状态记忆在每一层持续协作。

设计边界因为每层仍存在部分 Attention heads，KV cache 依旧随上下文增长；节省来自 KV 头较少和 SSM 分担计算，而非完全实现常数内存。
为什么超大的 RoPE theta 值值得注意

34B 配置使用 1e11 的 RoPE theta。团队推测，SSM 已原生承担一部分顺序信息，因此注意力分支可以使用更缓慢的位置旋转，把更多维度留给长距离内容匹配。

  • 规模34B dense
  • 层数 / 隐藏维72 / 5120
  • Attention heads20 Q / 4 KV
  • Mamba‑2 heads32，state size 256
  • 位置编码RoPE theta = 1e11
  • 上下文256K

Attention-free Recurrent

RWKV‑7 Goose：彻底取消 Attention

把上下文压缩成持续演化的矩阵状态，同时保留训练时的序列并行能力。

03

RWKV‑7 是纯 RNN 架构，没有 Softmax Attention 和 KV cache。每层维护固定大小的多头矩阵状态，用 Generalized Delta Rule 决定忘掉什么、覆盖什么以及写入什么。

Stateₜ₋₁ ── decay / remove ──┐ ├→ Stateₜ → receptance read → output Tokenₜ ───── key / value write ┘

其中逐通道的 wₜ 类似遗忘门，aₜ 类似上下文内部更新的学习率；删除旧记忆与写入新记忆还可以使用不同的 key。状态因此可理解为模型在推理时不断更新的“小型键值模型”。

核心取舍推理每 token 的计算时间和状态大小不随已有上下文长度增长，但固定状态必然压缩历史，对逐字回看和高精度检索的天然支持弱于保留全注意力层的混合模型。
为什么它又像 RNN，又像线性注意力

训练时，状态更新可以重写成可并行的矩阵前缀计算；推理时则按 token 递归更新。因此它兼具 Transformer 式训练并行和 RNN 式常数状态推理，但信息表示仍属于有损压缩。

  • Token mixerGeneralized Delta Rule
  • Attention无
  • KV cache无
  • 推理状态固定大小的矩阵 fast weights
  • 公开规模0.19B–2.9B（论文系列）
  • 许可Apache 2.0

Linear Attention at Scale

MiniMax‑Text‑01：规模化实验与架构回撤

它既证明了线性注意力能扩展到商业级模型，也揭示了理论效率之外的隐藏成本。

04

MiniMax‑Text‑01 共 80 层，每 7 个 Lightning Attention 层后插入 1 个 Softmax Attention 层；FFN 使用 32 专家 Top‑2 MoE。训练上下文达到 1M，推理声明可外推到 4M。

[ Lightning Attention × 7 → Softmax Attention × 1 ] × 10 └─ 32 Experts / Top‑2 MoE

Lightning Attention 将计算拆为块内和块间：块内保留因果 token 交互，块间只传递累积的 KᵀV 状态；配合分块和 IO-aware kernel，避免传统线性注意力的串行累加与频繁显存访问。

最值得讲的后续MiniMax 后续在 M2 上回到全注意力，原因包括复杂多跳推理的隐性损失、低精度状态敏感、Prefix Cache 与投机解码基础设施不成熟。低理论复杂度并不自动等于更低线上成本。
“没有免费午餐”体现在哪里

线性状态擅长低成本概括历史，但精确 token-to-token 关系可能被压缩。增加全注意力比例可以补质量，却又会重新引入 KV cache 与二次复杂度；最终需要在能力、硬件利用率和服务生态之间共同优化。

  • 参数456B 总参数 / 45.9B 激活
  • 层数80
  • Attention 比例7 Lightning : 1 Softmax
  • MoE32 experts / Top‑2
  • Attention heads64 × 128
  • 上下文1M 训练 / 4M 推理外推
