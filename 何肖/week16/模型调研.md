## 1. 调研口径

### 1.1 “开源模型”与“开放权重”

本文统一使用“开放权重模型”这一更精确的称呼。模型能够下载权重，不一定意味着其训练数据、完整训练代码及许可证都符合 OSI 对开源软件的定义。不同模型的许可证也不完全相同，落地前仍需单独核查商用、再分发和衍生模型条款。

### 1.2 参数量的含义

- **总参数量**决定权重存储、下载规模以及完整加载所需的内存或显存。
- **激活参数量**主要反映 MoE 模型每个 token 实际参与前向计算的参数规模。
- 激活参数较少不代表模型能够只加载激活专家；常规部署通常仍需保存全部专家权重。
- Dense 模型每层参数都参与计算，因此“总参数量”和“激活参数量”基本相同。

### 1.3 注意力术语

- **MLA**：Multi-head Latent Attention，通过低秩潜变量压缩 KV 表示，主要降低 KV Cache。
- **Gated DeltaNet / KDA**：带门控的线性注意力，以递归状态代替对全部历史 token 做完整 softmax 注意力。
- **DSA**：DeepSeek Sparse Attention，使用轻量索引器从历史 token 中选择 Top-k，再执行核心注意力。
- **CSA / HCA**：DeepSeek-V4 的两类压缩注意力。CSA 先压缩 KV，再做稀疏选择；HCA 更强地压缩 KV，但对压缩后的条目执行稠密注意力。
- **MTP**：Multi-Token Prediction，可作为训练目标，也可为投机解码提供草稿预测。

### 2.2 一句话理解

- **DeepSeek-V3**：用 MLA 压缩 KV Cache，用细粒度 MoE 控制每 token 的计算量。
- **DeepSeek-V4**：在 V3 的 MoE 基础上，进一步对序列维度做压缩和稀疏化，目标是高效处理 1M 上下文。
- **GLM-5.2**：使用 DSA 选择 Top-2048 历史位置，并让相邻四层共享索引结果，减少索引器重复计算。
- **Kimi-K3**：用 KDA 处理大部分层、Gated MLA 保留全局建模能力，再用超稀疏 LatentMoE 扩大总容量。
- **Qwen3.6 / 3.8**：以“3 层线性注意力 + 1 层全注意力”为固定节奏，兼顾长上下文效率和精确检索。

## 3. DeepSeek 系列

### 3.1 DeepSeek-V3

#### 基本结构

| 项目 | 配置 |
|---|---|
| 架构 | Decoder-only Transformer + DeepSeekMoE |
| 总参数 / 激活参数 | 671B / 37B |
| 主体层数 | 61 |
| Hidden size | 7,168 |
| 注意力 | MLA，128 个注意力头 |
| Query 压缩 | `q_lora_rank = 1536` |
| KV 压缩 | `kv_lora_rank = 512` |
| QK 维度 | 128 维 NoPE + 64 维 RoPE |
| Value 维度 | 128 |
| FFN | 前 3 层 Dense；其余层 MoE |
| MoE | 256 个路由专家，Top-8 + 1 个共享专家 |
| 专家中间维度 | 2,048 |
| MTP | 1 层 |
| 精度 | 官方权重以 FP8 为主 |

#### 结构特点

1. **MLA 压缩 KV Cache**  
   DeepSeek-V3 不直接为每个注意力头保存完整 K/V，而是先把 KV 压缩到 512 维潜变量。解码时可以显著降低长序列的 KV Cache 占用。

2. **细粒度 DeepSeekMoE**  
   模型拥有 256 个路由专家，但每个 token 只选择 8 个，并额外使用 1 个共享专家。共享专家负责吸收通用知识，路由专家承担差异化表示。

3. **无辅助损失负载均衡**  
   路由使用 sigmoid 打分和校正偏置实现专家负载均衡，避免较强的 auxiliary loss 直接干扰主训练目标。

4. **MTP 训练目标**  
   除下一个 token 外，模型还训练额外的后续 token 预测模块。该模块既能改善训练信号，也能用于投机解码。

#### 上下文长度说明

官方模型卡标称 **128K** 上下文；当前官方 `config.json` 中 `max_position_embeddings` 为 **163,840**，并配置了 YaRN 扩展。两者属于“产品标称窗口”和“内部配置上限”两个不同口径，部署时不应直接把 163,840 当作官方保证的有效上下文长度。

### 3.2 DeepSeek-V4-Pro

#### 基本结构

| 项目 | 配置 |
|---|---|
| 总参数 / 激活参数 | 1.6T / 49B |
| 主体层数 | 61 |
| Hidden size | 7,168 |
| 注意力 | CSA + HCA 混合架构 |
| Query heads | 128 |
| Shared KV heads | 1（MQA 风格） |
| Attention head dim | 512 |
| 索引器 | 64 头，Top-1024 |
| MoE | 384 个路由专家，Top-6 + 1 个共享专家 |
| 专家中间维度 | 3,072 |
| 前置路由 | 前 3 层使用 Hash routing |
| 残差结构 | mHC，残差流扩展倍数 4 |
| 上下文 | 1,048,576 |
| MTP | 1 层；新版检查点另附 DSpark 投机解码模块 |

#### 结构特点

1. **CSA：先压缩，再稀疏选择**  
   CSA 将连续 token 的 KV 条目按块压缩，Pro 的常见压缩率为 4；随后使用 lightning indexer 从压缩后的历史条目中选择 Top-1024。核心注意力只处理被选中的条目与局部滑动窗口。

2. **HCA：更强压缩，压缩后做稠密注意力**  
   HCA 常见压缩率为 128。它不再对压缩条目做 Top-k 稀疏选择，而是对大幅缩短后的序列进行稠密注意力。CSA 与 HCA 交替使用，以平衡精细检索和超长上下文效率。

3. **局部窗口补偿压缩损失**  
   CSA 和 HCA 都增加 128-token 的未压缩滑动窗口，让模型保留最近邻 token 的细粒度关系。

4. **mHC 超连接**  
   mHC 将一条残差流扩展为 4 条，并通过受约束的输入、输出和残差映射进行组合。残差映射由 Sinkhorn-Knopp 迭代投影为双随机矩阵，目的是在扩大残差通道容量的同时维持训练稳定性。

5. **低精度部署设计**  
   后训练版本的 MoE 专家采用 FP4，其他主要部分采用 FP8；索引器 QK 路径也进行了低精度优化。这是 V4 长上下文效率的重要组成部分，而不仅是权重压缩手段。

### 3.3 DeepSeek-V4-Flash

#### 基本结构

| 项目 | 配置 |
|---|---|
| 总参数 / 激活参数 | 284B / 13B |
| 主体层数 | 43 |
| Hidden size | 4,096 |
| 注意力 | CSA + HCA 混合架构 |
| Query heads | 64 |
| Shared KV heads | 1 |
| Attention head dim | 512 |
| 索引器 | 64 头，Top-512 |
| MoE | 256 个路由专家，Top-6 + 1 个共享专家 |
| 专家中间维度 | 2,048 |
| 前置路由 | 前 3 层使用 Hash routing |
| 残差结构 | mHC，残差流扩展倍数 4 |
| 上下文 | 1,048,576 |
| MTP | 1 层；新版检查点另附 DSpark |

#### 与 Pro 的核心差异

- Flash 不是 Pro 的量化版，而是独立训练的较小 MoE 模型。
- 层数从 61 降到 43，hidden size 从 7,168 降到 4,096。
- 路由专家从 384 降到 256，索引 Top-k 从 1,024 降到 512。
- 激活参数只有 13B，因此单位 token 计算成本明显低于 Pro。
- 二者共享 CSA、HCA、mHC、Hash routing、MTP 和 FP4/FP8 混合精度等设计。

### 3.4 DeepSeek 系列演进

```text
DeepSeek-V3
  MLA 压缩 KV + DeepSeekMoE + MTP
          ↓
DeepSeek-V4
  CSA/HCA 压缩序列 + 稀疏选择
  + mHC 残差扩展
  + 更低精度的专家与索引器
  + 原生 1M 上下文
```

## 4. GLM-5.2

### 基本结构

| 项目 | 配置 |
|---|---|
| 架构 | `GlmMoeDsaForCausalLM` |
| 总参数 / 激活参数 | 744B / 40B |
| 主体层数 | 78 |
| Hidden size | 6,144 |
| 注意力 | MLA + DSA |
| 注意力头 | 64 |
| Q 压缩 | `q_lora_rank = 2048` |
| KV 压缩 | `kv_lora_rank = 512` |
| QK 维度 | 192 维 NoPE + 64 维 RoPE |
| DSA indexer | 32 头，每头 128 维，Top-2048 |
| IndexShare | 每 4 层计算一次完整索引，其余层复用 |
| FFN | 前 3 层 Dense；之后为 MoE |
| MoE | 256 个路由专家，Top-8 + 1 个共享专家 |
| MTP | 1 层，MTP 迭代也共享索引 |
| 上下文 | 1,048,576 |
| 模态 | 纯文本 |

### 结构特点

1. **DSA 不是固定稀疏模式**  
   DSA 使用可学习的轻量索引器，根据当前 query 动态评估历史 token 的相关性，并选择 Top-2048 个位置执行核心注意力。它不是固定窗口、固定块或预设稀疏掩码。

2. **MLA 与 DSA 分工**  
   MLA 负责压缩 KV 表示，DSA 负责减少每个 query 真正参与核心注意力的位置数。前者主要降低缓存，后者主要降低注意力计算。

3. **IndexShare 减少重复索引**  
   GLM-5.2 的关键升级是让一个完整索引器服务连续四个稀疏注意力层。78 层中，21 层生成完整索引，57 层复用前一索引结果。官方报告称，在 1M 上下文下，这使每 token FLOPs 降低约 2.9 倍。

4. **不要误读 `full/shared`**  
   配置文件中索引器类型的 `full` 表示“本层运行完整索引器”，`shared` 表示“复用索引结果”。它不代表 `full attention` 与 `sparse attention` 的交替；核心注意力仍走 DSA 稀疏路线。

5. **MTP 与索引共享联动**  
   GLM-5.2 改进 MTP 层，并允许索引在 MTP 迭代之间共享。官方模型卡称投机解码接受长度最高提升约 20%。

## 5. Kimi-K3

### 基本结构

| 项目 | 配置 |
|---|---|
| 架构 | 原生多模态 MoE |
| 总参数 / 激活参数 | 2.8T / 104B |
| 主体层数 | 93 |
| Hidden size | 7,168 |
| 注意力布局 | 69 KDA + 24 Gated MLA |
| 注意力头 | 96 |
| KDA head dim | 128 |
| KDA short convolution | kernel size 4 |
| AttnRes | 每 12 层一个块 |
| FFN | 第 1 层 Dense；之后为 Stable LatentMoE |
| MoE | 896 个路由专家，Top-16 + 2 个共享专家 |
| Latent MoE 维度 | 3,584 |
| 专家中间维度 | 3,072 |
| 激活函数 | SiTU-GLU |
| 上下文 | 1,048,576 |
| 视觉编码器 | MoonViT-V2，约 401M 参数 |
| MTP | 无，配置为 0 层 |
| 量化 | MXFP4 权重 / MXFP8 激活，QAT |

### 结构特点

1. **KDA 负责大多数层**  
   93 层中有 69 层 Kimi Delta Attention。KDA 属于 DeltaNet 系线性注意力，使用短卷积、QK 归一化和 full-rank gate，在序列长度上避免标准全注意力的二次复杂度。

2. **Gated MLA 保留全局注意力能力**  
   每组 3 个 KDA 层之后放置 1 个 Gated MLA 层，模型尾部还有连续的 MLA 层。MLA 使用低秩 Q/KV 表示并增加输出门控，补充线性注意力在精确检索和全局交互方面的能力。

3. **Attention Residuals 跨层聚合**  
   AttnRes 不是普通的相邻层残差相加，而是学习如何组合更早层的表示。其目的在于改善 93 层深网络中的信息传递，让模型可以跨越较长的网络深度访问历史表征。

4. **Stable LatentMoE**  
   Kimi-K3 将路由专家的主要计算放在 3,584 维 latent 空间中，而不是始终在 7,168 维主 hidden space 内完成。配合 896 选 16 的超稀疏路由，可以扩大总容量，同时控制激活计算量。

5. **原生多模态**  
   MoonViT-V2 视觉编码器约 401M 参数，配置为 27 层、hidden size 1,024。官方资料声明支持文本、图像和视频；视觉特征经过 projector 映射到 7,168 维语言空间。

6. **原生低精度权重**  
   Kimi-K3 从 SFT 阶段开始进行量化感知训练，公开权重采用 MXFP4，激活采用 MXFP8。它不是简单的发布后压缩版本，而是训练流程中已考虑低精度误差。

## 6. Qwen 系列

### 6.1 Qwen 的共同骨架

四个 Qwen 模型都建立在 Qwen3.5 架构基础上，核心节奏为：

```text
3 × (Gated DeltaNet → FFN/MoE)
1 × (Gated Attention → FFN/MoE)
```

也就是每四层中，前三层使用线性注意力，第四层使用全注意力。这样可以让大多数层以接近线性复杂度处理长序列，同时定期使用全注意力恢复精确的全局 token 交互。

### 6.2 Qwen3.6-27B

| 项目 | 配置 |
|---|---|
| 类型 | Dense 原生多模态模型 |
| 参数量 | 27B |
| 层数 / Hidden size | 64 / 5,120 |
| 层布局 | 16 ×（3 DeltaNet + 1 Gated Attention） |
| DeltaNet | QK 16 头、V 48 头、head dim 128、卷积核 4 |
| 全注意力 | Q 24 头、KV 4 头、head dim 256 |
| FFN | Dense SwiGLU，intermediate size 17,408 |
| RoPE | 仅旋转 head 的 25%，即 64 维；mRoPE |
| MTP | 1 层，训练时多步预测 |
| 上下文 | 原生 262,144，可扩展至约 1,010,000 |
| 视觉编码器 | 27 层 ViT，hidden 1,152，16 头 |

**特点**：27B 的全部 FFN 都是 Dense，推理路径规则、模型质量稳定，但每个 token 都需要经过完整 27B 主体参数。多模态部分支持图像与视频，使用交错 mRoPE 表达时间、高度和宽度位置。

### 6.3 Qwen3.6-35B-A3B

| 项目 | 配置 |
|---|---|
| 类型 | MoE 原生多模态模型 |
| 总参数 / 激活参数 | 35B / 3B |
| 层数 / Hidden size | 40 / 2,048 |
| 层布局 | 10 ×（3 DeltaNet + 1 Gated Attention） |
| DeltaNet | QK 16 头、V 32 头、head dim 128 |
| 全注意力 | Q 16 头、KV 2 头、head dim 256 |
| MoE | 256 个路由专家，Top-8 + 1 个共享专家 |
| 专家中间维度 | 512 |
| MTP | 1 层 |
| 上下文 | 原生 262,144，可扩展至约 1,010,000 |
| 视觉编码器 | 与 27B 同类，输出映射到 2,048 维 |

**特点**：虽然总参数比 27B 更大，但每 token 只激活约 3B 参数，因此在能够高效调度 MoE 专家的服务框架上，吞吐量通常更有优势。代价是部署仍需保存全部 35B 权重，并处理专家并行与路由通信。

### 6.4 Qwen3.8-27B

Qwen3.8-27B 的官方结构配置与 Qwen3.6-27B 相同：

- 64 层，hidden size 5,120；
- 48 层 Gated DeltaNet + 16 层 Gated Attention；
- 27B Dense FFN；
- 相同的注意力头数、mRoPE、MTP 和视觉编码器配置；
- 原生 262,144 上下文，可扩展至 1M。

独立对比两份官方 `config.json` 后，结构字段一致，主要可见差异是所记录的 Transformers 版本。因此，**Qwen3.8-27B 的主要升级来自训练数据、预训练/后训练配方、强化学习和 agent 能力，而不是新的网络骨架**。

### 开放权重与云端 Max 的区别

官方模型卡明确说明：开放权重 `Qwen3.8-2.4T-A95B` 是纯文本模型；云端 `Qwen3.8-Max` 基于它提供视觉输入、默认 1M 上下文、非思考模式和内置工具等额外功能。因此不能把云端 Qwen3.8-Max 的全部产品能力直接归到开放权重检查点上。

## 7. 横向比较

### 7.1 长上下文技术路线

| 路线 | 代表模型 | 核心方法 | 主要优势 | 主要代价 |
|---|---|---|---|---|
| MLA 全注意力 | DeepSeek-V3 | 压缩 KV 潜变量，但仍对历史位置做注意力 | 精确、结构成熟 | 序列越长，注意力计算仍快速增长 |
| 压缩 + 稀疏混合 | DeepSeek-V4 | CSA/HCA 压缩序列，CSA 再做 Top-k | 1M 下同时降低 FLOPs 与 KV Cache | 结构和高性能内核复杂 |
| DSA + 索引共享 | GLM-5.2 | Top-2048 动态选择，四层共享一次索引 | 稀疏选择明确，减少索引器开销 | 需要专门支持 DSA/IndexShare 的推理栈 |
| 线性 + MLA 混合 | Kimi-K3 | 69 KDA + 24 Gated MLA | 大部分层线性复杂度，同时保留全局建模 | 新算子、超大 MoE 和低精度格式部署门槛高 |
| 线性 + GQA 混合 | Qwen3.6/3.8 | 3 DeltaNet + 1 全注意力 | 结构规律，兼顾长上下文与多模态 | 全注意力层仍需 KV Cache |

### 7.2 MoE 路由比较

| 模型 | 路由专家 | 每 token 路由专家 | 共享专家 | 特点 |
|---|---:|---:|---:|---|
| DeepSeek-V3 | 256 | 8 | 1 | sigmoid + 分组 Top-k + 无辅助损失均衡 |
| DeepSeek-V4-Pro | 384 | 6 | 1 | sqrt-softplus；前 3 层 Hash routing |
| DeepSeek-V4-Flash | 256 | 6 | 1 | 与 Pro 同路线，规模更小 |
| GLM-5.2 | 256 | 8 | 1 | sigmoid + correction bias；前 3 层 Dense |
| Kimi-K3 | 896 | 16 | 2 | Stable LatentMoE，在 3,584 维 latent 空间计算 |
| Qwen3.6-35B-A3B | 256 | 8 | 1 | 小激活参数，强调吞吐 |
| Qwen3.8-2.4T-A95B | 512 | 10 | 1 | 同一 Qwen MoE 骨架的大规模扩展 |

### 7.3 Dense 与 MoE 的部署含义

- **本地单用户、显存可控、追求兼容性**：Qwen3.6-27B 和 Qwen3.8-27B 的 Dense 结构最容易理解和部署。
- **高吞吐服务**：Qwen3.6-35B-A3B 的激活参数只有约 3B，在 MoE 内核成熟时很有吸引力。
- **超大集群推理**：DeepSeek-V4、GLM-5.2、Kimi-K3 和 Qwen3.8-2.4T-A95B 都需要多机、多卡、专家并行及专用内核，不能仅凭“激活参数量”估算硬件需求。
- **1M 上下文**：除了权重，KV Cache、索引器缓存、媒体 token 数量和推理框架实现都会成为主要瓶颈。

### 7.4 多模态比较

| 模型 | 多模态状态 | 结构说明 |
|---|---|---|
| DeepSeek-V3 / V4 | 纯文本 | 无原生视觉编码器 |
| GLM-5.2 | 纯文本 | DSA 语言模型 |
| Kimi-K3 | 原生多模态 | MoonViT-V2，官方声明支持图像和视频 |
| Qwen3.6-27B | 原生多模态 | 独立 ViT + mRoPE |
| Qwen3.6-35B-A3B | 原生多模态 | 独立 ViT + MoE 语言主体 |
| Qwen3.8-27B | 原生多模态 | 图像、视频、文本 |
| Qwen3.8-2.4T-A95B | 开放权重纯文本 | 云端 Max 的视觉能力不等于开放权重能力 |

## 8. 结论

1. **DeepSeek 的演进重点是从 KV 压缩走向“序列压缩 + 稀疏选择”**。V3 的 MLA 主要压缩表示；V4 的 CSA/HCA 进一步减少真正参与注意力的历史条目，并以 mHC 增强超深网络的信息流。

2. **GLM-5.2 是 DSA 路线中强调跨层复用的代表**。其关键不是简单的 Top-k，而是 IndexShare：让四层共享一次动态索引，从而把索引器本身的成本也降下来。

3. **Kimi-K3 是规模最大、结构最激进的模型**。它同时使用 KDA、Gated MLA、AttnRes、Stable LatentMoE 和原生 MXFP4/MXFP8，在 2.8T 总参数下维持 104B 激活，但部署复杂度也最高。

4. **Qwen3.6 与 Qwen3.8 延续同一套稳定的混合注意力骨架**。27B 版本的结构几乎没有代际变化；Qwen3.8 的提升更多来自训练和 agent 后训练，而 2.4T 旗舰是这一架构的超大规模 MoE 扩展。

5. **“1M 上下文”背后的实现并不相同**。DeepSeek-V4 依赖 CSA/HCA，GLM-5.2 依赖 DSA + IndexShare，Kimi-K3 依赖 KDA/MLA 混合，Qwen 则依赖 DeltaNet/全注意力混合与位置扩展。仅比较上下文数字无法判断真实成本和效果。

6. **选择模型时需要同时看四个指标**：总权重规模、每 token 激活参数、注意力/KV Cache 路线、推理框架支持。只看榜单或激活参数量容易严重低估部署要求。
