# 课程作业报告：基于 GRPO 的强化学习提升模型数学能力

> 本报告所有实验数据均在本机（Apple M3，24GB 统一内存，macOS）实测产生，代码与复现步骤见 §7。

---

## 摘要

本项目使用 **GRPO（Group Relative Policy Optimization）** 强化学习算法，在消费级 Mac（Apple M3）上对
Qwen2.5-0.5B-Instruct 小模型进行全量参数训练，目标是提升模型做数学题（算术）的能力。训练使用
**可程序化验证的规则奖励**（无需奖励模型、无需人工标注），通过复合奖励同时塑造"输出格式"与"答案正确性"
两种行为。

**主要结果**：200 步训练（45 分钟）后，模型在六档难度上的 `<answer>` 格式遵循率从 0.38~0.64 全部提升至
1.00（含未训练难度，证明泛化）；训练集内难度正确率显著提升（L2 0.86→1.00、L3 0.74→0.92、L5 0.92→0.96）；
而超出模型能力边界的两位数乘法（L6）仅从 0.50→0.54，几乎不涨——验证了 **RL 在能力边界内重排概率分布、
不能凭空创造能力** 的经典结论。结果与项目文档在 RTX 4060 上的结论定性一致，证明该方法论具有跨硬件、
跨模型基线的可复现性。

## 1. 任务与动机

### 1.1 任务定义

课程需求：**基于 GRPO 的强化学习提升模型做数学题能力**。

- **方法**：GRPO（TRL `GRPOTrainer` 实现）
- **模型**：Qwen2.5-0.5B-Instruct（0.5B 参数，可在本机全量训练）
- **任务**：算术题（加法/减法/乘法），答案可由程序精确验证
- **目标**：让模型学会（a）输出 `<answer>答案</answer>` 格式；（b）答案正确

### 1.2 为什么用算术题

| 选型维度 | 算术题的表现 |
|---------|------------|
| 奖励可验证 | `47 + 38 = 85` 可程序精确判定对错，零成本零噪声（RLVR 范式） |
| 难度可控 | 位数即难度旋钮，可精确把基线调到 GRPO 可学习的区间 |
| 有认知锚点 | 与 DeepSeek-R1 / TinyZero 同款的"可验证奖励 RL"叙事 |
| 资源友好 | 答案只有几个 token，生成快，200 步训练仅 45 分钟 |

选择算术题而非 GSM8K 等真实推理数据集的原因：0.5B 模型在真实推理数据集上难以观察到可学习的提升，
而算术题的"难度旋钮"特性更适合展示 GRPO 的核心机制（组内方差驱动的学习信号）。

### 1.3 待回答的问题

1. GRPO 能否让模型"算得更准"？提升幅度多大？
2. GRPO 能否让模型学会输出格式（表层行为）？学会后是否泛化到未训练难度？
3. RL 的提升是否有边界？超出模型能力的题目是否也涨？
4. 训练动态（熵、退化组比例）如何反映学习过程？

## 2. 方法

### 2.1 GRPO 原理简述

GRPO（DeepSeek 提出）是 PPO 的简化变体：

- **去掉价值网络**：PPO 需要训练 Critic 估计状态价值；GRPO 对同一个 prompt 采样 K 条回答，
  用**组内奖励的均值/标准差**做归一化得到 advantage，无需价值网络。
- **组内归一化**：`advantage = (r_i - mean(r_组)) / std(r_组)`
- **组内采样**：本项目 K=8（与评估口径 pass@8 一致）

**关键推论**：GRPO 的梯度来源是组内奖励方差。若一组 8 条全部答对或全部答错，
advantage = 0，该组**不产生任何学习信号**。因此选题的核心指标是
**informative group rate**（组内 0 < 正确数 < K 的比例）。

### 2.2 复合奖励设计

两个独立的 reward 函数（TRL 分别记录曲线，最后求和）：

```python
reward = reward_correct(1.0 正确 / 0.0 错误)   # 宽松解析：有标签取标签内，无标签取最后一个数字
       + reward_format(0.2 符合 <answer>N</answer>)  # 与正确性解耦
```

- **宽松解析**：模型基线期可能完全不输出标签，若严格要求标签内数字，正确信号恒为 0 → 组内全零 →
  advantage 全 0 → 训练无法启动。宽松解析保证冷启动有梯度。
- **格式分 0.2 的权重**：故意小于正确分（1.0），制造"主次信号竞争"的真实场景，用于观察
  "格式先收敛、正确率后爬坡"的训练动态。

### 2.3 难度选题方法论（本项目最重要的方法论）

训练集难度配比依据**基线摸底**的 informative group rate 选择（本机实测，见 §4.1）：

| 难度 | informative | 是否进训练集 | 理由 |
|------|:---:|:---:|------|
| L1 个位数加法 | 0.34 | ✗ | 太易，组内常全对，留作泛化评估 |
| L2 两位数加减 | 0.54 | √（25%） | 可学习甜区 |
| L3 三位数加减 | 0.64 | √（50%） | 主训难度 |
| L4 表内乘法 | 0.24 | ✗ | 组内常全对，留作泛化评估 |
| L5 两位数×一位 | 0.58 | √（25%） | 主训难度 |
| L6 两位数×两位数 | 0.58 | ✗ | 【讨论点】本机基线上 informative 达 0.58，理论上可学；此处按原方案留作边界对照 |

> 注：原项目文档（RTX 4060 + Qwen2 基线）中 L6 的 informative 仅 0.24，故不进训练集。
> 本机（Qwen2.5-0.5B）基线上 L6 的 informative 高达 0.58——这是一个值得讨论的复现差异（见 §5.3）。

## 3. 实验设置

### 3.1 环境

| 项目 | 配置 |
|------|------|
| 硬件 | Apple M3，24GB 统一内存（MPS 加速） |
| Python | 3.12（conda env: py312） |
| torch | 2.6.0（MPS） |
| transformers | 5.9.0（经 `src/trl_compat.py` 兼容补丁适配 trl 0.21） |
| trl | 0.21.0 |

> 工程说明：trl 0.21 与 transformers 5.x 存在已知兼容问题（`_is_package_available()` 返回值类型变更），
> 项目通过 `src/trl_compat.py` monkeypatch 解决，本机验证有效。

### 3.2 模型

- 基座：`Qwen2.5-0.5B-Instruct`（本地路径，无需下载）
- 训练方式：**全量微调**（494M 参数全部可训练）
- 显式 bf16 加载（本地 config 标注 fp16，不显式指定会导致 AdamW eps 下溢训废模型——项目实测定位的坑）

### 3.3 GRPO 训练参数

| 配置 | 取值 | 说明 |
|------|------|------|
| num_generations | 8 | 组内采样数 K |
| beta | 0.0 | KL 系数为 0，不加载参考模型，省显存 |
| epsilon | 0.2 | PPO-clip 裁剪范围 |
| temperature | 1.0 | 采样温度，保证组内多样性 |
| max_completion_length | 64 | 答案 token 数需求小 |
| learning_rate | 2e-6 | 全量 RL 微调典型量级，线性衰减至 1e-8 |
| 批次 | 8 completions × 累积 4 | 每优化步 = 4 prompt × 8 采样 = 32 条 completions |
| max_steps | 200 | 优化步数 |
| 训练集 | 1000 prompt（L3 50% / L5 25% / L2 25%） | 程序化生成，seed=123 |
| gradient_checkpointing | False | transformers 5.x 下会损坏 generate 输出（项目踩坑） |

### 3.4 评估协议

- 评估集：每难度 50 题，seed=42 程序化生成
- **配对原则**：基线、训练后使用**完全相同**的题目（同 seed），前后可逐题对比
- 每个 prompt 两种解码：greedy ×1（确定性能力）+ 温度 1.0 采样 ×8（pass@8）
- 指标：格式遵循率、greedy 正确率（宽松口径）、采样正确率、pass@8、informative group rate

## 4. 结果

### 4.1 基线摸底（训练前，Qwen2.5-0.5B-Instruct 原始能力）

| 难度 | greedy 正确 | 格式率 | 采样正确率 | pass@8 | informative 组比例 |
|------|:---:|:---:|:---:|:---:|:---:|
| L1 个位加法 | 0.94 | 0.50 | 0.92 | 1.00 | 0.34 |
| L2 两位数加减 | 0.86 | 0.38 | 0.82 | 0.98 | 0.54 |
| L3 三位数加减 | 0.74 | 0.64 | 0.71 | 0.96 | 0.64 |
| L4 表内乘法 | 0.98 | 0.50 | 0.94 | 1.00 | 0.24 |
| L5 两位数×一位 | 0.92 | 0.48 | 0.85 | 0.98 | 0.58 |
| L6 两位数×两位数 | 0.50 | 0.54 | 0.39 | 0.68 | 0.58 |

**基线观察**：
- 模型算术能力随难度递减（L1 0.94 → L6 0.50），符合预期；
- 格式遵循率整体偏低（0.38~0.64），模型对 `<answer>` 指令的遵循不稳定；
- 所有难度 informative 组比例均 ≥0.24，其中 L3/L5/L6 处于"可学习甜区"（0.5~0.8）。

> 【复现差异】原项目文档（Qwen2 基座，CUDA）基线为 L3 0.40 / L5 0.20 / L6 0.08，
> 本机（Qwen2.5 基座）基线全面更强（0.74 / 0.92 / 0.50）。这使本实验成为"强基线下 GRPO 是否仍有效"的验证。

### 4.2 训练动态（200 步，45 分钟）

关键指标序列（每 5 步记录一次）：

| 指标 | step 5 | step 50 | step 100 | step 200 | 趋势解读 |
|------|:---:|:---:|:---:|:---:|------|
| 正确分 mean | 0.831 | 0.950 | 0.906 | 0.950 | 快速爬升后高位震荡 |
| 格式分 mean | 0.099 | 0.200 | 0.200 | 0.200 | 约 15~20 步内饱和（0.2 = 100% 带格式） |
| 策略熵 | 0.186 | 0.014 | 0.019 | 0.017 | 持续下降，策略趋于确定性 |
| 退化组比例 | 0.15 | 1.00 | 0.95 | 1.00 | 后期绝大多数组全对/全错（探索枯竭） |

- **格式分约 15~20 步即饱和**：表层行为学习极快，与文档结论一致；
- **正确分前 50 步从 0.83 升到 0.95**：主信号学习；
- **熵从 0.186 降至 0.017**：策略收敛为近确定性——短训练中是收敛标志，长训练中则意味着探索枯竭隐患；
- **退化组比例升至 0.9+**：模型变强后简单题组内全对、无学习信号，后期学习主要靠中等难度题；
- **grad_norm 出现多次尖峰（最高 107）**：全量 bf16 微调受单步梯度噪声扰动，与文档观察一致
  （LoRA 模式该值基本 <1）。

训练曲线图见 `outputs/figures/train_curves_mac.png`。

### 4.3 训练前后对比（同评估集，seed=42，50 题/难度）

| 难度 | 训练集 | 格式率 前→后 | greedy 正确 前→后 | pass@8 前→后 |
|------|:---:|:---:|:---:|:---:|
| L1 个位加法 | — | 0.50 → **1.00** | 0.94 → **1.00** | 1.00 → 1.00 |

| L3 三位数加减 | √ | 0.64 → **1.00** | 0.74 → **0.92** | 0.96 → 0.94 |
| L4 表内乘法 | — | 0.50 → **1.00** | 0.98 → **1.00** | 1.00 → 1.00 |
| L5 两位数×一位 | √ | 0.48 → **1.00** | 0.92 → **0.96** | 0.98 → **1.00** |

## 5. 分析

### 5.1 格式学习：快、彻底、完全泛化

- 格式率在**全部六档难度**（含 L1/L4/L6 三个未训练难度）都达到 1.00；
- 训练日志显示格式分约 20 步内饱和；
- **结论**：格式是"表层行为"，RL 极易学会，且不依赖题目难度——学到的不是"某几道题的格式"，而是"输出格式"这一行为本身。

### 5.2 正确率提升与能力边界

- 训练集内难度：L2 0.86→1.00（+0.14）、L3 0.74→0.92（+0.18）、L5 0.92→0.96（+0.04）；
- 未训练难度 L4 也达 1.00（能力泛化，非背题）；
- **L6 几乎不涨（0.50→0.54）**：两位数乘法的多步进位超出 0.5B 模型能力边界，给奖励也学不会
  （但注意：§5.5 消融实验表明此边界是"软"的——给足 informative 信号后采样层面可部分学习）。
- **教科书级结论**：RL 在能力边界内重排概率分布、提升确定性，但不能凭空创造能力。

### 5.3 与文档（CUDA 基线）的复现差异讨论

| 维度 | 文档（RTX 4060 + Qwen2） | 本实验（M3 + Qwen2.5） |
|------|:---:|:---:|
| L3 基线正确率 | 0.40 | 0.74 |
| L5 基线正确率 | 0.20 | 0.92 |
| L6 基线正确率 | 0.08 | 0.50 |
| 训练后格式率 | 0.82~1.00 | **全部 1.00** |
| 训练后 L5 正确率 | 0.88 | 0.96 |
| 能力边界结论（L6 不涨） | 成立 | **成立（0.50→0.54）** |

**讨论**：基座模型换代（Qwen2 → Qwen2.5）使基线全面变强，绝对提升幅度变小，
但三大定性结论（格式秒学且泛化、边界内正确率提升、边界外无效）完全复现。
这证明该方法的有效性不依赖特定模型与硬件。

【实验验证】本实验"L6 的 informative 达 0.58 却未进训练集"是否合理，已通过消融实验直接回答（见 §5.5）：
L6 组确实提供可学习信号，加入训练集后 L6 的 pass@8 提升 +0.10——能力边界不是二值的，而是"软边界"。

### 5.4 训练健康的代价：熵崩溃与探索枯竭

- 熵 0.186 → 0.017，退化组比例后期 0.9+：策略已近确定性，后期梯度信号变稀；
- 短训练（200 步）内这不是问题（任务简单、已收敛）；
- 若延长训练或换更难任务，需引入熵正则或提高温度，否则探索枯竭后无法继续改进。
- 【补充实验】今天早些时候的 LoRA 50 步短训（`train_log_lora_mac_test.json`）显示
  正确分 0.78→0.92、熵降至 0.01、退化组比例 0.9+，与全量模式熵崩溃趋势一致，
  印证了"小模型短训练 + 可验证奖励"场景下 LoRA 也有效的结论。

### 5.5 消融实验：把 L6 加入训练集（50 步）

**动机**：本机基线摸底显示 L6 的 informative 组比例高达 0.58（处于可学习甜区），与文档
（CUDA 基线 0.24，组内常全错）不同。若 L6 组确实有学习信号，那么"能力边界"结论需要修正为
"软边界"。为直接验证，将训练集配比改为 L3 40% / L5 20% / L2 20% / **L6 20%**，训练 50 步
（`src/train_grpo_l6_ablation.py`），其余设置不变。

**训练动态差异**（与无 L6 训练对比）：

| 指标（step 5） | 无 L6（200 步） | 含 L6（消融，50 步） | 解读 |
|------|:---:|:---:|------|
| 正确分 mean | 0.831 | 0.669 | L6 难，整体均值被拉低，符合预期 |
| 退化组比例 | 0.15 | **0.00** | L6 组有对有错，信号充足 |
| 策略熵 | 0.186 | 0.275 | L6 答案多样性强 |

**三方对比结果**（同评估集，seed=42，50 题/难度；greedy 正确率 / pass@8）：

| 难度 | 基线 | 原训练（200 步，无 L6） | L6 消融（50 步，含 L6） |
|------|:---:|:---:|:---:|
| L1 个位加法 | 0.94 / 1.00 | 1.00 / 1.00 | 1.00 / 1.00 |
| L2 两位数加减 | 0.86 / 0.98 | 1.00 / 1.00 | 1.00 / 1.00 |
| L3 三位数加减 | 0.74 / 0.96 | 0.92 / 0.94 | 0.92 / 0.92 |
| L4 表内乘法 | 0.98 / 1.00 | 1.00 / 1.00 | 1.00 / 1.00 |
| L5 两位数×一位 | 0.92 / 0.98 | 0.96 / 1.00 | 0.96 / 0.98 |
| **L6 两位数×两位数** | **0.50 / 0.68** | **0.54 / 0.68** | **0.56 / 0.78** |

**结论**：

1. **L6 可学**：L6 的 pass@8 从 0.68 提升至 **0.78**（+0.10），仅 50 步、20% 配比就超过
   原训练 200 步的效果——informative=0.58 的组确实提供学习信号，模型在采样层面学会了部分 L6 题目；
2. **greedy 提升有限（0.50→0.56）**：确定性单步解码对多步进位乘法仍吃力——
   **能力边界是"软"的**：采样层面（pass@8）可部分突破，确定性层面受限；
3. **零回退**：其他难度与 200 步原训练持平（L3 0.92、L5 0.96、L2 1.00），降低配比无损害，
   且格式率全部保持 1.00。

> 实验局限：消融仅 50 步，与 200 步原训练不是严格对照（步数与配比同时变化）。
> 更严格的验证应固定 200 步、仅改配比。但作为"L6 组是否有信号"的定性验证已足够。

**对项目结论的修正**：文档中"L6 几乎不涨（0.08→0.24）"的结论建立在较弱基线
（informative=0.24，组内几乎全错）之上；在更强基线上，L6 位于能力边界边缘，
**给足信号（informative 组）后采样层面可以部分学习**。这深化了"RL 不能凭空创造能力"的表述：
不是绝对不可学，而是学习收益随难度远离能力边界而迅速衰减。

## 6. 结论

1. **需求满足**：基于 GRPO 的强化学习在本任务上切实提升了模型做数学题的能力——
   正确率在能力边界内显著提升（L3 +0.18、L2 +0.14），格式遵循率 0.38~0.64 → 1.00 且完全泛化。
2. **机制验证**：训练动态（格式先收敛、正确率后爬坡、熵下降、退化组比例上升）符合 GRPO 理论预期。
3. **边界认知**：RL 无法凭空创造能力（L6 greedy 几乎不涨），但消融实验表明**能力边界是"软"的**——
   给足 informative 信号后，L6 的 pass@8 从 0.68 → 0.78（+0.10），采样层面可部分突破；
   选题（informative group rate）是 GRPO 工程的核心。
4. **可复现性**：三大结论在不同于文档的硬件（M3）与模型（Qwen2.5）上定性复现。

## 7. 复现说明

环境与依赖见 `requirements.txt`（本机使用 conda env `py312`；`torch==2.6.0` MPS 版）。

```bash
conda activate py312
cd grpo_arithmetic

# 1. 基线摸底（6 难度 × 50 题，约 10 分钟）
python src/probe_baseline.py --n 50 --seed 42 --out outputs/baseline_probe_mac_full.json

# 2. GRPO 训练（200 步，本机约 45 分钟；--max_steps 3 --tag smoke 可先冒烟验证）
python src/train_grpo.py --tag mac_full

# 3. 训练后评估（同 seed 42，保证题目与基线完全相同）
python src/probe_baseline.py --n 50 --seed 42 --model outputs/grpo_ckpt_mac_full \
  --out outputs/post_train_probe_mac_full.json

# 4. 对比表 + 训练曲线
python src/compare_mac.py

# 5.（消融实验）把 L6 加入训练集，训练 50 步
python src/train_grpo_l6_ablation.py --max_steps 50 --tag l6ablation

# 6. 消融 checkpoint 评估（同 seed 42）
python src/probe_baseline.py --n 50 --seed 42 --model outputs/grpo_ckpt_l6ablation \
  --out outputs/post_train_probe_l6ablation.json
```

注意事项：

- 所有脚本第一行 `import trl_compat` 修复 trl 0.21 × transformers 5.x 兼容问题，勿删；
- 评估必须保持 `--seed 42` 与基线一致，保证前后配对可比；
- 训练必须显式 bf16（`model_init_kwargs`），否则 fp16 下 AdamW 一步训废模型；
- 曲线图中文标签需要中文字体，图例使用 ASCII（见 `src/compare_mac.py`）。
