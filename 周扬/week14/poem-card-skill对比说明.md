# poem-card Skill 优化对比说明

> 课程：badou-nlp · Week14 ｜ 优化日期：2026-08-06
> 原版：`week14/skills/poem-card/` ｜ 优化版：`week14/skills/poem-card-opt/`

---

## 一、优化目标

poem-card 是一个为古诗生成静态 HTML 学习卡（原文/注释/译文/赏析/背诵自测）的 myagent skill。
myagent 的 `skill_manager.py` 在命中关键词后会将**整篇 SKILL.md 注入 prompt**（top_k=2），
因此优化核心是：**在不损关键词命中率和功能的前提下，压缩每次调用消耗的 token，并精简脚本实现**。

## 三、SKILL.md 优化点

### 3.1 触发例句收敛为单一来源（关键）
原版触发例句在 frontmatter `description` 和正文「触发场景」章节**重复出现两遍**。
关键词打分只看短语是否出现在文本中，重复出现不增加命中率，纯属 token 浪费。

```diff
- ## 触发场景
- 当用户说出类似下面的话时触发本 skill：
- - "做一张《静夜思》的古诗卡"
- - "《登鹳雀楼》的学习卡"
- - "生成 poem card：悯农"
- - "复习《泊船瓜洲》，做个诗词卡"
+ （例句全部收敛到 frontmatter description，正文不再重复）
```

### 3.2 JSON 示例改紧凑单行格式（关键）
原版示例 20 行缩进格式 → 优化版单行紧凑格式。收益有两层：

1. **示例本身**：去掉换行缩进，省约 100 token；
2. **输出侧（更重要）**：LLM 会模仿示例格式生成数据，示例紧凑 → **LLM 输出的 JSON 也变紧凑**，
   每次任务省约 40% 输出 token（缩进换行全部消失），且 `json.load` 解析不受格式影响。

### 3.3 删除空泛铺垫，只留行为约束
原版「注意」段落与流程散文合并压缩，仅保留对工具调用有硬约束的内容：
不试 shell、`script_path` 必须是真实脚本路径、输出到当前工作目录。

### 3.4 数据契约字段说明一行式
字段说明从逐行列表压缩为一行（`title`诗题 / `author`作者 / …），与紧凑示例对照清晰；
「恰好 3-6 条 notes」「3-5 条 quiz」等数量约束保留，防 LLM 缺字段。

### 3.5 内容准确性护栏保留
「原文必须逐字准确，不确定就提醒核对，不凭印象杜撰」等护栏原样保留，未因压缩删减。

## 四、脚本优化点

### 4.1 删除 1.8KB 大 docstring
原版模块 docstring 重复了 SKILL.md 中的数据契约与用法说明，属于注释冗余。
优化版只保留一行用法说明（数据契约的唯一权威在 SKILL.md）。

### 4.2 渲染函数紧凑化
- 4 个 render 函数改用**生成器表达式**，减少中间 list 分配；
- `esc = html.escape` 局部别名，避免循环内重复属性查找；
- `render_grade_tag` 合并进 `build_html`，少一层函数调用。

### 4.3 产物零回归
模板与 CSS **逐字保留**，新旧脚本对同一数据文件生成结果经 `diff` 验证完全一致。

## 五、主观对比评价

| 维度 | 评价 |
|---|---|
| **注入 token** | SKILL.md -37%，每次命中 prompt 直接少约 600~1000 token（中文约 1 token/字估算） |
| **输出 token** | 紧凑示例引导 LLM 输出紧凑 JSON，每次任务输出侧再省约 40% |
| **执行时间** | 脚本本身 ~50ms 级（Python 启动占大头），优化版约持平，微秒级提升可忽略 |
| **生成延迟/成本** | 真实收益在 LLM 层：prefill 输入减少 → 首字延迟更低、成本按比例下降，**每次使用都生效** |
| **可维护性** | 触发例句单一来源，以后加例句只改 description 一处；字段契约一行式，改 schema 两边同步更不易漏 |
| **功能一致性** | 产物逐字节一致，无回归风险 |

**结论**：本次优化的主战场是 **token 消耗（输入注入 + 输出格式引导）**，
脚本层收益主要是体积与可维护性，执行时间基本持平。

## 六、风险与权衡

1. **紧凑 JSON 可读性略降**：LLM 偶尔仍可能输出多行格式，但 `json.load` 不受影响，无功能风险；
2. **关键词重叠**：两个 skill（poem-card 与 poem-card-opt）关键词高度重叠，若并存会互相挤占 top_k=2 加载名额；
3. **示例即模板**：示例格式影响 LLM 输出格式，改动示例时注意保持字段完整。
