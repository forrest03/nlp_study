为什么值得读源码？

🏗️ 架构是性能的上限

总参数量、上下文长度、推理成本几乎都由架构决定：MLA 把 KV cache 压缩约 93%，稀疏注意力把 1M 上下文 FLOPs 降到 27%，线性注意力把单步成本压到 O(1)。读源码才能看懂这些数字从哪来。

🎯 “为什么这样写”比“写了什么”更重要

同一件事（如 MoE 路由）五家各有写法：sigmoid 打分 vs softmax、有无 bias、有无分组限制、哈希 vs 打分——每一处取舍都对应训练稳定性、负载均衡或推理效率的考量。

🧭 一条清晰的技术演化主线

从 V3 的 MLA → V4 的 CSA/HCA、GLM 的 DSA、Kimi/Qwen 的线性注意力：业界在“注意力成本”上的探索殊途同归——精确注意力只留给少数关键位置。

技术演化时间线

DeepSeek-V3 — MLA + 无辅助损失 MoE
注意力 KV 压缩到潜在空间；sigmoid 打分 + 分组 top-k 路由，去掉负载均衡辅助损失。
GLM-5 / DSA — 稀疏注意力工业化
轻量索引器选 top-k token，主注意力从 O(L²) 降到 O(L·k)；GLM-5.2 进一步用 IndexShare 跨层复用索引。
Kimi-K3 / Qwen3.6 — 线性注意力回归
门控 Delta 规则（KDA / GatedDeltaNet）用固定大小状态压缩历史，单步 O(1) 成本；与全注意力分层混用。
DeepSeek-V4 — 混合注意力 + 超连接
窗口 + 压缩稀疏 (CSA) + 重度压缩 (HCA) 三层混合；mHC 超连接、哈希路由、FP4 专家；1M 上下文单 token FLOPs 仅为 V3.2 的 27%。

亮点洞察：最值得记住的“为什么这样写”

来自源码逐行解读

DS-V3 DeepSeek-V3

💡 吸收式注意力：把“省存储”变成“省算力”

MLA 把 KV 压成 512 维潜在向量后，若先解压再打分，省下的存储会变成解压的算力开销。代码用 q_nope @ wkv_b 把打分提前投影到低秩空间（dsv3_model.py:255），打分与加权全程留在低维完成——KV cache 省 ~71 倍，FLOPs 几乎零增加。

💡 bias 与权重严格分离 = 负载均衡不污染模型

路由用 scores + bias 选专家，权重却取自 original_scores（dsv3_model.py:302-314）——“干预谁被选中、但不干预输出力度”，这正是无辅助损失负载均衡能避免损害性能的全部秘密。

💡 分组 top-k 把通信预算编译进路由逻辑

真实训练每 token 最多发往 4 个节点，代码不做事后裁剪，而是把 256 专家分成 8 组、先按“组内 top-2 之和”选 4 组再组内选 8（dsv3_model.py:304-313）——通信预算直接变成路由的归纳偏置。

💡 YaRN 用“旋转圈数”而非维度决定插值边界

以“在原始 4096 长度内转 32 圈/1 圈”反推维度区间（dsv3_model.py:160-166），使修正范围与序列长度解耦：只拉伸转得太快的低频维度，配合 mscale² 修正，4096→128K 平滑外推。

DS-V4 DeepSeek-V4

💡 压缩不是池化，是“投票”

Compressor 用 wgate 学习“该不该保留这个 token”的软掩码，softmax 后加权求和，模型自主决定块摘要由谁主导；ape 让块内每位置有独立门控偏置——KV 压缩从信息论问题变成可学习问题（dsv4_model.py:304, 348, 352）。

💡 “决定看哪里”与“认真看”彻底解耦

Indexer 用 64×128 小头（FP4 全链路）预筛 top-k 压缩块，q 直接复用主注意力的低秩 qr（零额外前向）；512 维大头算力只花在被选中的条目上——1M 上下文 27% FLOPs 正是靠“先选后看”。

💡 残差被“数学锁死”反而更自由

mHC 把残差矩阵经 Sinkhorn 投影到 Birkhoff 多面体（谱范数≤1、对乘法封闭），深堆叠不爆炸；hc_pre/hc_post“合并-过层-展开”，层内计算不变却白得 4 条残差通路。

💡 bias 只“选人”不“给人开工资”

路由 bias 只参与 topk 排序、权重永远来自原始分数——负载均衡与真实贡献解耦；前 3 层更极端：tid2eid 查表定专家，路由计算整个消失，同 token 恒走同专家白拿激活局部性。

💡 为量化而生的注意力

KV 非 rope 维 FP8、rope 维保 BF16（位置精度不能丢）；Indexer 压缩 KV 先哈达玛旋转摊平离群值再 FP4——量化误差被“均摊”，叠加 FP4→FP8 无损反量化复用 FP8 训练管线，低精度体系环环相扣。

GLM GLM-5.2

💡 IndexShare 的全部工程成本 = 一个参数 + 一个 if-else

没有新缓存、没有新数据结构，一条贯穿 78 层的 topk_indices 变量（modeling_glm_moe_dsa.py:732-743）就砍掉 75% 索引器计算——论文里的 T_cache 就是一行 Python 变量。

💡 索引器 query 直接吃 MLA 的 q_resid

索引器用主注意力已算好的低秩 q_resid 而非 hidden_states（:224）：与主注意力共享低秩语义空间，又省一次大矩阵乘，是“lightning indexer 便宜一个数量级”的代码级落地。

💡 e_score_correction_bias 是 Buffer 而非 Parameter

选择与加权解耦、训练学推理固定、浮点语义确定（:500, 658），配合确定性 topk 共同保障 RL 训练/推理一致——论文为此弃用非确定性 CUDA topk。

💡 interleave RoPE 在奇偶切片上直接旋转

在 q[..., 0::2]/q[..., 1::2] 上直接算旋转（:156-160），位一致且省一次 contiguous 拷贝——1M 上下文下这是每层每 token 都要省的搬运。

💡 3D 专家权重 + one_hot + index_add_

gate/up 合并一次 GEMM、按专家切片即单专家（:539-565），天然适配 EP/TP 与内核替换；router 的 n_group=1 保留 DeepSeek 分组门控代码路径但实际关闭——“语义兼容、配置可调”的工程取舍。

K3 Kimi-K3

💡 把“残差”从加法升级成“对深度的注意力”

普通残差把所有历史压进单一状态（RNN 式深度瓶颈）；AttnRes 用 13 行代码（kimi_k3_linear_modeling.py:1075-1088）的可学习伪查询对多个块级表示做 softmax 加权，既缓解深层梯度又让每层能“跳过”无关历史，内存从 O(L·d) 降到 O(N·d)。

💡 一个数学参数化直接改变了 kernel 结构

把无界负 Softplus 衰减换成 g_min·Sigmoid(e^A·z)（g_min=-5），把衰减率约束在有限范围内，让 KDA 分块形式的所有 tile 都能用稠密 Tensor Core GEMM——数值选择即计算设计。

💡 门控 Delta 规则 = 有界记忆 + 选择性遗忘

(I−βkkᵀ) 外积项可“擦除”旧键、Diag(α) 通道衰减可“遗忘”，让固定 128×128 状态同时做到长上下文与 O(1) decode；比纯线性注意力“只叠加不删除”的记忆更干净。

💡 负载均衡与路由学习互不干扰

QB 偏置只进 top-k 选择、不进权重（:750 行 topk_weight = scores.gather），对应论文“b 被省略于 p_ij”——用一次 forward 的分位数设定偏置，让 896 专家各拿精确目标负载而不污染梯度。

💡 SiTU-GLU 是为 MXFP4 而生的激活

SwiGLU 两个因子无界、低精度必溢；SiTU 近原点保持 SwiGLU 响应、全局有界（β₁β₂=100），配合 LatentMoE 内 RMSNorm，共同驯服 2.8T 规模下 16/896 极端稀疏的激活爆炸——稳定即量化可行。

Q3.6 Qwen3.6

💡 对数参数化衰减：数值稳定性焊进参数本身

A_log 存 log 空间使 exp(A)>0 恒成立，g 恒负、exp(g)∈(0,1)，递归记忆只衰减不发散（modeling_qwen3_5_moe.py:416-417）；注释还提醒 fp16 下必须 .float() 防 -inf。

💡 全注意力的“免费”输出门控

q_proj 直接输出 2 倍宽度，对半切成 query 与 gate 两路，sigmoid(gate) 给每 4 层才出现一次的全注意力加了一个零额外参数的软开关（:639-641, :667-670, :698）。

💡 共享专家用独立 sigmoid 门而非固定权重

路由权重经 softmax 归一化总和恒为 1，共享专家若混入同一分布会被“平均稀释”；Linear(H,1)+sigmoid 让模型逐 token 学会“何时依赖共享专家”（:785, :794）。

💡 MTP：训练目标与 serving 引擎分工

config 开 1 层 MTP、checkpoint 带 mtp.* 权重，但 HF 前向用 _keys_to_ignore_on_load_unexpected 忽略，由 vLLM/SGLang 在投机解码中兑现——工程化范本。

1. 标准 Transformer 块

注意各模型的“变体”：DeepSeek-V4 把残差升级为 Hyper-Connections（4 份状态互连）；Kimi-K3 把残差升级为 AttnRes（块级前缀和 + 学习加权）；其余模型保持经典残差。

3. MoE 路由 —— 每 token 只激活少数专家

各家差异点：DeepSeek-V3/GLM 用 sigmoid 打分（去掉负载均衡辅助损失），Qwen 用 softmax；DeepSeek-V4 前 3 层改用哈希路由；Kimi-K3 激活 16/896 专家，稀疏度最高。

2. 架构总览

DeepSeek-V3 仍属于标准的 decoder-only Transformer 框架（论文 §2.1），整体数据流如下：

tokens ──▶ ParallelEmbedding ──▶ h ──▶ [ Block × 61 ] ──▶ RMSNorm ──▶ head(ColumnParallelLinear) ──▶ logits
                                        │ 每个 Block：                          ▲ 取最后一位 token 的 hidden
                                        │   h = h + MLA(attn_norm(h))           （推理/续写场景）
                                        │   h = h + FFN(ffn_norm(h))
                                        │   FFN = MLP（前 3 层）或 MoE（其余 58 层）

对应 Transformer.forward（dsv3_model.py:395-411）：embed 查表（ParallelEmbedding，dsv3_model.py:54-74）→ 逐层穿过 self.layers（61 个 Block，dsv3_model.py:389-390）→ 末尾 RMSNorm（dsv3_model.py:391,405）→ 取 h[:, -1]（最后一个 token）→ head 线性投影出词表 logits（dsv3_model.py:406）→ 多 rank 时 all_gather 拼接完整词表（dsv3_model.py:407-410）。

每个 Block（dsv3_model.py:365-376）是"Pre-Norm + 残差"结构：

  • attn_norm/ffn_norm 均为 RMSNorm（dsv3_model.py:140-149，计算 x * rsqrt(mean(x²) + eps)，无均值偏移项）；
  • 注意力子层为 MLA（dsv3_model.py:368）——用低秩潜在向量压缩 KV，显著降低 KV cache 与训练激活内存；
  • 前馈子层：layer_id < n_dense_layers 时是 dense MLP（dsv3_model.py:369, 272-280，SwiGLU 激活），否则是 MoE（dsv3_model.py:369, 332-362）——256 个 routed expert + 1 个共享 expert，每 token 只激活 8 个 routed expert，是模型参数量 671B 却只激活 37B 的根本原因；
  • 每个子层带残差连接（dsv3_model.py:374-375），即 x = x + sublayer(norm(x))。

两大稀疏化手段共同构成"大而省"的架构：MLA 压缩了注意力侧的存储与带宽；DeepSeekMoE 把稠密 FFN 拆成细粒度专家，每 token 只计算约 1/32 的 FFN 参数。注意 MoE 层里每个专家与共享专家都是 SwiGLU 双层 MLP（Expert，dsv3_model.py:321-329；MLP，dsv3_model.py:272-280），w1/w3 将维度放大到 inter_dim、w2 投影回 dim。

4. 核心组件解读

MLA 多头潜在注意力（dsv3_model.py:195-269）

代码位置与逐段含义：

  • 结构定义（dsv3_model.py:196-228）：MLA.__init__ 里，q_lora_rank > 0 时 Q 采用两段式低秩投影：wq_a: dim→q_lora_rank（dsv3_model.py:211）→ q_norm（RMSNorm，dsv3_model.py:212）→ wq_b: q_lora_rank→n_heads×qk_head_dim（dsv3_model.py:213）；q_lora_rank == 0 时退化为单层 wq（dsv3_model.py:209）。KV 侧是 MLA 的精髓：wkv_a: dim→(kv_lora_rank + qk_rope_head_dim)（dsv3_model.py:214）——一次线性把输入压到 512 维潜在向量 + 64 维解耦 RoPE 键；kv_norm 对低秩向量做 RMSNorm（dsv3_model.py:215）；wkv_b: kv_lora_rank→n_heads×(qk_nope_head_dim + v_head_dim) 负责"解压"（dsv3_model.py:216）；wo 是输出投影（dsv3_model.py:217）。
  • 缓存设计（dsv3_model.py:223-228）：attn_impl == "absorb"（默认，dsv3_model.py:17）时只注册两个 buffer：kv_cache（形状 [batch, max_seq_len, kv_lora_rank]，512 维）与 pe_cache（[batch, max_seq_len, qk_rope_head_dim]，64 维）；而 naive 模式要缓存展开后的 k_cache（每 token 每头 192 维）与 v_cache（每头 128 维），即每 token 320 维。真实配置下 128 头展开后每 token 的 k+v 共 128×(192+128)=40960 维，absorb 模式只缓存 512+64=576 维，KV cache 节省约 71 倍，这正是 MLA 论文公式 1-5 的落地。
  • 前向（dsv3_model.py:230-269）：Q 计算（233-239）后 q = q.view(bsz, seqlen, n_local_heads, qk_head_dim)，split 成 q_nope(128) 与 q_pe(64)，仅 q_pe 过 RoPE（239）。KV 侧（240-242）：wkv_a 输出 split 成 kv(512) 与 k_pe(64)，k_pe 过 RoPE。absorb 打分（252-259）：先把 wkv_b 权重（FP8 时先 weight_dequant，253 行）view 成 [n_local_heads, -1, kv_lora_rank]，然后用 einsum("bshd,hdc->bshc", q_nope, wkv_b[:, :qk_nope_head_dim])（255 行）把 q_nope 投影到 512 维低秩空间——这样打分时 q_nope·c_KV 就等价于"解压后的 q·解压后的 k"，而无需真正解压出 k；kv_cache 存 kv_norm(kv)（256 行），pe_cache 存 k_pe（257 行）；得分 = q_nope·kv_cache + q_pe·pe_cache 再乘 softmax_scale（258-259 行）。softmax 用 float32 精度（262 行）。加权求和阶段同样吸收：einsum("bsht,btc->bshc", scores, kv_cache) 在低秩空间聚合，最后再用 wkv_b[:, -v_head_dim:] 一次投影出 v 维输出（266-267 行），再 wo 输出（268 行）。

为什么这样写（设计动机）：

  1. KV cache 是长上下文推理的第一瓶颈。标准 MHA 每 token 要存所有头的 K、V；MLA 把 K、V 联合压缩进一个 512 维潜在向量，推理时只缓存它和 64 维 RoPE 键（论文："only the blue-boxed vectors (i.e., c_KV_t and k_R_t) need to be cached"）。这让 DeepSeek-V3 能在一张 80GB GPU 上跑出远大于同规模 MHA 模型的 batch × 上下文。
  2. "吸收"（absorb）是为了让"低秩缓存"不增加计算量。若先解压 k 再打分，低秩压缩省下的存储会变成解压的算力开销；吸收式把 q_nope 先乘 wkv_b 的 nope 部分，把打分和后续加权都留在 512 维空间完成，只在最后投影一次——省存储的同时几乎不增加 FLOPs。
  3. Q 也做低秩（q_lora_rank=1536） 是为了省训练激活内存（论文：query 压缩"can reduce the activation memory during training"），且 q_norm（RMSNorm）稳定低秩投影后的数值分布。
  4. softmax_scale 的 mscale 修正是为长上下文服务的：qk_head_dim = 128 + 64 = 192，基础 scale 为 192^-0.5（dsv3_model.py:205,218）；当 max_seq_len > original_seq_len（启用了 YaRN 扩展）时，mscale = 0.1·mscale_arg·ln(rope_factor) + 1 ≈ 1.369，softmax_scale *= mscale²（dsv3_model.py:219-221）。因为 YaRN 把 q/k 的频率都缩放（每边乘 mscale），点积整体放大 mscale²，需要按论文的 √t = 0.1·ln(s)+1 补偿，否则 softmax 会饱和、注意力变"尖"。
  5. kv_norm 在压缩表示上做 RMSNorm（dsv3_model.py:215），论文提到"additional RMSNorm layers after the compressed latent vectors"——压缩后数值范围被压缩，先归一化再解压，训练更稳。

DeepSeek MoE 路由（Gate, dsv3_model.py:283-318）

代码位置与逐段含义：Gate.__init__（283-293）持有一个 [n_routed_experts, dim] 的路由权重与可选 bias（293 行，仅 dim == 7168 时创建，对应真实模型）。forward（295-318）：

  1. scores = linear(x, weight)（296）——每 token 对 256 个专家各算一个线性得分；
  2. 打分函数：softmax 或 sigmoid（297-300）。真实模型用 sigmoid（config scoring_func: sigmoid），并把原始得分存为 original_scores（301）；
  3. bias 加入：scores = scores + self.bias（302-303）——bias 只用于 top-k 选择；
  4. group top-k（304-312）：得分 reshape 成 [batch, n_groups, -1]（8 组 × 32）；每组内取 top-2 求和得到组得分（309，bias 存在时用 top2 和，否则 amax）；组得分 top-topk_groups（4）选出 4 组（310）；scatter_ 构造掩码，把未选中组的得分全部置 0（311-312）；
  5. 最终在保留组内 torch.topk(scores, topk=8) 选出 8 个专家索引（313）；
  6. 权重取自未加 bias 的原始得分 original_scores.gather(1, indices)（314）；sigmoid 模式下除以权重和做归一化（315-316）；最后乘 route_scale（真实 2.5，317）。

为什么这样写：

  1. sigmoid 替代 softmax 的意义（论文公式 13-15 与 §2.1.2）：softmax 的得分是"相对"的，token 间不可比且容易两极分化；sigmoid 让每个专家独立打分，配合归一化得到更平稳的专家权重。论文明确指出"DeepSeek-V3 uses the sigmoid function to compute the affinity scores, and applies a normalization among all selected affinity scores"。
  2. bias 是实现 auxiliary-loss-free 负载均衡的载体（论文公式 16 与 §2.1.2）：传统 MoE 用辅助损失惩罚不均衡，但会损害模型性能；V3 为每个专家维护一个 bias，训练时按负载动态增减（过载减、欠载增），从而只影响"谁被选中"、不影响"权重多大"——路由用 scores + bias，权重用 original_scores，正是这句话的代码化。参考实现把它做成可学习 nn.Parameter，训练框架里等价于论文的按负载更新。
  3. group top-k 是"节点受限路由"的廉价近似（论文 §2.1.2 "Node-Limited Routing"）：真实训练中每 token 最多发往 4 个节点（M=4），把 256 个专家分成 8 组、先按组得分选 4 组，等价于预先限制 token 只可能落在 4 个"专家组"内，从而把 all-to-all 通信量约束在论文要求的 ≤4 节点，同时保持路由质量（组内 top2 求和近似组内专家水平）。先粗筛组、再细选专家是"先降维度、再做决策"的两级路由，省通信且几乎不损失精度。
  4. 权重归一化 + route_scale：sigmoid 得分之和不为 1，归一化后保证各专家输出加权求和尺度稳定；route_scale=2.5 是训练时的缩放超参（论文超参表 routed_scaling_factor），在保持梯度和输出幅度平衡上起补偿作用。

Expert 与 MoE 前向（dsv3_model.py:321-362）

代码位置与逐段含义：Expert（321-329）就是一个 SwiGLU 双层 MLP（w1/w3 升维、w2 降维）。MoE.__init__（332-345）：按 world_size 把 256 个专家切给各 rank（n_local_experts = n_routed_experts // world_size，338），ModuleList 中只实例化本 rank 的专家、其余位置置 None（343-344）；shared_experts = MLP(dim, n_shared_experts * moe_inter_dim)（345）——把共享专家合并进一个 MLP，inter_dim 按个数放大。

MoE.forward（347-362）是稀疏执行的关键：

x = x.view(-1, self.dim)                                   # 349: 展平 [B*S, dim]
weights, indices = self.gate(x)                            # 350: [B*S, 8] 权重与专家索引
y = torch.zeros_like(x)                                    # 351
counts = torch.bincount(indices.flatten(), minlength=self.n_routed_experts).tolist()  # 352
for i in range(self.experts_start_idx, self.experts_end_idx):                          # 353
    if counts[i] == 0:                                     # 354-355: 无人路由的专家直接跳过
        continue
    expert = self.experts[i]
    idx, top = torch.where(indices == i)                   # 357: 找出路由到专家 i 的 (token, topk位)
    y[idx] += expert(x[idx]) * weights[idx, top, None]     # 358: 只算这些 token，按权重累加
z = self.shared_experts(x)                                 # 359: 共享专家对所有 token 计算（稠密）
if world_size > 1: dist.all_reduce(y)                      # 360-361: 跨 rank 汇总专家输出
return (y + z).view(shape)                                 # 362

为什么这样写：

  1. bincount + where 是 PyTorch 里"按索引稀疏计算"的标准做法：没有原生的"对每个 token 只跑被选中的专家"算子，于是先 bincount 统计每个专家收到的 token 数，再对每个本地专家用 torch.where 取出被路由到的 token 行，只对这些 token 做专家前向，再用 y[idx] += ... 散射回原位置。这等价于把"动态分组"实现成"遍历专家 + 掩码索引"，避免了把不同 token 拼成稠密 batch 的拷贝开销（gather 也是零拷贝索引）。
  2. counts[i] == 0 跳过避免空转：MoE 层 256 个专家、每 token 只选 8 个，绝大多数专家在单个 batch 上收到的 token 可能为 0；跳过它们把稀疏计算收益落到实处。
  3. 共享专家单独稠密计算（359 行）：1 个共享专家被所有 token 激活，捕获"所有 token 都需要的通用知识"，让 routed 专家可以更专注地做专业化分工（论文：isolates some experts as shared ones；Figure 10 显示 aux-loss-free 模型专家专业化更强）。实现上把 n_shared_experts 个共享专家合并成一个宽 MLP，一次 GEMM 完成，避免逐专家调用。
  4. 专家并行下的结果汇总：每个 rank 只持有本地专家（343 行），路由索引是全局的（gate 权重未切分），因此各 rank 的 y 只是部分和，需要一次 all_reduce 求和（360-361）——这是 MoE 与 ColumnParallelLinear/RowParallelLinear 不同的第三种并行模式（EP，专家并行），论文里训练用 EP64、推理预填充用 EP32。

位置编码 YaRN（dsv3_model.py:152-192）

代码位置与逐段含义：precompute_freqs_cis（152-184）一次性预计算好整张旋转频率复数表：

  • find_correction_dim（160-161）：给定"旋转圈数"，反推对应维度：dim · log(max_seq_len / (rotations·2π)) / (2·log(base))——维度越高频率越高，同样序列长度下转的圈数越多；
  • find_correction_range（163-166）：用 beta_fast=32 与 beta_slow=1 两个圈数阈值算出需要修正的维度区间 [low, high]（真实配置约覆盖低频端）；
  • linear_ramp_factor（168-173）：在 [low, high] 上构造 0→1 的线性斜坡（clamp 到 [0,1]）；
  • 频率修正（175-179）：freqs = 1 / base^(i/dim) 是原始 RoPE 频率；当 seqlen > original_seq_len(4096) 时，smooth = 1 - ramp，freqs = freqs/factor·(1-smooth) + freqs·smooth——低频维度整体除以 factor=40（拉伸周期），高频维度几乎不变，中间线性过渡；
  • 张成复数表（181-183）：freqs = outer(t, freqs) 得到 [seqlen, dim/2] 的角度矩阵，torch.polar 转成复数 freqs_cis。

apply_rotary_emb（187-192）把实数张量 view_as_complex 变成复数，与 freqs_cis 逐元素复数相乘（等价于旋转矩阵乘法），再 view_as_real 展平——比显式构造旋转矩阵更紧凑高效。

为什么这样写：

  1. 直接外推在长上下文下失效：RoPE 的周期由 base 决定，位置超出预训练长度后，某些维度的相邻位置角度差会超过 π/2，导致位置向量无法区分相邻 token（"位置混淆"）。YaRN 的思路是按维度分级处理：频率低（周期长）的维度负责大范围位置分辨，直接除以 factor 拉伸（等效于把原 4096 的波形铺到 163840）；频率高的维度周期本就短，拉伸会破坏高频细节，保持原频率。
  2. 斜坡过渡避免"断层"：若在某个维度上频率从"除 40"突变到"不变"，会让该维度的相位不连续、破坏模型已学到的相对位置语义；linear_ramp_factor 让修正比例平滑过渡。
  3. 为何用"旋转圈数"阈值而非固定维度：find_correction_range 按"在原始序列长度内最多转 32 圈 / 最少转 1 圈"反推维度边界，物理含义是"转太多圈的维度才需要拉伸"，与序列长度解耦，可泛化到不同的扩展目标。
  4. 与 MLA 协同：YaRN 只施加于解耦的 RoPE 键 k_R/q_R（论文：applied exclusively to the decoupled shared key），nope 部分不含位置信息；配套的 mscale² 修正已在 MLA 节解释。论文的两阶段扩展（4K→32K→128K，各 1000 步）正是这套代码所支持的场景。

FP8 量化线性层（dsv3_model.py:77-137）

代码位置与逐段含义：核心是 linear 函数（77-88）与 Linear 类（91-111）：

  • 权重以 FP8 存储时 element_size() == 1（98-99 行），此时按 block_size=128 计算 scale 的形状 [(out+127)//128, (in+127)//128]（100-102）——按 128×128 块共享一个 FP32 scale，与 config weight_block_size: [128,128] 一致；
  • 前向三选一（78-88）：BF16 权重直接 F.linear；FP8 权重但 gemm_impl == "bf16" 时先 weight_dequant 再 BF16 GEMM（回退路径，81-82）；FP8 模式下 act_quant(x, block_size) 把激活按 1×128 tile 动态量化（84），再调 fp8_gemm(x, scale, weight, weight.scale)（85）——激活 scale 与权重 scale 分别传入，内积后按两 scale 乘积反量化；
  • ColumnParallelLinear（114-122）按输出列切分、RowParallelLinear（125-137）按输入行切分并在 all_reduce 后加 bias（135-136，避免 bias 被重复累加）。

为什么这样写：

  1. 为什么动态量化（online quantization）：论文明确对比了 delayed quantization（用历史最大值推断 scale）与在线计算每个 tile/block 的最大绝对值。在线量化只需一次 amax 归约即可得 scale，无需维护历史状态、对分布漂移更鲁棒，且天然适配小粒度分组（论文 §3.3.2 "Online Quantization"）。activation_scheme: dynamic 即此意。
  2. 为什么 block_size=128：FP8 动态范围有限（E4M3 只有 4 位指数），激活/权重里的 outlier 会撑大整体 scale、压垮正常值精度。论文的细粒度量化把 scale 下放到 激活 1×128 tile、权重 128×128 block（论文 Figure 7(a)），让每个小块的 scale 适应该块数值，outlier 只影响所在小块。这与 NVIDIA 微缩放格式（microscaling）思想一致。
  3. 为什么激活按 1×128 而非 128×128：论文附录 B.2 专门讨论了激活按 block 量化会引发训练不稳定，因此激活用更细的"每 token 每 128 通道"一维 tile，权重则用二维 block——不对称粒度是对精度与开销的折中。
  4. E4M3 全 tensor 统一：传统方案 Fprop 用 E4M3、反传用 E5M2；论文全用 E4M3 换取更高尾数精度，并论证"细粒度分组共享指数位"弥补了动态范围不足（§3.3.2 "Mantissa over Exponents"）。代码 Linear.dtype = torch.float8_e4m3fn（384 行）与此一致。
  5. 代码的双路径设计（bf16 回退）：gemm_impl 可切换（16 行），让同一份代码既能演示 FP8 也能在无 FP8 内核的平台上以 BF16 跑通——这是"可读参考实现"的工程取舍，也说明 FP8 的真正收益（H800 上约 2 倍算力、激活缓存减半，论文 §3.3.1）来自内核与量化框架的配合，而非模型结构本身。

并行化（ParallelEmbedding / Column / RowParallelLinear, dsv3_model.py:54-137）

代码位置与逐段含义：

  • ParallelEmbedding（54-74）：把词表按 rank 切成 part_vocab_size 份（59-60），每 rank 只存一段词表。前向时 mask 掉不属于本 rank 的 token id 并做偏移（66-69），查表后把本 rank 无权贡献的位置置 0，再 all_reduce 求和（71-73）——因为只有拥有该 token 的 rank 贡献非零，求和即"取回正确 embedding"。
  • ColumnParallelLinear（114-122）：out_features // world_size（117）沿输出列切分权重，每 rank 输出部分维度，无需通信——它与下一个 RowParallelLinear 的 all_reduce 成对抵消。
  • RowParallelLinear（125-137）：沿输入行切分（127-129），每 rank 只算部分和，all_reduce 求和得到完整输出（133-134）；bias 放在 all_reduce 之后（135-136），否则 bias 会被 world_size 个 rank 重复累加。

为什么这样写：

  1. 切分方式由"矩阵乘法形状"决定：Y = X·W，按输出维切 W 则每 rank 算 X·W_i 得到 Y 的不同列（column-parallel，无需归约）；按输入维切 W 则每 rank 算 X_i·W_i 得到 Y 的部分和（row-parallel，需归约）。两者配对使用（如 MLP 的 w1/w3 用 Column、w2 用 Row，dsv3_model.py:275-277），正好把通信次数降到每对一次 all_reduce。
  2. Embedding 用"置 0 + all_reduce"而非 all_gather：embedding 是"查表"，稀疏性天然存在；置 0 后归约是 O(vocab/rank) 内存、一次通信的优雅实现，且与输出头（也按词表切分，head = ColumnParallelLinear(dim, vocab_size)，392 行）形成对称——词表维度的切分是 LLM 张量并行的惯例（embedding 和 head 共享同一套切分逻辑）。
  3. all_reduce 的位置决定数值正确性：RowParallelLinear 若在 all_reduce 前加 bias，各 rank 的部分和里都含 bias，归约后 bias 变 world_size 倍——所以 bias 必须放在归约之后（135-136）。ParallelEmbedding 同理，mask 置 0 必须在查表后、归约前。
  4. 代码的"演示默认"与真实训练的差异：文件默认 world_size = 1（13 行），Transformer.__init__ 里从 dist 环境读取真实 world_size/rank（381-383 行）——单卡演示与多卡张量并行共用同一份代码。真实训练（论文 §3.2）用的是 PP16 + EP64 + ZeRO-1，张量并行只出现在推理预填充（TP4），因为论文刻意"avoiding the use of costly tensor parallelism"来省内存；本文件的 Column/Row 并行正是推理 TP 的代码形态。

片段 2：Gate 的 group top-k 与 bias 分离（dsv3_model.py:295-318）

def forward(self, x):
    scores = linear(x, self.weight)                    # 256 维原始得分
    scores = scores.sigmoid()                          # 真实模型用 sigmoid
    original_scores = scores                           # 备份：权重只来自这里
    if self.bias is not None:
        scores = scores + self.bias                    # bias 只参与"选谁"
    if self.n_groups > 1:
        scores = scores.view(x.size(0), self.n_groups, -1)          # 8 组 × 32
        group_scores = scores.topk(2, dim=-1)[0].sum(dim=-1)        # 每组取 top2 求和 → 组得分
        indices = group_scores.topk(self.topk_groups, dim=-1)[1]    # 选 top4 组
        mask = torch.zeros_like(scores[..., 0]).scatter_(1, indices, True)
        scores = (scores * mask.unsqueeze(-1)).flatten(1)           # 屏蔽未选中组
    indices = torch.topk(scores, self.topk, dim=-1)[1]              # 组内选 8 个专家
    weights = original_scores.gather(1, indices)                    # 权重取原始得分
    weights /= weights.sum(dim=-1, keepdim=True)                    # sigmoid 得分归一化
    weights *= self.route_scale                                     # × 2.5

注释式解读：两处"分离"是本段的灵魂。第一处：bias 与权重的分离——scores + bias 只决定 top-k 选谁，original_scores.gather 决定权重多大，这正是 auxiliary-loss-free 负载均衡"干预路由但不污染门控值"的代码形态（论文公式 16）。第二处：两级路由的分离——先按"组内 top2 得分和"选 4 组（相当于粗粒度预筛，把通信范围限制在 4 组内），再把未选中组整体屏蔽后做最终 top-8（细粒度决策）。设计理由：真实训练里每 token 最多发往 4 个节点（论文 M=4），group top-k 把"节点约束"直接编码进路由逻辑，比事后限制通信更优雅，且组得分用 top-2 而非平均/最大，能反映组内"最强的两个专家"的水平，路由更准。

def find_correction_dim(num_rotations, dim, base, max_seq_len):
    return dim * math.log(max_seq_len / (num_rotations * 2 * math.pi)) / (2 * math.log(base))

def find_correction_range(low_rot, high_rot, dim, base, max_seq_len):
    low = math.floor(find_correction_dim(low_rot, dim, base, max_seq_len))
    high = math.ceil(find_correction_dim(high_rot, dim, base, max_seq_len))
    return max(low, 0), min(high, dim-1)

def linear_ramp_factor(min, max, dim):
    linear_func = (torch.arange(dim, dtype=torch.float32) - min) / (max - min)
    return torch.clamp(linear_func, 0, 1)

6. 优点与局限

优点

  1. 推理成本被 MLA 大幅压低：KV cache 每 token 仅 576 维（512 潜在 + 64 RoPE），相比标准 MHA（真实配置 40960 维）节省约 71 倍，长上下文与高并发场景下显存压力显著小于同规模稠密模型；同时"吸收式"实现不牺牲算力（§4.1）。
  2. 训练成本与稀疏收益：671B 参数只激活 37B，配合 FP8 训练（约 2 倍 GEMM 算力、激活缓存减半）、DualPipe 流水并行与辅助损失无关负载均衡，全训练仅 278.8 万 H800 GPU 小时（论文 Table 1），且论文报告全程无不可恢复的 loss spike。
  3. auxiliary-loss-free 负载均衡兼顾性能与均衡：bias 动态调整避免了传统辅助损失对模型性能的损害，附录 Figure 10 显示其专家专业化模式更强（论文 §4.5.2）。
  4. MTP 多 token 预测一石二鸟：训练目标提升数据效率与表示预规划；推理时 MTP 模块可复用做投机解码，第二 token 接受率 85%-90%，生成速度提升约 1.8×（论文 §5.4.3）。
  5. 长上下文扩展平滑：YaRN 仅插值低频维度 + mscale² 修正，两阶段（4K→32K→128K）微调后 NIAH 测试在 128K 内表现稳定（论文 Figure 8）。
  6. 代码可读性极高：单文件 421 行、零依赖（仅 torch 与自定义 kernel），把 MLA 吸收、group top-k、YaRN、FP8 等核心机制浓缩成可逐行阅读的教学级实现。

局限

  1. 部署门槛高（论文 §6 明言）：为保证推理负载均衡与吞吐，预填充最小部署单元为 4 节点 32 卡、解码为 40 节点 320 卡，对小型团队不友好；671B 参数本身也需要多卡承载。
  2. MoE 通信是持续瓶颈：虽然训练侧用节点受限路由 + DualPipe 把 all-to-all 通信几乎全隐藏，但通信仍占用 20/132 个 SM（论文 §3.5），计算单元被通信任务挤占；论文建议未来硬件将通信 offload 到专用协处理器。
  3. FP8 受硬件掣肘：Hopper 的 FP8 GEMM 累加精度仅约 14 位，需 CUDA Core 提升（N_C=128 间隔）补偿，且 fine-grained 量化缺原生支持、有频繁的数据搬运开销（论文 §3.5.2）——FP8 收益高度依赖下一代硬件（Blackwell 的 microscaling 支持）。
  4. 上下文与推理速度仍有提升空间：论文自述端到端生成速度"超过 DeepSeek-V2 的两倍，但仍有提升空间"，且 128K 上下文相比前沿的无限上下文目标仍有限制。
  5. 参考实现的局限（本文代码本身）：dsv3_model.py 是教学/参考实现，未实现训练循环、MTP 模块、bias 的动态负载更新（以可学习参数代替）、以及论文中的冗余专家部署等工程细节；world_size=1 默认单卡，真实并行需外部初始化 dist。

2.2 每层的注意力形态由 compress_ratios[layer_id] 决定

Attention.__init__ 一行代码决定了该层是"纯窗口"还是"压缩注意力"（dsv4_model.py:466）：

self.compress_ratio = args.compress_ratios[layer_id]  # 取值 0 / 4 / 128
  • compress_ratio == 0：纯滑动窗口注意力（Sliding Window Attention, SWA）。只用窗口 128 内的原始 KV，不压缩、无索引器；RoPE 关闭 YaRN、用基础 rope_theta=10000（dsv4_model.py:488-494）。Flash 层 0/1 与最后一层，Pro 最后一层。
  • compress_ratio == 4：CSA（Compressed Sparse Attention）。KV 每 4 个 token 用门控池化压成 1 条，再用 Indexer 打分选 top-k（Flash 512 / Pro 1024），只对被选中的压缩条目做稀疏注意力（sparse_attn 内核）；压缩窗口重叠（overlap），边界更平滑。层内同时配 128 滑动窗口分支保留局部细粒度依赖。
  • compress_ratio == 128：HCA（Heavily Compressed Attention）。KV 每 128 个 token 压成 1 条，不做稀疏选择——对全部压缩条目做"稠密"注意力，但条目数只有 1/128，成本极低。

两种压缩层的 KV cache 布局统一为 window_size + max_seq_len // ratio：前 128 槽是滑动窗口环形缓冲，后面是压缩条目区（dsv4_model.py:486）；Compressor 拿到的是 kv_cache[:, win:]（dsv4_model.py:504）。

2.3 训练与服务侧要点（论文）

  • 预训练：Flash 32T token、Pro 33T token；序列长度 4K → 16K → 64K → 1M 渐进；前段用稠密注意力热身，到 64K 引入稀疏注意力，并先短暂热身 CSA 的 lightning indexer 再全面开启稀疏训练。
  • 优化器：Muon 用于绝大多数参数（动量 0.95、weight decay 0.1、RMS 重缩放 0.18）；AdamW 保留给 embedding、预测头、静态 bias/门控因子、RMSNorm 权重；Muon 的正交化用混合 Newton-Schulz 迭代（前几步系数 (3.4445, -4.7750, 2.0315) 快速收敛，后几步 (-1.5615, 0.6414) 精确稳定），并用 Nesterov 技巧。
  • 服务：DSpark（semi-autoregressive 推测解码：并行 MoE 主干 + 轻量顺序模块 + 置信度调度）部署在 DeepSeek-V4 服务系统，替代原 MTP-1 基线；离线与线上均验证 60%–85% 的每用户生成速度提升。

Compressor 压缩器（dsv4_model.py:288-387）——门控池化、overlap、ape、增量压缩、fp32、部分 RoPE、哈达玛旋转

代码位置与逐段含义

  • 初始化（293-315）：compress_ratio 传入 4（CSA）或 128（HCA）；self.overlap = compress_ratio == 4（300 行）——只有 ratio=4 启用重叠窗口；coff = 1 + overlap（302 行）使 wkv/wgate 输出 2×head_dim（overlap 时前半维用于重叠压缩、后半维用于常规压缩，见 306 行注释）。self.ape = nn.Parameter([r, coff*head_dim], fp32)（304 行）是块内位置的可学习门控偏置。wkv/wgate 是 Linear(dim → coff*head_dim, fp32)（307-308 行），即"值投影"与"压缩权重（门控）投影"。kv_state/score_state 两个 fp32 buffer（313-314 行）保存解码阶段的半成品：overlap 时 state[:, :ratio] 是重叠窗口、state[:, ratio:] 是当前窗口。
  • prefill 分支（335-352）：should_compress = seqlen >= ratio；先处理余数（remainder = seqlen % ratio，未满一个块的尾部 token 存入 state 待下次凑齐）；kv = kv.unflatten(1, (-1, ratio)) 把序列切成 [b, s/r, r, 2d] 的块；score = score.unflatten(...) + self.ape（348 行）给块内每个位置加门控偏置；overlap 时用 overlap_transform（317-324 行）把每个块扩成 2r 槽（前 r 槽来自上一块的"前半"，后 r 槽是当前块的"后半"，即相邻压缩条目重叠 r 个 token）；最后 kv = (kv * score.softmax(dim=2)).sum(dim=2)（352 行）——软掩码加权求和，一个压缩条目 = 块内 token 的门控加权和。
  • decode 分支（353-369）：每个新 token 先做 score += self.ape[start_pos % ratio]（355 行），写入 kv_state[start_pos % ratio] 槽；should_compress = (start_pos+1) % ratio == 0（354 行）——凑满 r 个才触发一次压缩；压缩时对 state 中所有槽做同样的 softmax → sum（362/369 行），overlap 时还要把"当前窗口"整体搬进"重叠窗口"槽位（363-364 行）。这就是增量式 decode 压缩：解码过程中 KV 不立即写入压缩缓存，而是先在小的固定缓冲里累积，满一个块才落一条。
  • 压缩后处理（370-387）：未凑满则直接 return（370-371 行）；凑满后 kv = self.norm(kv.to(dtype))（RMSNorm，372 行）；取该压缩块对应的 freqs_cis（prefill 为 [:cutoff:ratio]，decode 为 [start_pos+1-ratio]，373-376 行）；apply_rotary_emb(kv[..., -rd:], freqs_cis)（377 行）——RoPE 只作用于每条压缩 KV 的尾部 rope dims（64 维）；随后 rotate_activation（哈达玛旋转，256-260 行）+ fp4_act_quant（Indexer 场景）或 act_quant(kv[..., :-rd], 64, ...) 为什么这样写（设计动机/收益）

  1. 压缩 = 可学习门控池化而非平均池化。用 wgate 学一个"这个 token 对块摘要的贡献"软掩码，softmax 后加权求和，模型可以自主决定哪些 token 信息主导压缩条目（例如放弃停用词、保留关键词）；ape 让块内每个位置拥有独立的门控偏置，避免位置信息在池化中被抹平。
  2. overlap 只在 ratio=4 用。ratio=4 时每个压缩条目只覆盖 4 个 token，边界截断会造成信息跳变；重叠 4 个 token 让相邻条目共享上下文，边界更平滑。ratio=128 时条目本身已很"粗"，重叠的边际收益低且代价高，故关闭。
  3. fp32 计算（332 行）。压缩是 KV cache 的唯一入口，任何误差都会被所有后续 token 的注意力反复放大；门控加权和在 fp32 下做，配合 RMSNorm（fp32 参数，194 行）避免低精度误差累积。
  4. 部分 RoPE + 混合精度存储。只有位置敏感的最后 64 维旋转（与主注意力 qk_rope_head_dim=64 一致），非 rope 维保持"语义内容"可直接量化；论文 2.3.4 明确指出 KV 用 BF16(rope 维)+FP8(其余维)混合存储，cache 体积接近减半。Indexer 侧更进一步：压缩 KV 先经哈达玛旋转把信息均匀扩散到各维（消除离群值），再 FP4 量化——量化误差被旋转"摊平"，这是 QAT 之外的无损化手段。
  5. 增量式 decode 压缩使解码路径完全 O(1) 维护：无需重算历史块，状态缓冲大小固定（coff*ratio × coff*head_dim），与序列长度无关——这是 1M 上下文下逐 token 生成可行的前提。

为什么这样写（设计动机/收益）

  1. "决定看哪里"与"认真看"解耦。主注意力 head_dim=512、对每个位置做稠密/稀疏注意力成本高；Indexer 用 64×128 的小头以极低代价为每个 query 预筛出 top-K 压缩块，主注意力 sparse_attn 只对被选中的位置计算——论文称其为 lightning indexer，注意力计算在 FP4 下进行（论文 2.3.4），1M 上下文时收益巨大。
  2. q 复用主注意力低秩 qr（1024/1536 维）。这是"零额外前向"的关键设计：Indexer 不需要从 x 单独投影 query，直接消费 Attention 已经算好的低秩中间态，只多一个 wq_b（q_lora_rank → 64×128）的小矩阵。
  3. 逐头加权 + relu+sum 的"投票"式聚合。不同头可能关注不同类型的压缩块（如有的头偏位置、有的头偏内容），weights_proj 学习每头对最终分数的贡献权重；ReLU 保证只有"正相关"的头参与投票，避免负分头互相抵消；最终单分数 topk 稳定且可并行。
  4. 自带压缩器而非复用主压缩器。打分需要低延迟、低精度、位置信息少的小 KV（128 维 + FP4），与主注意力 512 维的 BF16/FP8 压缩 KV 用途不同；独立压缩器让两者各取所需。论文 5.2.1 提到索引分数从 FP32 量化到 BF16，top-k 选择器获得 2× 加速且保持 99.7% 召回。

代码位置与逐段含义

  • 初始化（778-792）：继承 Block（含 Attention+MoE+HC 全套）；新增 e_proj(dim→dim)、h_proj(dim→dim)、enorm、hnorm、norm 五个模块（780-784 行）；HC 头参数 hc_head_fn[hc_mult, hc_dim]、hc_head_base[hc_mult]、hc_head_scale[1]（788-790 行）；embed/head 由外部注入（791-792 行）。
  • forward（794-804）：e = self.embed(input_ids)（798 行，取下一位置 token 的 embedding）；enorm(e)（799 行）；hnorm(x)（800 行）；x = self.e_proj(e).unsqueeze(2) + self.h_proj(x)（801 行）——把"下一 token 的 embedding 特征"加进当前隐藏状态（unsqueeze(2) 对齐 HC 的 4 份通道）；再走一遍完整 Block（802 行）；logits = self.head(x, hc_head_fn, ...)（803 行）输出下一 token 预测。
  • 装配（Transformer 827-831 行）：self.mtp.append(MTPBlock(n_layers + layer_id, args)) 且 mtp[-1].embed = self.embed; mtp[-1].head = self.head——MTP 与主干共享 embedding 与 lm_head。

为什么这样写（设计动机/收益）

  1. 共享 embed/head 几乎不增加参数，MTP 只是一个"额外走一遍 Block 的深度监督头"；num_nextn_predict_layers: 1（config），训练时 MTP loss 权重 0.3（学习率衰减开始后降至 0.1，论文 4.2.2）。
  2. 利于推测解码（关联 DSpark）：MTP 天然给出"下一 token 分布的提前预测"——DSpark 论文明确指出 DeepSeek-V4 服务系统旧的线上生产基线就是 MTP-1（单 token 的 MTP 配置），DSpark 在其后两周内上线取代之；DSpark 的草稿模型共享目标模型的 embedding 与 lm_head（DSpark 论文 2.2），与 MTP 的共享设计一脉相承。有了 MTP/共享头的结构，草稿模型的边际训练与服务成本都很低。
  3. h_proj + e_proj 的信息融合：e_proj(e) 注入"将要预测什么 token"的线索，h_proj(x) 保留"当前看到什么"的上下文，两者相加后过 Block——MTP 头可以"看着下一个 token 的 embedding 预测它的分布"，等价于把 next-token 任务的难度提前分摊。

FP4/FP8 量化与内核（dsv4_model.py:108-157）——linear 分派、fp4_block_size=32、weight.scale

代码位置与逐段含义

  • linear() 分派（108-125）：按权重 dtype 三选一——torch.float4_e2m1fn_x2 → act_quant(x, block_size=128, ...) 量化激活后走 fp4_gemm（116-120 行，DeepGEMM 的 FP8 激活 × FP4 权重混合精度 GEMM）；torch.float8_e4m3fn → fp8_gemm（121-123 行）；否则 F.linear（125 行）。所有量化路径都先对激活做 act_quant（动态量化，论文 activation_scheme: dynamic）。
  • Linear 权重布局（128-157）：FP4 权重形状 [out, in//2]（E2M1 两元素打包一个字节），scale 形状 [out, in//32]（fp4_block_size=32，每 32 个 FP4 元素沿 K 共享一个 FP8 scale，139-142 行）；FP8 权重 [out, in]，scale [ceil(out/128), ceil(in/128)]（block_size=128，144-147 行）；self.weight.scale = self.scale（142/147 行）把 scale 挂到权重上随 checkpoint 存储。
  • 配套：ColumnParallelLinear/RowParallelLinear（160-185 行）做 TP 分片；RMSNorm 参数 fp32 存储 bf16 checkpoint（194 行）；rotate_activation（256-260 行）哈达玛旋转。

为什么这样写（设计动机/收益）

  1. 两级量化策略：主体权重 FP8（E4M3）+ 专家权重 FP4（E2M1），README 明确 "FP4 + FP8 Mixed: MoE expert parameters use FP4; most other parameters use FP8"。论文 5.2.1 还披露了关键技巧：FP4→FP8 反量化是无损的（FP8 多 3 个指数位、动态范围更大，只要 FP4 子块 scale 比值不超阈值即可完全吸收），因此训练管线可完全复用 FP8 框架（FP32 master → FP4 存储 → FP8 计算）。
  2. 分组 scale：FP4 用 32 粒度、FP8 用 128 粒度（weight_block_size: [128,128]），在"显存节省"与"量化误差"之间取平衡；scale 本身用 FP8（E8M0）进一步压缩。
  3. QAT 配套（论文 5.2.1）：post-training 阶段用 Quantization-Aware Training 让模型适应量化退化，覆盖 teacher 与 reference 模型；推理代码中用 act_quant 对激活做同样的 FP8/FP4 模拟，保证训练-推理一致（如 522 行对 kv 非 rope 维的 FP8 模拟注释： "FP8-simulate non-rope dims to match QAT"）。

ParallelHead（dsv4_model.py:741-773）——hc_head sigmoid 合并 hc 份

代码位置与逐段含义

  • 初始化（743-751）：weight = nn.Parameter([part_vocab, dim], fp32)（751 行）——lm_head 权重 fp32 存储（checkpoint 为 bf16），便于稳定计算 logits。
  • forward（756-764）：x = self.hc_head(x, hc_fn, hc_scale, hc_base)（758 行）——先把 HC 的 4 份状态合并回 1 份；logits = self.get_logits(norm(x))（759 行）——get_logits 只取 x[:, -1]（最后一个 token）乘权重（753-754 行）；TP 下 all_gather 拼回完整词表（760-763 行）。
  • hc_head（766-773）：与 hc_pre 相同的动态参数化，但合并门控用 pre = sigmoid(mixes * hc_scale + hc_base) + hc_eps（771 行）——sigmoid 保证门控 ∈ (0,1) 且非负（对应论文式 6 的输入映射约束），+hc_eps 防止全零门控；y = sum(pre_j * x_j)（772 行）加权合并。

为什么这样写（设计动机/收益）

  1. HC 的"收官"：所有 Block 保持 4 份状态并行，只在最后一步合并，最大化 mHC 的信号传播收益；合并门控沿用 sigmoid 约束保证非负、不抵消。
  2. fp32 logits：lm_head 权重与计算在 fp32（751/754 行），词表 129280 的 logits 是数值敏感点，fp32 避免采样分布被低精度污染。
  3. get_logits 只算最后一个位置：生成场景 logits 只用于最后一个 token，x[:, -1] 直接切片省掉整序列 × 词表的巨型矩阵乘。

5.1 Compressor 门控池化核心（dsv4_model.py:326-352, prefill 路径）

def forward(self, x: torch.Tensor, start_pos: int):
    bsz, seqlen, _ = x.size()
    ratio, overlap, d, rd = self.compress_ratio, self.overlap, self.head_dim, self.rope_head_dim
    dtype = x.dtype
    x = x.float()                      # 压缩全程 fp32，避免误差被注意力放大
    kv = self.wkv(x)                   # 值分支：[b,s,coff*512]
    score = self.wgate(x)              # 门控分支：学习"每个 token 对块摘要的贡献"
    if start_pos == 0:                 # ---- prefill：整段压缩 ----
        should_compress = seqlen >= ratio
        remainder = seqlen % ratio
        cutoff = seqlen - remainder
        if remainder > 0:              # 尾部不足一个块的 token 存入 state 待下次
            kv, self.kv_state[...] = kv.split([cutoff, remainder], dim=1)
            self.score_state[...] = score[:, cutoff:] + self.ape[:remainder]
            score = score[:, :cutoff]
        kv = kv.unflatten(1, (-1, ratio))          # [b, s/4, 4, 2d]
        score = score.unflatten(1, (-1, ratio)) + self.ape   # 块内位置门控偏置
        if overlap:                                # ratio==4 时重叠窗口
            kv = self.overlap_transform(kv, 0)                 # 扩成 2r 槽
            score = self.overlap_transform(score, float("-inf"))  # 无效槽门控 -inf
        kv = (kv * score.softmax(dim=2)).sum(dim=2)  # 软掩码加权和 → 1 条压缩 KV

解读：wkv/wgate 双分支 + ape 位置偏置 + softmax 归一化 + 加权求和，四步构成"可学习门控池化"。overlap_transform 的关键在 322-323 行：new_tensor[:,:,ratio:] = tensor[:,:,:,d:]（当前块后半）与 new_tensor[:,1:,:ratio] = tensor[:,:-1,:,:d]（上一块前半，整体下移一格）——相邻压缩条目共享 r 个 token。

设计理由：如果只是平均池化，摘要会丢失关键词信息；门控让模型自行决定保留谁，ape 弥补池化丢失的位置线索，overlap 平滑块边界。fp32 兜底 + 后续 act_quant/fp4_act_quant 的量化出口，保证 1M 上下文下压缩 KV 的精度不劣化。

5.5 Hyper-Connections 混合（dsv4_model.py:703-716）

def hc_pre(self, x, hc_fn, hc_scale, hc_base):
    shape, dtype = x.size(), x.dtype
    x = x.flatten(2).float()                          # [b,s,4d]
    rsqrt = torch.rsqrt(x.square().mean(-1, keepdim=True) + self.norm_eps)
    mixes = F.linear(x, hc_fn) * rsqrt                # 动态参数：24 维
    pre, post, comb = hc_split_sinkhorn(mixes, hc_scale, hc_base,
                                        self.hc_mult, self.hc_sinkhorn_iters, self.hc_eps)
    y = torch.sum(pre.unsqueeze(-1) * x.view(shape), dim=2)   # 4 份 → 1 份
    return y.to(dtype), post, comb

def hc_post(self, x, residual, post, comb):
    y = post.unsqueeze(-1) * x.unsqueeze(-2) \
        + torch.sum(comb.unsqueeze(-1) * residual.unsqueeze(-2), dim=2)  # 1 份 → 4 份
    return y.type_as(x)

解读：hc_pre 内 hc_split_sinkhorn（来自 kernel.py）把 24 维输出拆成 pre[4]、post[4]、comb[4,4]，其中 comb 经 Sinkhorn-Knopp 投影为双随机矩阵；hc_post 的 comb[i,j]·residual_j 即"第 j 份旧状态对第 i 份新状态的贡献"。hc_scale[3]/hc_base[24] 是静态门控与偏置，hc_eps 防零。

设计理由：这是 mHC 的"纯数学"版本——Sinkhorn 投影把残差映射约束到 Birkhoff 多面体（谱范数 ≤ 1，非扩张，集合对乘法封闭，论文式 2/8），深度堆叠时信号既不爆炸也不消失；sigmoid 化的 pre/post（论文式 6-7）保证非负、不抵消。层内只处理合并后的单份状态，故计算开销接近普通残差，却额外获得 4 条残差通路。

6. 优点与局限

优点

  1. 长上下文效率的量级跃升。CSA+HCA 混合注意力 + KV 压缩 + 稀疏内核，官方给出 1M 上下文下 V4-Pro 推理 FLOPs 降至 V3.2 的 27%、KV cache 降至 10%（README/论文摘要）；论文 2.3.4 对比 BF16 GQA8（head_dim 128）基线，1M 上下文时 cache 可缩小约两个数量级（论文原文称 "dramatically reduced approximately [N] times"，具体数字因文本损坏缺失，需以官方为准）。
  2. 工程完整度高：混合精度存储（rope 维 BF16 + 其余 FP8）、Indexer 全 FP4、FP4 专家 + FP8 主体的两级量化、sparse_attn/fp4_gemm/fp8_gemm 定制内核、QAT 训练-推理一致（act_quant 模拟）、增量式 decode 压缩——每一环都为 1M 上下文服务。
  3. 数值稳定性设计系统化：mHC 用 Sinkhorn 约束残差谱范数、q 用 RMSNorm 替代 QK-Clip、压缩全程 fp32、logits fp32——从注意力到优化器（Muon 的混合 Newton-Schulz + Nesterov）都有数学依据，论文 2.2/2.4 明确这些设计的动机是"深度堆叠稳定"。
  4. 训练-推理-服务三层联动：哈希路由提供激活局部性、MTP 共享头支撑推测解码（MTP-1 → DSpark 60%–85% 提速）、on-disk cache 三种策略（全量缓存/周期检查点/零缓存）按部署场景取舍存储与算力。
  5. 开源与生态：MIT 协议、Flash/Pro 双版本、Base/Instruct 四件套，上下文 1M 且推理成本大幅低于前代，推动长上下文开源模型的可用性。

局限

  1. 论文文本质量有限（本文引用论文处基于 zlib 抢救的 token 流，单词截断严重，个别数字如"cache 缩小倍数""dense warmup token 数"无法精确还原，建议以官方 arXiv 版本为准）。
  2. 注意力是"有损摘要"：压缩条目丢失块内细粒度信息，极端任务（如需要逐字对齐的抽取、1M 级精确检索）可能不如全注意力；index_topk 限制了每个 query 的全局视野（Flash 512 / Pro 1024 条），理论上存在"关键信息未被选中"的召回风险（论文以 99.7% 召回率回应，但那是 top-k 选择器量化前后的对比，不是对内容召回的整体保证）。
  3. 复杂性与部署门槛高：混合注意力带来异构缓存（窗口 + CSA/HCA 压缩 + Indexer 自己的缓存），论文 3.5 明确指出这违背 PagedAttention 的基本假设，需要定制缓存布局与稀疏内核协同设计；sparse_attn/hc_split_sinkhorn 等依赖私有内核（kernel.py），脱离 DeepSeek 生态难以直接移植。
  4. 哈希路由的表达力折衷：前 3 层路由与上下文无关，同 token 恒走同专家，虽换来局部性，但牺牲了浅层的上下文自适应（DeepSeek 用"只在前 3 层"控制损失）。
  5. 显存与推理优化的"双刃剑"：FP4 专家需要 fp4_block_size=32 分组 scale 与 FP8 反量化通路，若部署硬件不支持 FP4 GEMM 则需额外转换；swiglu_limit 钳制虽稳定量化，但也在训练后固定了激活范围。

注意力路线对比（重点：V3 的 MLA → V4 的 CSA+HCA 演进）：V3 系（V3/V3.1/V3.2）的核心是 MLA——用低秩投影压缩 KV 的维度，再叠加 DSA 稀疏注意力与滑动窗口；V4 保留了 MLA 的低秩 Q/KV 与共享 KV（wq_a/q_norm/wq_b、wkv/kv_norm，dsv4_model.py:470-474），但在时间轴上新增两级压缩：CSA（4:1 门控池化 + Indexer 选 top-k）与 HCA（128:1 重压缩），并让每层由 compress_ratios[layer_id] 决定采用哪种形态（0/4/128，dsv4_model.py:466）。这本质上是把 DSA 的"稀疏选择"前移到了压缩块层：先压缩再稀疏，两者叠加才换来 1M 上下文的量级收益。

与其他厂商长上下文注意力路线的差异：

  • GLM（DSA 系）：GLM 采用 DeepSeek Sparse Attention 思路的稀疏注意力（token 级 top-k 选择 + 无压缩），KV 仍按原始 token 存储；V4 的 CSA 是"先压缩、后稀疏"，Indexer 选择的粒度是压缩块而非原始 token——V4 的 KV 存储与注意力算力同时下降，而 DSA 系主要省算力、省不了多少存储。
  • Kimi（KDA / MoBA 类块级稀疏）：MoBA 用块级 top-k 稀疏注意力（KV 不压缩、直接选原始 token 块）；V4 与 MoBA 相似处是"块级选择"，但 V4 额外引入可学习门控池化压缩（KV 本身变小）与轻量 Indexer 预筛（低秩小头打分），MoBA 的块选择更多基于查询-块相似度且不做 KV 维度/数量双重压缩。
  • Qwen（GatedDeltaNet 等线性注意力）：Qwen3-Next 系用线性注意力/门控 DeltaNet（状态压缩为固定大小矩阵，O(1) 记忆，但依赖固定状态表达，长程精确回忆受限）；V4 走"显式稀疏 + 显式压缩"路线，压缩条目仍是可检索的内容摘要（门控池化 + top-k 选择），不牺牲精确注意力的可解释性，代价是需要 Indexer 与稀疏内核的工程复杂度。
  • 共性：三家都认同"全注意力不可行"，但 V4 的选择是"压缩 + 稀疏"双管齐下 + 服务端推测解码，把效率压榨到了从架构到内核到服务的每一层。

几个关键结构关系：

  1. DecoderLayer = MLA 注意力 + MoE/稠密 MLP 交错（源码:594-638）。config.mlp_layer_types[layer_idx] 决定第 layer_idx 层是 "sparse"（挂 GlmMoeDsaMoE）还是 "dense"（挂 GlmMoeDsaMLP）；本配置前 3 层 dense、其余 75 层 sparse（config:110-189），与 first_k_dense_replace=3（config:14）呼应——早期层用稠密 MLP 稳定训练，这是 DeepSeek 系 MoE 的惯例。
  1. indexer_types 与 layer_types 的关系。indexer_types[layer_idx]（config:26-105）决定该注意力层是 "full"（自带 GlmMoeDsaIndexer）还是 "shared"（复用最近上层 full 的 top-k 索引），见源码:366-367（self.skip_topk = config.indexer_types[layer_idx] == "shared"）与 422-436。而 layer_types 是本建模文件之外、由 configuration_glm_moe_dsa.py（不在本次材料中）提供的属性：GlmMoeDsaModel.forward 用 causal_mask_mapping[self.config.layer_types[i]] 为每层挑选 create_causal_mask 生成的掩码（源码:727, 736，key 为 "deepseek_sparse_attention"），推测 layer_types 由 indexer_types 派生，用于把 full/shared 语义映射到 DSA 专用因果掩码。
  1. IndexShare 的数据流是一条贯穿 78 层的 topk_indices 接力（源码:732-743）：GlmMoeDsaModel.forward 用 topk_indices = None 初始化，然后逐层把上一层的 topk_indices 作为 prev_topk_indices 传给下一层（741）；每个 DecoderLayer 返回 (hidden_states, topk_indices)（638），full 层返回自己新算的索引，shared 层原样透传（470, 436）。实现上只是一个额外参数 + 一次 if-else——这正是 IndexShare 论文所说的"单条件分支"（arXiv:2603.12201 §3）。
  1. 复杂度账本。核心注意力被 top-k 稀疏化到 O(L·k)（k=2048），但 DSA 索引器本身仍是 O(L²)（轻量：32 头 × 128 维、低秩投影），且论文实测相邻层 top-k 交集高达 70-100%（IndexShare 论文 Appendix A），所以"每 4 层算一次索引器"把索引器总成本从 O(N·L²) 降到 O(N·L²)/4。README 给出 1M 上下文下每 token FLOPs 降 2.9×。

4. 核心组件解读

GlmMoeDsaIndexer 索引器（modeling_glm_moe_dsa.py:164-255）

代码位置：164-255；构造 177-193，前向 195-255。

代码含义（逐段）：

  • 构造（177-193）：与主 MLA 完全分离的一套轻量投影——wq_b: Linear(2048, 32×128)（189）从 q_resid 投影 query；wk: Linear(6144, 128)（190）从 hidden_states 投影 key；k_norm: LayerNorm(128, eps=1e-6)（191）；weights_proj: Linear(6144, 32)（192）为每个头算一个标量权重；softmax_scale = 128^(-0.5)（193）。
  • 前向（195-255）：
  • q = wq_b(q_resid) 并 view 成 [B,S,32,128]（224-225）；k = k_norm(wk(x)) 成 [B,S,1,128]（228）；
  • 各自 split 出 qk_rope_head_dim=64 的 rot 段与 pass 段（226, 229），rot 段做 interleaved RoPE（232，注释 231 明确"GLM-MoE-DSA uses interleaved RoPE in the indexer"），再拼回（233-234）；
  • key 进索引器 KV 缓存：past_key_values.update_indexer(k, layer_idx)（237）——解码时索引器也要能看全历史；
  • scores = matmul(q.float(), k^T) × scale（239，fp32 计算），F.relu 截断负分（240）；
  • 逐头加权：weights = weights_proj(x) × 32^(-0.5)，index_scores = weights·scores（243-244），把 32 个头的打分折叠成每个 (query, key) 一个分数；
  • 因果性：有 mask 就加 mask，否则手动 masked_fill（247-252）；
  • topk = min(index_topk, T)（254），topk(…).indices.to(torch.int32)（255）返回 int32 索引 [B,S,2048]。

为什么这样写：

  • query 直接复用 MLA 的 q_resid（低秩 2048 维潜变量）而非重新投影 x：索引器与主注意力共享语义空间，又省掉一次 6144→ 的大矩阵乘，保持"lightning"的轻量定位（IndexShare 论文 §2.1：索引器比 MLA 每 FLOP 便宜一个数量级）。
  • ReLU + 逐头加权求和：ReLU 把"负相关"的 token 清零，加权求和模拟多头的集体投票，只保留一个聚合分数再 top-k，避免为每个头各自选 top-k 带来的掩码膨胀。
  • 返回 int32 索引而非稀疏掩码：这是与 DeepSeek-V3.2 的显式差异——DSV3.2 的 indexer 直接返回"选中处 0、其余 -inf"的加法掩码（类 docstring 168-171 还残留着这段描述，属于 modular 拷贝的痕迹），而 GLM 返回索引，因为 flash-mla 内核直接吃索引（464），eager/sdpa 才在 Attention 内 scatter 成掩码（439-449）。文档字符串（219-220）与实现一致：int32 top-k token indices。
  • fp32 打分 + 确定性 topk：GLM-5 论文专门指出 RL 阶段用确定性的 torch.topk 解决训练/推理不一致（glm5_tech_report.txt:643-660）；fp32 计算同理是为保证可复现。

GlmMoeDsaTopkRouter（modeling_glm_moe_dsa.py:489-527）

代码位置：489-527。

代码含义：

  • 参数：weight [256, 6144]（495，零初始化）；e_score_correction_bias 是 nn.Buffer（500）而非 Parameter——它是训练中学习、推理中固定的打分偏置。

  • sigmoid（而非 softmax）打分 + 偏置校正：sigmoid 输出是"这个专家是否适用"的独立概率，配合 noaux_tc（无辅助损失）路由，避免 softmax 的耦合归一化；e_score_correction_bias 让模型在训练中微调选择边界而不动主权重。
  • 分组 top-2 预筛：n_group>1 时先用廉价的组分数砍掉大部分组，再在幸存组内做精确 top-8，把 top-k 从 O(E) 降到 O(E/n_group + k·n_group)（DeepSeek 论文的动机）；GLM-5.2 把 n_group 设为 1，等于关闭该加速但保留代码路径。
  • 权重取"选择前"的分数：避免偏置污染路由权重的相对大小。

RoPE interleave（modeling_glm_moe_dsa.py:125-161）

代码位置：125-161；RotaryEmbedding 68-122。

代码含义：

  • GlmMoeDsaRotaryEmbedding 按 rope_theta=8e6 生成 inv_freq，emb = cat(freqs, freqs) 后取 cos/sin（118-120）。
  • apply_rotary_pos_emb_interleave（125-161）：先取 cos/sin 的前半（153-154，每个频率只对应一对旋转角），再把 q/k 拆成奇偶切片 q[..., 0::2] / q[..., 1::2]（156-157），按 q1·cos − q2·sin、q2·cos + q1·sin 旋转后拼回（159-160）。交错布局：相邻维 (x0, x1) 组成一对，由同一个频率旋转。
  • 在注意力里只对 q_rot/k_rot（64 维 = 32 对）旋转（412），索引器同理（232）；config rope_interleave=true、indexer_rope_interleave=true（config:25, 210）。

为什么这样写：

  • 与 DeepSeek 半切布局的差异：DeepSeek 系传统实现（rotate_half）把维度按"前半/后半"配对 (x_i, x_{i+d/2})；而交错布局按"奇偶相邻"配对 (x_{2i}, x_{2i+1})——两者只要频率指派一致就是位一致的等价旋转。文档字符串（129-132）明确说明：GLM 直接在奇偶切片上算旋转，避免 view/transpose/reshape 去交错带来的额外 contiguous 拷贝——在 1M 上下文下，这是每层每 token 都要省的搬运。
  • 索引器 docstring（208-209）点出差异：DSV3.2 索引器用非交错（半切）RoPE，GLM 索引器与主注意力统一用交错 RoPE。
  • 一个需要如实标注的技术疑点：compute_default_rope_parameters（99）取 config.head_dim（本配置 JSON 为 192）生成频率，则 cos/sin 半区为 96，与 32 对旋转维失配（已用 torch 实测复现 RuntimeError）。这暗示 released 的 configuration_glm_moe_dsa.py 必然把该维度归一为 qk_rope_head_dim=64（2×64 维 emb、半区 32 对），或官方 config 与本副本不同——本地的 head_dim=192（GLM-5 遗留的 qk_nope 维度，tech report Table 10 "QK Head Dim 192"）不应被直接理解为 RoPE 维度。教学上按"rope 维度 = qk_rope_head_dim = 64"理解 interleave 语义即可。

5.4 路由器：sigmoid + 偏置 + 分组 top-2 预筛（源码:502-527）

router_logits = F.linear(hidden_states.type(torch.float32), self.weight.type(torch.float32))
scores = router_logits.sigmoid()
scores_for_choice = scores + self.e_score_correction_bias          # 偏置只影响选择
group_scores = (scores_for_choice.view(-1, self.num_group, self.num_experts // self.num_group)
                .topk(2, dim=-1)[0].sum(dim=-1))                    # 组内 top-2 求和
group_idx = torch.topk(group_scores, k=self.topk_group, dim=-1, sorted=False)[1]
group_mask = torch.zeros_like(group_scores); group_mask.scatter_(1, group_idx, 1)
score_mask = (group_mask.unsqueeze(-1).expand(-1, self.num_group, self.num_experts // self.num_group)
              .reshape(-1, self.num_experts))
scores_for_choice = scores_for_choice.masked_fill(~score_mask.bool(), float("-inf"))
topk_indices = torch.topk(scores_for_choice, k=self.top_k, dim=-1, sorted=False)[1]
topk_weights = scores.gather(1, topk_indices)                      # 权重取原始分数
if self.norm_topk_prob:
    denominator = topk_weights.sum(dim=-1, keepdim=True) + 1e-20
    topk_weights /= denominator
topk_weights = topk_weights * self.routed_scaling_factor            # ×2.5

解读：e_score_correction_bias 是 nn.Buffer（500）且被声明为严格 fp32（_keep_in_fp32_modules_strict，658）——训练学、推理固定、语义必须确定。n_group=1 时组掩码恒真，整段退化为"全局 top-8"；topk_weights 用未加偏置的 scores 并归一化后放大 2.5 倍。设计理由：选择与加权解耦（偏置管边界、权重管大小），sigmoid 独立概率配合无辅助损失路由，归一化 × 缩放保证输出尺度稳定。

5.5 专家计算：one-hot 掩码 + 逐专家 GEMM + index_add_（源码:549-567）

final_hidden_states = torch.zeros_like(hidden_states)
with torch.no_grad():
    expert_mask = torch.nn.functional.one_hot(top_k_index, num_classes=self.num_experts)  # [S,8,E]
    expert_mask = expert_mask.permute(2, 1, 0)
    expert_hit = torch.greater(expert_mask.sum(dim=(-1, -2)), 0).nonzero()
for expert_idx in expert_hit:
    ...
    top_k_pos, token_idx = torch.where(expert_mask[expert_idx])
    current_state = hidden_states[token_idx]
    gate, up = nn.functional.linear(current_state, self.gate_up_proj[expert_idx]).chunk(2, dim=-1)
    current_hidden_states = self.act_fn(gate) * up
    current_hidden_states = nn.functional.linear(current_hidden_states, self.down_proj[expert_idx])
    current_hidden_states = current_hidden_states * top_k_weights[token_idx, top_k_pos, None]
    final_hidden_states.index_add_(0, token_idx, current_hidden_states.to(final_hidden_states.dtype))

解读：3D 权重 [E, 2·inter, H] / [E, H, inter] 切片即单专家；gate_up_proj 一次 GEMM 出 gate 与 up；index_add_ 原子累加多专家输出。设计理由：use_experts_implementation 装饰器（530）允许训练/推理引擎用融合内核替换这个 Python 循环；3D 布局天然适配 EP（按专家切分）与 TP（按维切分），且消除 256 个独立模块的调度开销。

6. 优点与局限

优点

  1. 架构简洁、复用 DeepSeek 系成熟组件：MLA + MoE + sigmoid 路由 + 共享专家都是经过验证的 DeepSeek-V3 家族设计，DSA 索引器与 DeepSeek-V3.2 同源（源码注释明示"Same as DeepseekV32Indexer"），工程风险低。
  2. IndexShare 是"用极简工程实现大收益"的典范：不新增结构、只改一个分支与一个参数，砍掉 75% 索引器计算；1M 上下文每 token FLOPs −2.9×（README），30B 规模实测 prefill 1.82× / decode 1.48×（IndexShare 论文 Table 1），且论文给出了训练感知版（多层蒸馏）的理论保证（梯度等价于对平均分布蒸馏）。
  3. 双路径设计兼顾正确性与性能：eager/sdpa 用 scatter 掩码保移植性，flash-mla 内核直接消费 int32 索引走极致性能；fp32 打分与确定性 topk 保障 RL 训练/推理一致性（GLM-5 论文明确为此放弃非确定性 CUDA topk）。
  4. 1M 上下文的系统性工程：从 rope_theta=8e6、max_position_embeddings=1M，到 MTP（num_nextn_predict_layers=1 + index_share_for_mtp_iteration）与 IndexShare 的组合，是"架构 + 推测解码 + 稀疏化"三件套的完整落地。
  5. MIT 开源 + 全栈国产芯片适配：README 列出 SGLang/vLLM/KTransformers/Unsloth 及昇腾等七家国产平台。

局限

  1. HF 侧内核未闭环：_supports_flash_attn = False（648）且注释自承 "flash-mla kernels need a bit more work"——indices 参数已就位但官方内核接入未完成，eager/sdpa 的 scatter 掩码路径在 1M 上下文下显存/开销可观。
  2. IndexShare 的模式敏感性与未公开的搜索细节：论文实证 uniform 交错在 1/4 保留率下质量明显下降（Long Avg 50.2→43.0），必须用贪心搜索或训练感知蒸馏；GLM-5.2 直接采用 FSSS 均匀模式，其收益建立在"训练时就让索引器服务 4 层"的假设上，而具体训练细节（蒸馏损失权重、warm-up 步数）不在公开材料中。
  3. 参数量与论文对齐度存疑：tech report 是 GLM-5 的（744B/40B、Table 10 记 3 dense + 75 MoE = 78 层，但正文又说"层数降到 80"），GLM-5.2 的独立技术报告未提供；README 数据与模型卡一致但缺乏自证。
  4. RoPE 维度配置存在不一致（见 §4 末尾）：本地 config head_dim=192 与 qk_rope_head_dim=64 组合在 eager 路径会形状失配（已实测复现），真实发布配置必然另有归一化——这提醒 auto-generated 代码的配置与实现之间存在"校验真空"。
  5. 稀疏注意力的固有权衡：top-k=2048 在大上下文下仍要显式选 token，索引器 O(L²) 打分会随 L 增长；IndexShare 缓解了层维度，但 token 维度上预填充成本仍随上下文超线性增长（论文 prefill 时索引器占比 27%→81%，随 10K→200K 上升）。
  6. 依赖 serving 侧特性：index_skip_topk_offset、index_topk_pattern（config 中为 null）等键由推理框架消费，HF 建模文件不读取，跨框架行为一致性依赖各引擎自行实现。

2.1 两种注意力的交错排布

配置中的 linear_attn_config 显式列出两层表（1 起编）：

  • full_attn_layers = [4, 8, 12, …, 88, 92, 93]（24 个）——Gated MLA 层；
  • kda_layers = [1, 2, 3, 5, 6, 7, …, 89, 90, 91]（69 个）——KDA 层。

69 + 24 = 93，恰好覆盖全部层。可见排布规律是"每 4 层一组：3 层 KDA + 1 层 MLA"，MLA 落在 4, 8, 12, …, 92，最后再追加一层 MLA（层 93），保证末层一定是全局注意力（论文 §2.1："An additional Gated MLA layer is placed at the end of the backbone"）。由于 KDA 是带固定大小状态的线性注意力，它天然支持超长序列，而 MLA 提供无位置约束的全量内容交互，二者按 3:1 混合。KimiDynamicCache.__init__（kimi_k3_linear_modeling.py:131-139）正是通过 config.is_kda_layer(i) 把每层标记为 linear_attention 或 full_attention，从而决定走哪套缓存。

2.2 AttnRes 块残差（深度维）

attn_res_block_size = 12（配置），即把 93 层分成 8 个 12 层块（末块只有 9 层，是"partial final block"），加上第 0 层输入的 token embedding 作为源头，共 9 个块级表示（论文 §2.2）。KimiDecoderLayer._forward_attn_res（kimi_k3_linear_modeling.py:973-1046）在每个块边界层（layer_idx % 12 == 0）把当前 prefix_sum 追加进 block_residual，其余层则把注意力输出与 FFN 输出累加进 prefix_sum，最后在注意前后各做一次 _apply_attn_res 学习加权（详见 §4.3）。

2.3 MoE 从第 1 层开始

first_k_dense_replace = 1 且 moe_layer_freq = 1，因此 0 基第 0 层使用稠密 KimiMLP，第 1 层起全部使用 KimiSparseMoeBlock（kimi_k3_linear_modeling.py:893-900）。这与 README"Number of Dense Layers: 1"一致。

2.4 长上下文与 NoPE

K3 全文不施加显式位置编码：MLA 的 rotary_emb = None（kimi_k3_linear_modeling.py:403）且 forward 中从不调用 RoPE（position_ids 只用于 mask），位置信息完全由 KDA 的循环门控与衰减机制隐式携带（论文 §3.4："the model extrapolates directly to 1M-token contexts without any positional-encoding modification"）。这免去了长上下文时重调 RoPE 基频 / YaRN 插值的麻烦。

2.5 输入表示：文本与视觉 token 的拼接

文本 token 经 embed_tokens（1096-1097）得到 7168 维嵌入；视觉 token 由 MoonViT-V2 编码（1024 维）后经 PatchMergerMLPV2 投影到 7168 维。KimiK3ForConditionalGeneration.forward（kimi_k3_modeling.py:1113-1251）中，有图时先取文本嵌入，再调用 _merge_input_ids_with_image_features（958-1090）把 media_placeholder_token_id=163605 按 grid_thws 记录的 (t, h, w) 网格展开成对应数量的视觉 token 并插入文本流，随后按 attention_mask 的累积和重算 position_ids（1078-1079）。因此进入 93 层主干的是一个"文本与视觉 token 交错"的单一序列，共享同一套 KDA/MLA 注意力与 MoE——这正是"原生多模态、无后置对齐阶段"（论文 §2.4）的实现形态：视觉特征从第一层起就与文本在同一 token 流中被联合建模，为 vision-in-the-loop 的长程 agent 行为（写代码→看渲染结果→再改）提供了架构基础。

4. 核心组件解读

KimiDeltaAttention KDA（kimi_k3_linear_modeling.py:477-664）

代码位置与含义。 类定义于 477 行，mode 固定为 "chunk"（481），支持 chunk 与 fused_recurrent 两种执行模式（492-493）。构造（478-541）：

  • 短卷积（484，504-518）：conv_size = short_conv_kernel_size = 4，q/k/v 各配一个 ShortConvolution(hidden, kernel_size=4, activation='silu')（来自 FLA 库）。对应论文式(2)：q,k = L2Norm(Swish(ShortConv(W_q/k x)))、v = Swish(ShortConv(W_v x))；q/k 的 L2Norm 在 kernel 内完成（use_qk_l2norm_in_kernel=True，620/639）。
  • A_log 与 dt_bias（520-527）：A_log 是每头一个的可学习对数尺度（初始化为 log(U(1,16))），dt_bias 是每头每通道偏置（形状 96×128），二者与衰减 logits 一起送入 kernel，共同决定每步对数衰减，对应论文式(5) 的 g^h = g_min·Sigmoid(e^{A^h} z^h)、α = exp(g)。一个值得注意的细节：论文称初始化 A^h = 0，而仓库代码把 A_log 初始化为 log(U(1,16))（520-521），两者并不完全一致，推理端以仓库实现为准；dt_bias 在 kernel 内充当逐通道偏置，其角色近似论文式(2) 的每头偏置 b^h_α。
  • f_a / f_b 门控（523-524）：f_a_proj: 7168→128、f_b_proj: 128→96×128，构成低秩投影，产出每头每通道的衰减 logits z_t（论文式(2)的 z^h = W↑_α W↓_α x；注意代码未显式加偏置 b_α）。
  • b_proj beta（529）：b_proj: 7168→96，产出每头一个标量 β_t，kernel 内经 Sigmoid（use_beta_sigmoid_in_kernel=True，622/641）映射到 (0,1)，控制 delta rule 的写入强度。
  • g_gate（531-537）：use_full_rank_gate=True 时用全秩 g_proj: 7168→96×128；否则用低秩 g_a/g_b（7168→128→96×128）。K3 采用全秩输出门（论文 §2.1.1"Full-rank gate"）。
  • o_norm（539-540）：FusedRMSNormGated(head_dim=128, activation='sigmoid')——对循环输出先做逐头 RMSNorm，再与 Sigmoid(g_t) 逐元素相乘（论文式(6)：y = W_o[Sigmoid(W_g x) ⊙ RMSNorm(õ)]）。

forward（543-663）的关键逻辑：

  1. 模式切换（561）：mode = 'fused_recurrent' if use_cache and q_len == 1 else self.mode——decode 单步时走循环 kernel，训练/预填充走 chunk kernel；训练强制 chunk（562-563）。
  2. unpad（567-570）：线性注意力只支持 2D 0-1 mask（左填充语义，见 _update_linear_attn_mask），用 get_unpad_data 压缩成 packed 序列。
  3. 投影 + 短卷积（580-600）：q/k/v 投影后过 ShortConvolution，并回写卷积状态。
  4. 内核调用（609-645）：chunk_kda / fused_recurrent_kda 传入 q/k/v、衰减 logits g、β、A_log、dt_bias、初态，打开 use_qk_l2norm_in_kernel / use_gate_in_kernel / use_beta_sigmoid_in_kernel，safe_gate 与 lower_bound=gate_lower_bound(-5.0) 启用有下界衰减。返回值 o, recurrent_state。
  5. 缓存回写（646-649）：recurrent_states 与 conv_states 写回 KimiDynamicCache。
  6. 输出门（651-656）：全秩 g = g_proj(hidden_states) → o = o_norm(o, g)。
  7. 还原 padding（660-661）：pad_input 恢复 batch 形状。

为什么这样写：

  • 门控 Delta 规则优于纯线性注意力：普通线性注意力（如 Mamba 一族的 S_t = S_{t-1} + k vᵀ）只会"叠加"记忆，旧信息永不消除，导致状态被无关历史污染；KDA 的 delta rule 更新 S_t = (I−βkkᵀ)Diag(α)S_{t-1} + βkvᵀ 同时具备两个能力：① 外积项 (I−βkkᵀ) 可按需擦除/覆盖已存记忆（写新键时先删旧键的贡献），② 通道级遗忘门 Diag(α) 提供选择性遗忘（按通道按位置指数衰减旧信息）。二者合起来让模型在固定大小状态里做"有界记忆 + 选择性读写"，这正是长上下文下线性注意力不丢精度、decode 又保持 O(d_k·d_v) 常数开销的关键。
  • 有下界衰减是计算设计：Kimi Linear 用无界负 Softplus（g=−e^A Softplus(z) ∈ (−∞,0)），分块形式需要 1/Γ（累积衰减倒数），可能指数爆炸，因此对角 tile 必须用 position-pair 显式计算；K3 改用 g = g_min·Sigmoid(e^A z)，g_min=−5，把每个保留因子约束在 (e^{−5}, 1)，16-token tile 的累积对数衰减落在 (−80, 0)，1/Γ < e^80 仍在 BF16 动态范围内（论文 §2.1.1），于是所有因果 tile 都能用稠密 Tensor Core GEMM，删掉了 position-pair 对角路径。
  • 低秩投影 + 每头标量：β（写入强度）用 96 维每头标量、衰减 logits 用 128 维低秩（f_a/f_b），把引入的参数量压到最小，让"门控"本身便宜。
  • 全秩输出门：相比 Kimi Linear 的低秩输出门，全秩门让每个 token 能精细调制"从状态里读出哪些通道"，与 MLA 侧的新参数化保持一致（论文 §2.1.1-2.1.2）。
  • chunk/fused 双模式：训练要并行（chunk 形式块内并行、块间串行），decode 要 O(1) 状态；forward 按 q_len==1 自动切换，上层无需感知。

KimiMLAAttention（kimi_k3_linear_modeling.py:335-474）

代码位置与含义。 335 行起，注释明确"Multi-Latent Attention adapted from deepseek-v3"。构造要点：

  • MLA 维度（351-359）：q_lora_rank=1536、kv_lora_rank=512、qk_nope_head_dim=128、qk_rope_head_dim=64、v_head_dim=128，q_head_dim = 128+64 = 192；scaling = 192^{-0.5}。
  • Q 侧压缩（364-373）：有 q_lora_rank 时走 q_a_proj(7168→1536) → q_a_layernorm → q_b_proj(1536→96×192)，即 DeepSeek-V3 的"query 也压到低秩再展开"。
  • KV 侧 MQA 压缩（378-389）：kv_a_proj_with_mqa: 7168 → 512+64，每 token 只产出一个共享 latent（512 维 noPE 部分 + 64 维 rope 部分），再经 kv_a_layernorm + kv_b_proj 展开成 96 头。
  • 输出门（398-401）：mla_use_output_gate=True → g_proj: 7168 → 96×128，attn_output = attn_output * sigmoid(g)（470-472），即论文式(7)的全秩通道级输出门。
  • NoPE（403）：self.rotary_emb = None，forward 中 q_rot/k_rot 原样拼接，从不施加旋转位置编码——这是与 DeepSeek-V3 的 MLA 最大的行为差异（论文 §2.1.2：所有 MLA 层应用 NoPE）。

forward（405-474）要点：

  1. 投影并拆分 q_pass/q_rot、k_pass/k_rot、value_states（418-440）。
  2. KV 缓存更新（442-444）：past_key_values.update 沿 dim=2 cat。
  3. flash_attention_2 下 q_head_dim≠v_head_dim 的 pad 处理（446-448）：q_head_dim=192 ≠ v_head_dim=128，FA2 要求 q/k/v head_dim 一致，因此对 value 做 F.pad(value, [0, 64]) 补到 192，attention 之后裁回 [:, :, :, :128]（465-466）。
  4. 输出门 + o_proj（470-473）。

为什么这样写： MLA 把每个 token 的 KV 压缩进 512 维 latent，缓存只存 512+64 维而非 96×128 全量，KV 缓存占用大幅下降；"Gated"二字来自全秩输出门——它让每个 token 决定从全局注意力结果里读哪些通道（论文：gate 允许 token 调制从全局注意力读出的通道）。NoPE 的动机是与 KDA 分工：KDA 提供位置敏感、recency 感知的序列混合，MLA 只做无位置约束的内容交互；同时避免扩展上下文时改位置编码参数（论文 §2.1.2）。

AttnRes 注意力残差（kimi_k3_linear_modeling.py:877-1046, 1075-1088）

代码位置与含义。 attn_res_block_size=12 时 KimiDecoderLayer 在构造里新增两组参数（906-917）：self_attention_res_norm/proj 与 mlp_res_norm/proj（各一个 RMSNorm + 一个 Linear(7168→1)，proj 无 bias）。forward 转入 _forward_attn_res（930-934）。

_forward_attn_res（973-1046）逐层维护两个量：

  • prefix_sum（前缀和）：从本层输入开始，每层把注意力输出（1023-1026）与 FFN 输出（1041-1044）累加进去——相当于"本块内从块首到当前层的所有子层输出之和"；
  • block_residual（块残差）：在块边界层（layer_idx % 12 == 0，995-998）把当时的 prefix_sum 作为一个块级表示追加进缓存（首块边界即 token embedding，对应论文 b_0 = h_1）。

每层在两个位置调用 _apply_attn_res（987-993 与 1028-1033）：

  1. 注意力之前：对 [block_residual(历史各块) + 当前 prefix_sum] 做加权，得到送入注意力的输入；
  2. 注意力之后：对同样的值集合（此时 prefix_sum 已含本层注意力输出）做加权，得到送入 FFN 的输入。

_apply_attn_res（1075-1088）的实现等价于"对深度做 softmax 注意力"：

v = torch.cat((block_residual, prefix_sum.unsqueeze(1)), dim=1)      # (T, N+1, d)
v_float = v.float()
variance = v_float.pow(2).mean(-1, keepdim=True)
k = v_float * torch.rsqrt(variance + norm.variance_epsilon)          # RMSNorm(k)
score_weight = norm.weight.float() * proj.weight.squeeze(0).float()  # 可学习伪查询 w
scores = (k * score_weight).sum(-1)                                  # q·RMSNorm(k)
probs = scores.softmax(-1).unsqueeze(1)
hidden_states = torch.matmul(probs, v_float).squeeze(1)              # 加权和

模型末尾再聚合一次（_apply_output_attn_res，1226-1233，用 output_attn_res_norm/proj），即论文式(10)的"final output layer aggregates all N block representations"。

为什么这样写： 标准残差把所有历史压缩进单一状态 h_l——这本质上是"沿深度的 RNN"，是瓶颈；AttnRes 把注意力机制从序列维搬到深度维：每一层用可学习伪查询 w（res_norm.weight ⊙ res_proj.weight，1084 行，即论文式(8)的 q_l = w_l）对"历史层输出"做数据依赖的软选择，取代无差别的加法累加，从而缓解深层梯度问题并保留长程信息。块化（12 层一块）则把"保留所有层输出"的 O(L·d) 内存与跨阶段通信降到 O(N·d)（N=8 个块），同时用 online softmax 把块间并行结果与块内串行部分和合并，显著降低推理开销（论文 §2.2）。论文实验指出 N≈8 即可恢复大部分收益，K3 恰取 8 块×12 层。

Situ 激活（kimi_k3_linear_modeling.py:64-88）

代码位置与含义。 SituAndMul（64-82）实现论文的 SiTU-GLU：

d = x.shape[-1] // 2
gate = x[..., :d].to(torch.float32)
up = x[..., d:].to(torch.float32)
situ_a = beta * torch.tanh(gate / beta) * torch.sigmoid(gate)   # gate 分支：β1=4
if linear_beta is not None:
    up = linear_beta * torch.tanh(up / linear_beta)             # up 分支：β2=25
return (situ_a * up).to(x.dtype)

配置 hidden_act: "situ"、activation_situ_beta: 4.0、activation_situ_linear_beta: 25.0。ACT2FN["situ"] = SituAndMul（85）注册进 transformers 激活表；KimiBlockSparseMLP（253-258）与 KimiMLP（285-290）在 hidden_act=="situ" 时把 gate/up 两路 torch.cat 后一次性喂给 SituAndMul（264-265、296-297），而不是标准的 act(w1(x)) * w3(x)。

为什么这样写： SwiGLU 的两个乘性因子都无界，低精度（BF16/MXFP4）下大坐标相乘容易溢出；GLU 的纯 Sigmoid 门虽有界但失去了 Swish 近原点近似线性的正区间。SiTU-GLU 用 softcap(x, β)=β·tanh(x/β) 分别约束两个分支：近原点保持 SwiGLU 响应（β1=4），而 |f(x)| ≤ β1·β2 = 100 全局有界（论文 Fig.4），为 MXFP4/MXFP8 量化感知训练提供了数值安全垫。代码全程用 float32 计算再 cast 回原 dtype，也是同样的稳定性考虑。

MoE 与 LatentMoE（kimi_k3_linear_modeling.py:666-875, 242-271）

KimiMoEGate（666-759）。 由 DeepSeek-V3 的 MoE gate 改写而来（注释 668-674 给出参数对应表）。要点：

  • 路由分数（703-718）：logits = F.linear(x.float(), weight.float())，moe_router_activation_func="sigmoid" → scores = sigmoid(logits)（无辅助损失路由，对应 topk_method: "noaux_tc"）。
  • QB 偏置只影响选择不影响权重（723, 750）：scores_for_choice = scores + e_score_correction_bias，但最终 topk_weight = scores.gather(1, topk_idx) 用的是原始 sigmoid 分数——这正是论文式(13)"Because b is omitted from p_ij, it regulates dispatch without altering the mixture weights"。e_score_correction_bias 即 Quantile Balancing 的偏置，训练期按分位数更新、推理期冻结（论文 §2.3.3）。
  • num_expert_group=1、topk_group=1，因此 DeepSeek-V3 式的分组 topk 分支（724-744）被跳过，直接全局 top-16。
  • 权重归一化（753-757）：top_k>1 && moe_renormalize → 除以和使 topk_weight 和为 1，再乘 routed_scaling_factor=1.0。

KimiSparseMoeBlock（762-874）。 use_latent_moe = routed_expert_hidden_size is not None（776）→ 3584：

  • 结构：routed_expert_down_proj: 7168→3584（804-806）→ 896 个 KimiBlockSparseMLP(hidden=3584, intermediate=3072)（786-795，每个专家一个独立 FFN，块稀疏）→ 加权聚合 → routed_expert_norm（RMSNorm 3584，latent_moe_use_norm=true，810-813）→ routed_expert_up_proj: 3584→7168（807-809）。
  • 共享专家（797-801）：num_shared_experts=2，shared_experts = KimiMLP(intermediate_size=3072×2=6144)，在全宽 7168 维上直接处理输入（837：y = y + shared_experts(identity)）。
  • forward（815-838）：路由 → 压缩 → moe_infer → norm → 还原 → 加共享专家；训练模式直接 raise NotImplementedError（827）——这是推理/微调用参考实现（与文件头"Reference implementation"一致）。
  • moe_infer（840-874，@torch.no_grad()）：按 token 分桶排序（idxs = topk_ids.argsort()，845），相同专家的 token 连续喂给同一专家（852-860），最后按 topk_weight 加权求和（867-873）——典型的"grouped GEMM"式专家调度。

KimiBlockSparseMLP（242-271）。 单专家 FFN：w1(gate)/w3(up): 3584→3072、w2(down): 3072→3584（249-251），Situ 时把 gate/up 拼接喂激活（263-265）。

为什么这样写： 896 专家 × 16 激活（稀疏度 56）若按常规 MoE，每个被选专家都要接收全宽 7168 维 token，通信与专家权重流量随激活数爆炸；LatentMoE 把"全宽共享路径"与"低维潜空间路由路径"分离——共享专家保留全宽通用变换，路由专家只在小得多的 3584 维（0.5×hidden）上做专用变换。但这带来两个新故障模式：路由链（W↓→专家→W↑）近乎连续四次矩阵乘，2.8T 规模下路由分支内部激活爆炸；近千专家的负载均衡超出无辅助损失路由的调节能力。Stable LatentMoE 的三个组件对症下药：聚合后 RMSNorm（latent_moe_use_norm）压制尺度漂移、SiTU-GLU 把激活有界化、Quantile Balancing（e_score_correction_bias）按分位数设定专家偏置实现精确负载均衡（论文 §2.3）。

动态缓存 KimiDynamicCache（kimi_k3_linear_modeling.py:120-224）

代码位置与含义。 受 Qwen3-Next 启发（注释 124），为混合架构设计的自定义缓存（KimiLinearForCausalLM._supports_default_dynamic_cache 返回 False，1237-1239，强制使用它）：

  • 层类型表（131-139）：按 is_kda_layer 把每层标为 linear_attention / full_attention；transformer_layers 只收录 MLA 层（141-143），last_linear_layer 记录最后一个 KDA 层（145-147）。
  • 状态容器（149-152）：每个 KDA 层一个 conv_states（存 q/k/v 三个短卷积状态）与 recurrent_states（存 S 矩阵）；每个 MLA 层一个 key_cache/value_cache。
  • update（157-173）：MLA 的 KV 沿 dim=2 cat 增长——只有 MLA 层需要"追加式"KV 缓存；KDA 层的状态由层内 forward 回写（646-649），大小恒定。
  • reorder_cache（175-196）：beam search 时对 KV 缓存与 conv/recurrent 状态都按 beam 索引重排。
  • get_seq_length / get_mask_sizes（198-216）：以任一 MLA 层的 KV 长度代表序列长度（KDA 状态无长度概念）。
  • has_previous_state（218-223）：是否已有缓存，由"最后一个 KDA 层的 conv 状态是否非空"判定。

为什么这样写： 混合架构下两类注意力对缓存的需求截然不同：MLA 是"随序列增长的 KV 张量"，KDA 是"固定大小的循环状态"。统一缓存对象把二者按层并排放置，decode 时 KDA 层从 conv_states/recurrent_states 增量续算（q_len==1 走 fused_recurrent），MLA 层从 KV cache 追加读取——这正是"1M 上下文下 decode 每步开销与序列长度基本无关"的工程基础。

片段 3：AttnRes 的"对深度做注意力"（kimi_k3_linear_modeling.py:1075-1088 全文）

def _apply_attn_res(prefix_sum, block_residual, proj, norm):
    v = torch.cat((block_residual, prefix_sum.unsqueeze(1)), dim=1)  # 值 = 历史块表示 + 当前前缀和
    v_float = v.float()
    variance = v_float.pow(2).mean(-1, keepdim=True)
    k = v_float * torch.rsqrt(variance + norm.variance_epsilon)      # RMSNorm(键)
    score_weight = norm.weight.float() * proj.weight.squeeze(0).float()  # 可学习伪查询 w（逐通道）
    scores = (k * score_weight).sum(-1)                              # q·RMSNorm(k)
    probs = scores.softmax(-1).unsqueeze(1)
    hidden_states = torch.matmul(probs, v_float).squeeze(1)          # softmax 加权和
    return hidden_states.to(v.dtype)

注释式解读：这段 13 行函数是 AttnRes 的全部数学：键/值取块表示本身（k_i = v_i = f_i(h_i)，论文式(8)），伪查询由 norm.weight 与 proj.weight 的逐通道乘积给出，softmax 后加权求和——完全等价于"对深度做一次点积注意力"。设计理由：norm.weight 负责缩放各块量纲（防大输出块主导权重），proj.weight 是可学习的方向向量，二者逐通道相乘即 q_l = w_l ∈ R^d，参数量仅 2d。

6. 优点与局限

优点

  1. 真正的长上下文：KDA 固定大小状态 + NoPE，1M 上下文无需 RoPE 重缩放/YaRN，训练与推理成本随序列长度近似线性可控（论文 §3.4）；decode 每步开销与上下文长度基本无关（§4.6 缓存设计）。
  2. 三条维度同时扩展信息流：KDA（序列）、AttnRes（深度）、Stable LatentMoE（宽度）各司其职，论文称整体扩展效率较 K2 提升约 2.5×——这是"架构创新换参数效率"的典型：总参数翻 2.7 倍的同时激活参数翻 3.2 倍，但每 FLOP 的信息吞吐更优。
  3. 数值/训练稳定性工程化：有下界衰减（g_min=−5）、SiTU-GLU 软上限、LatentMoE 内 RMSNorm、Quantile Balancing、Per-Head Muon、从零训练 MoonViT-V2——每个不稳定点都有对应机制，且在 MXFP4/MXFP8 QAT 下依然成立。
  4. 原生多模态 + Agentic：视觉编码器与文本主干从训练第一天联合优化，视觉 token 与代码/工具调用同流，支撑 vision-in-the-loop 的长程 agent 行为（README §1）。
  5. 开放权重 + 生态支持：Kimi K3 License 下开放全量权重，vLLM / SGLang / TokenSpeed 均有适配；代码基于 DeepSeek-V3（Apache-2.0）与 LLaVA 改造，工程上可直接跑 transformers 4.56+。

局限

  1. 训练代码缺失：KimiSparseMoeBlock.forward 在训练模式直接 NotImplementedError（827），KimiMoEGate 也断言 not self.training（721）——仓库是推理/微调参考实现，预训练配方（MoonEP、FlashKDA、KCP 等）不在其中，复现预训练仍需官方系统。
  2. 依赖 fla-core 与 FA2：chunk_kda/fused_recurrent_kda、FusedRMSNormGated、ShortConvolution 全部来自 fla-core（46-53），且 _attn_implementation 被强制为 flash_attention_2（1110-1117），无 FA2/无 FLA 环境无法运行；KimiDynamicCache.is_compileable = False（125），与 torch.compile 的兼容性受限。
  3. 资源门槛极高：2.8T 总参、104B 激活，即使 MXFP4 量化，单机部署仍需多卡专家并行（论文的 MoonEP 是为 2.8T 预训练设计的）；e_score_correction_bias 冻结于推理，长上下文下 QB 无法再自适应。
  4. NoPE 的取舍：位置信息完全依赖 KDA 循环机制，MLA 层对"绝对位置/距离"不敏感，某些需要精确位置检索的任务可能依赖 KDA 层的表达；长上下文能力依赖训练课程（8k→1M 渐进）与长数据合成，非零样本天然获得。
  5. 注意力权重不可解释：KDA 没有 softmax 注意力矩阵，output_attentions 只对 MLA 层有效（_can_record_outputs，1056-1060），可解释性/调试工具受限。

7. 与其他模型的差异

  • 注意力机制：DeepSeek-V3 是纯 MLA（全层全局 softmax）；DeepSeek-V3.2 / GLM 的 DSA（DeepSeek Sparse Attention） 保留 softmax 注意力但用 lightning indexer 做 KV 块稀疏；Qwen 的 GatedDeltaNet 与 KDA 同属 delta-rule 线性注意力家族，但 KDA 额外引入通道级遗忘门 α_t、有下界 sigmoid 衰减参数化与全秩输出门，并混入 24 层 NoPE MLA 做全局兜底——K3 的卖点是"3:1 线性/全局混合 + 深度维 AttnRes"。
  • MoE：DeepSeek-V3 为 256 路由专家/8 激活、FP8 训练；K3 是 896/16 + 2 共享，且用 LatentMoE（路由专家在 3584=0.5×hidden 潜空间运算，共享专家保持全宽）+ Quantile Balancing 无辅助损失均衡——激活专家数翻倍而通信不翻倍。
  • 长上下文：DeepSeek-V3.2 靠 DSA 稀疏化 + YaRN 外推；Qwen 靠 RoPE 插值/NeXT 混合注意力；K3 靠 KDA 常数状态 + NoPE + 渐进课程（8K→64K→256K→1M），上下文扩展无需改任何位置编码参数。
  • 量化：K3 从 SFT 起做 MXFP4 权重 / MXFP8 激活的量化感知训练（config 中 compressed-tensors 量化配置，并显式排除 self_attn、shared_experts、lm_head、vision_tower、mm_projector 等敏感模块）；DeepSeek-V3 用 FP8 训练，Qwen3-Next 等也走 MXFP4 QAT 路线，但 K3 的量化目标包含 2.8T 全模型。
  • 推理优化：K3 复用 FLA 的 chunk_kda/fused_recurrent_kda 融合 kernel，论文配套 FlashKDA、KDA Context Parallelism、状态感知的 KDA checkpoint + MLA 分页统一前缀缓存（§5.4）；主流引擎 vLLM / SGLang / TokenSpeed 均已支持，而纯 MLA 模型（DeepSeek-V3）与 DSA 模型（GLM）的前缀缓存策略完全不同——KDA 状态是固定大小、按对话边界存 checkpoint，MLA KV 是增长型分页。

2. 架构总览

从设计哲学上看，Qwen3.6 的文本主干可以概括为一句话：用 75% 的层换取近乎免费的长期记忆，用 25% 的层保留精确检索，再用每层之后的 MoE/dense FFN 承载知识。GatedDeltaNet 层把 KV cache 替换为一个固定大小的递推状态，使上下文长度不再直接决定显存与计算量；而每隔 3 层插入的全注意力层则充当"精确回看"的锚点，负责处理那些线性递推难以胜任的、需要逐 token 精确对齐的任务（例如代码中跨文件符号引用、长文档中的事实检索）。这种"粗记忆 + 精检索"的分工，是当前混合架构（hybrid attention）路线的主流解法，Qwen3.6 的特色在于把分工做成了严格周期性的 layer_types 声明，并且给全注意力配上了输出门控。

4. 核心组件解读

Qwen3_5MoeGatedDeltaNet（modeling_qwen3_5_moe.py:385-541）

代码位置：类定义 :385，__init__ :386-427，forward :429-541。

代码含义（逐段）：

  • :388-394 从 config 取 linear_num_key_heads/linear_num_value_heads（16/32 或 16/48）与 head_dim（128），得到 key_dim = 16×128、value_dim = V×128。
  • :402-410 构造深度可分离因果卷积：conv1d 通道数为 conv_dim = key_dim×2 + value_dim（即 q/k/v 拼接后整体过卷积），groups=conv_dim（每个通道独立卷积），kernel=4、padding=3。
  • :414-417 时间步（离散化）参数：dt_bias 初始化为全 1；A_log = log(A)，A 采样自 U(0,16)（对应 :901-902 的 _init_weights 重初始化）。
  • :419-427 输出侧：Qwen3_5MoeRMSNormGated(head_v_dim)（z 门控 RMSNorm）+ out_proj；四条输入投影 in_proj_qkv（H→2·kD+vD）、in_proj_z（H→vD）、in_proj_b（H→V 头数）、in_proj_a（H→V 头数）。
  • :437-450 前向入口：padding 掩码、qkv/z/b/a 投影。
  • :452-478 双路径卷积：单 token decode 且 cache 有历史时走 causal_conv1d_update（原位更新 conv_state，:455-461），否则先 update_conv_state 再 causal_conv1d_fn（:463-474）。
  • :480-493 拆 q/k/v 并按头 reshape。
  • :495-500 关键标量：beta = b.sigmoid()（选择性遗忘门）；g = -A_log.float().exp() * softplus(a + dt_bias)（对数空间衰减，恒负）；num_v_heads//num_k_heads > 1 时 q/k 按 repeat_interleave 扩展到 V 头数（35B：32/16=2）。
  • :502-528 双路径 delta rule：decode 用 torch_recurrent_gated_delta_rule（:332-381，逐 token 递推 S←S·exp(g)+k⊗(β⊙(v−kᵀS))），训练/prefill 用 torch_chunk_gated_delta_rule（:250-328，chunk_size=64，chunk 内并行 + chunk 间递推），两者均开 use_qk_l2norm_in_kernel=True 并以 fp32 计算（:266-268）。
  • :535-541 RMSNormGated(core_attn_out, z) 后接 out_proj。

为什么这样写：

  • conv1d 短卷积：线性注意力（delta rule）本质是"低秩 + 衰减"的记忆累积，对局部 n-gram 模式不敏感；在 q/k/v 上先做 kernel=4 的因果卷积 + silu，相当于给每层注入显式的短程局部特征，再进入全局递推——这是 GatedDeltaNet/Mamba 系架构的标准组合拳，改善表达力。
  • log 参数化保证正衰减：A_log 在 log 空间存储，A=exp(A_log)>0 恒成立，于是 g<0 恒成立、exp(g)∈(0,1)，递推状态必然衰减、不会发散。:496 的注释还点出工程细节："fp16 下不加 .float()，A 可能变成 -inf"——参数化与数值稳定性耦合设计。
  • β 选择性遗忘（delta rule）：v−kᵀS 是"实际值 − 记忆可检索出的值"的残差，β∈(0,1) 控制该残差写入记忆的比例，使记忆可以"纠错"，比纯指数衰减（如 Mamba 的 gating）更接近软删除。
  • 双内核：chunk 版利用 chunk 内并行（矩阵乘法）做训练/prefill，recurrent 版用 O(1) 显存状态做 decode，是"训练并行性与推理串行性"的工程折中；两内核都转 fp32，避免 bf16 下递推误差累积。
  • z 门控（RMSNormGated）：与 GatedDeltaNet 论文一致，输出先 RMSNorm 再由 silu(z) 逐元素门控，z 由独立投影产生——相当于可学习的输出"音量开关"。

Qwen3_5MoeAttention（modeling_qwen3_5_moe.py:627-701）

代码位置：:627-701。

代码含义：:639-641 q_proj 输出 num_attention_heads×head_dim×2（35B：16×256×2=8192，即 hidden 2048 的 4 倍）；:651-654 q_norm/k_norm 为仅作用在 head_dim 上的 RMSNorm（权重初始化为 0，等价于 (1+w) 缩放，:903-904 注释）；:667-670 把 q_proj 输出沿最后一维 chunk 成 query 与 gate 两半；:672-674 q/k 过 norm、v 不过；:676-677 应用 mRoPE；:682-695 经 ALL_ATTENTION_FUNCTIONS 接口分派 eager/flash/sdpa；:698 attn_output = attn_output * torch.sigmoid(gate)；:700 o_proj（4096→2048）。

为什么这样写：

  • q_proj 2 倍宽度 + gate 流：与其额外加一个独立 gate 投影，不如让 q_proj 一次性输出"query + gate"两路，共享同一份输入变换成本。gate 经 sigmoid 落在 (0,1)，对注意力输出做软开关——这是 config attn_output_gate=true 对应的实现，让每 4 层才出现一次的全注意力能自适应决定"这一层的信息要不要写回主干"。
  • 逐头 RMSNorm（q_norm/k_norm）：在全注意力之前先稳定 q/k 的尺度（注意 :651 注释 "unlike olmo, only on the head dim!"），配合 scaling = head_dim^-0.5，使 256 维大 head 的注意力 logits 数值更稳，且不引入跨头耦合。
  • KV 头数大幅少于 Q 头：35B 为 16 Q / 2 KV（group=8），27B 为 24 / 4（group=6）——GQA 压缩 KV cache，在全注意力只占 1/4 层的情况下进一步压低长上下文显存。

Qwen3_5MoeSparseMoeBlock（modeling_qwen3_5_moe.py:779-798）

代码位置：:779-798。

代码含义：:782 gate = Qwen3_5MoeTopKRouter(config)；:783 experts = Qwen3_5MoeExperts(config)；:784 shared_expert = Qwen3_5MoeMLP(config, intermediate_size=shared_expert_intermediate_size)（512）；:785 shared_expert_gate = Linear(hidden, 1, bias=False)；:790-792 先算共享专家输出，再做路由；:794 共享输出乘以 sigmoid(shared_expert_gate(x))；:796 expert_output = expert_output + shared_expert_output。

路由细节（Qwen3_5MoeTopKRouter，:760-776）：router_logits = F.linear(x, weight)（权重形状 256×2048，:766），:771 在 fp32 下 softmax，:772 topk(8)，:773 对 top-8 权重重归一化（除以和），确保路由权重和为 1。

为什么这样写：

  • softmax + topk + 重归一化是 Switch/GShard 风格的标准路由：先全专家 softmax 得到概率，再取 top-k 并归一化，保证被选中专家的权重是一个合法分布，梯度只流经被选专家。
  • 共享专家（shared expert）：256 个路由专家每个 token 只用 8 个，但某些"通用能力"（语法、常用词）每个 token 都需要；共享专家保证这些能力无条件可用，不被路由竞争挤掉。
  • 独立 sigmoid 门控：共享专家的权重不能参与 top-k 的归一化竞争（否则路由权重总和会变），所以用独立的 Linear(H,1)+sigmoid 逐 token 缩放其输出——让模型自己学会"何时该依赖共享专家"，比固定权重更灵活，这是 35B-A3B 相对早期 MoE（如 Mixtral 固定 1× 共享）的增强。
  • 辅助负载均衡损失 load_balancing_loss_func（:1693-1772，Switch Transformer 式）以 router_aux_loss_coef=0.001 加入损失（:1868），防止专家坍缩到少数几个。

Qwen3_5MoeExperts（modeling_qwen3_5_moe.py:721-757）

代码位置：:721-757。

代码含义：:729-730 专家权重以 3D 张量存储：gate_up_proj (num_experts, 2·intermediate, hidden)、down_proj (num_experts, hidden, intermediate)；:739-743 forward 中用 one_hot(top_k_index, num_experts) 构造专家掩码并找出被命中的专家集合 expert_hit；:745-755 只对命中的专家循环：F.linear 取 gate/up → silu(gate)*up（SwiGLU）→ down 投影 → 乘以对应 top_k_weights → final_hidden_states.index_add_(0, token_idx, ...) 累加。

为什么这样写：

  • 3D 权重 + index 路由：把所有专家并成一个 3D 参数块，路由只是"按专家索引取 2D 切片"，比 ModuleList 每专家一个 Linear 更省显存管理开销，也方便 tensor parallel 切分。

  • mRoPE 三维位置：图像/视频 token 需要 (T,H,W) 三维位置，文本需要一维位置；4 行 position_ids（:1271-1279）中第 1 行是文本、后 3 行是 T/H/W，一次前向统一编码多模态相对位置。
  • interleaved 布局：chunked 布局里同一频率在 T/H/W 三块间跳变会破坏相邻频率的连续性；interleaved 让第 i 个频率槽连续承载 T/H/W 三元组，插值/外推更平滑——这是从 Qwen2.5VL 到 3.5/3.6 的已知演进。

代码含义：HF transformers 前向不包含 MTP 模块；mtp.* 权重存在于 checkpoint 中但加载时被显式忽略（_keys_to_ignore_on_load_unexpected）。部署时 vLLM 用 qwen3_next_mtp（num_speculative_tokens=2），SGLang 用 NEXTN（3 步、4 草稿 token）。

为什么这样写：

  • MTP（Multi-Token Prediction，即 EAGLE/NEXTN 式多步预测头）：在主 LM 之外加 1 层轻量头，训练时让第 t 步的表示同时预测 t+1、t+2 等后续 token，把"单步 teacher-forcing"升级为"多步自洽"，推理时模型可一次草拟多个 token 再校验，大幅提升解码吞吐。
  • mtp_use_dedicated_embeddings=false：MTP 头复用主模型的 embedding/lm_head，几乎不增加参数量（这也是 35B 总参 35B 中 MTP 占比极小的原因）。
  • 为什么 transformers 文件里没有：MTP 需要专门的训练/推理 kernel 与投机解码调度，属于 serving 引擎（vLLM/SGLang）的职责；HF 实现保持"最小可用"（忽略 mtp 权重即可正常推理），README 也明确推荐生产环境用专用引擎。

RMSNormGated（modeling_qwen3_5_moe.py:169-185）

代码位置：:169-185。

代码含义：weight = ones(hidden_size)（:172），activation = "silu"（:174）；:176-185 forward(hidden_states, gate)：先转 fp32 求方差并 rsqrt 归一化（:179-181），乘回 weight 与输入 dtype（:182），最后乘以 silu(gate)（:183）。顺序是"先 Norm 后 Gate"（:180 注释 "Norm before gate"）。

为什么这样写：

  • 输出门控与归一化解耦：RMSNorm 保证幅值稳定，silu(gate) 提供非线性的 0~1 级输出缩放（silu 在负区接近 0、正区近似线性），比恒等/线性 gate 表达力更强；z 来自独立投影 in_proj_z，是可学习门控信号。
  • fp32 归一化避免 bf16 下方差估计误差（与全模型 mamba_ssm_dtype=float32 一致）。

这一节挑选 6 个最能体现 Qwen3.6 设计取舍的代码片段，每个片段给出：原始代码、逐行注释式解读、以及"为什么这样写"的设计理由。阅读时建议对照第 4 节的组件解读，二者行号引用一致。

片段 1：衰减与遗忘门——g 与 beta（:495-500）

beta = b.sigmoid()
# If the model is loaded in fp16, without the .float() here, A might be -inf
g = -self.A_log.float().exp() * F.softplus(a.float() + self.dt_bias)
if self.num_v_heads // self.num_k_heads > 1:
    query = query.repeat_interleave(self.num_v_heads // self.num_k_heads, dim=2)
    key = key.repeat_interleave(self.num_v_heads // self.num_k_heads, dim=2)

解读：A_log.exp() > 0 恒成立 ⇒ g < 0 恒成立 ⇒ 递推中的 exp(g) ∈ (0,1)，记忆只衰减不放大，这是 delta rule 数值稳定性的根基；softplus(a + dt_bias) 把标量离散化参数化为"基时间步 + 可学习偏移"。fp32 强制转换是为了防止 bf16 下 A_log.exp() 溢出为 -inf（:496 注释是作者亲笔的工程提醒）。q/k 按 V/K=2 倍 repeat_interleave 扩张，让 16 个 QK 头服务 32 个 V 头（共享 QK 表示、节省 QK 投影参数）。

设计理由：把"衰减率"约束在数学上安全的区间内，比直接学无约束标量更稳；同时用 log 空间参数化让梯度在宽动态范围内传播良好。

解读：单 token 且 cache 有历史 = decode 阶段，走逐 token 递推（:332-381，状态 S 形状 (bs, V头, kD, vD)，每步 S←S·exp(g)+k⊗(β⊙(v−kᵀS))）；否则 = prefill/训练，走 chunk 内核（:250-328，chunk_size=64：chunk 内用矩阵乘并行、chunk 间递推）。两条路径都开 use_qk_l2norm_in_kernel=True（q/k 先 L2 归一化，:263-265），与 FLA（flash-linear-attention）库语义对齐（:244 注释）。

片段 3：全注意力的输出门控（:667-670, :698）

...

解读：q_proj 输出维度是常规的 2 倍，沿最后一维对半切：一半当 query（heads×head_dim），另一半当 gate（同形状）。注意力输出（已含 softmax 权重）与 sigmoid(gate) 逐元素相乘后才进 o_proj。

设计理由：这是 attn_output_gate=true 的落地实现——"把注意力输出乘上一个 (0,1) 的软开关"。门控信号与 query 同源（同一输入变换），模型无需额外参数就能学会"此位置的全注意力结果是否可信/需要写回"，对只占 1/4 的 full attention 层来说，这是用极低成本换取混合架构的稳定性。

解读：共享专家与路由专家并行计算；共享专家的贡献 = 其输出 × sigmoid(Linear(hidden,1)(x))，即每个 token 一个标量门；最后与路由专家的加权和相加。

设计理由：路由专家的权重经过 softmax 归一化，总和恒为 1——共享专家若混入同一分布会被"平均稀释"成残差噪声。独立 sigmoid 门让模型学习"这个 token 是否需要共享专家，需要多少"，是 Mixtral 式固定共享专家之上的自适应改进，也是 35B-A3B 在 3B 激活预算内维持通用能力的关键。

片段 5：interleaved mRoPE 重排（:150-165）

def apply_interleaved_mrope(self, freqs, mrope_section):
    freqs_t = freqs[0]  # just overwrite the first dimension T
    for dim, offset in enumerate((1, 2), start=1):  # H, W
        length = mrope_section[dim] * 3
        idx = slice(offset, length, 3)
        freqs_t[..., idx] = freqs[dim, ..., idx]
    return freqs_t

解读：freqs 形状 (3, bs, seq, head_dim/2)，第 0 维是 T/H/W。默认布局按维度分块 [TTT…HHH…WWW]；本函数把 H、W 的频率按步长 3 交错回 T 行的对应槽位，最终一行同时含 THWTHW… 三元组。

设计理由：interleaved 布局保证相邻频率槽位（连续 i）始终是同一物理频率的 T/H/W 三元组，频率随索引连续变化（"preserving frequency continuity"），这对 RoPE 外推与插值更友好——是 Qwen3.5/3.6 相对 Qwen2.5VL chunked 布局的改进点。

6. 优点与局限

优点

  1. 推理成本与上下文友好：75% 层（30/40 或 48/64）是 O(1) 状态、常数成本的 GatedDeltaNet，262K 原生上下文、README 声明可扩展至 ~1,010,000 tokens；35B 总参仅 ~3B 激活（README），MoE 每 token 只算 8/256+1 个专家。
  2. 混合检索能力：每 4 层插入 1 层全注意力，为"精确全局检索"（如代码中跨文件的引用、长文档定位）保留软注意力能力，弥补纯线性注意力的检索短板；attn_output_gate 让 full 层可以自适应软开关。
  3. 数值稳定性设计：A_log 对数参数化保证衰减有界、双内核 fp32 计算、q/k L2 归一化、RMSNormGated 先归一后门控——递归模型最常见的发散问题在参数化层面被系统性规避。
  4. MoE 效率与通用性兼顾：256 专家 Top-8 + 1 共享专家（sigmoid 门控）+ 0.001 负载均衡损失；共享专家保证通用能力、路由专家提供专业化，3D 权重 + one_hot/index_add_ 实现紧凑。
  5. MTP 多步预测：训练时多步目标提升样本效率与推理期投机解码的草稿质量（README 提供 vLLM/SGLang 现成配置）。
  6. 统一多模态：单视觉塔（Conv3d patch，27 层）同时服务图像与视频，mRoPE 三维位置 + spatial merge 控制视觉 token 数量，文本/图像/视频共享同一混合主干。

局限

  1. 无独立技术报告：架构细节只能从代码/README 推断，部分设计动机（如为何选 3:1 混合比、为何 partial_rotary_factor=0.25）缺乏官方论证。
  2. MTP 依赖外部引擎：HF transformers 前向不含 MTP 模块（权重被 _keys_to_ignore_on_load_unexpected 忽略），只有 vLLM/SGLang 等专用引擎才能兑现投机解码收益。
  3. 递归状态工程门槛：_is_stateful=True 意味着线性层状态必须串行推进，conv_state/recurrent_state 的缓存管理、chunk 与 recurrent 内核的切换都对推理框架有较高要求（README 明确推荐专用引擎，且建议上下文 ≥128K 以保留思考能力）。
  4. 无 FP8 量化配置：两个 config 均无 quantization_config/FP8 字段（35B 显式 dtype=bfloat16），超大上下文下显存压力大；mamba_ssm_dtype=float32 也说明线性注意力内核不吃低精度。
  5. 27B dense 规格无稀疏性：27B 的 FFN 是 17408 维 dense SwiGLU，无 MoE 路由，长上下文下的激活成本高于 35B-A3B。
  6. 混合比与位置编码容量：layer_types 硬编码在 config（改混合比需重新训练）；全注意力只旋转 64 维（0.25），长距离位置信息容量相对有限；线性层完全无显式位置编码，长程顺序信息依赖递推隐式建模。

7. 与其他模型的差异

  • 注意力机制：Qwen3.6 的 GatedDeltaNet（深度可分离短卷积 → 门控 delta rule 递推，无位置编码，:385-541）与 DeepSeek-V4 的 CSA/HCA（MLA + sliding window + 学习式门控池化 KV 压缩 + indexer top-k 稀疏注意力，dsv4_model.py 的 Compressor/Indexer/Attention）、GLM-5.2 的 DSA（MLA + DSA indexer，且支持跨层 top-k 共享，GlmMoeDsaAttention）、Kimi K3 的 KDA（MLA 与 Delta attention 混合、q/k/v 各自短卷积，KimiDeltaAttention）同为"线性/稀疏混合"路线，但 Qwen3.6 用固定 3:1 周期（每 4 层 1 个 full）且 full 层带输出门控，是四者中最"规整"的调度。
  • MoE：35B-A3B 为 256 专家 Top-8 + 1 共享（sigmoid 独立门控，intermediate 仅 512）；DeepSeek-V4 为 top-k + 1 共享专家（n_shared_experts=1）且原生支持 FP8/FP4 gemm 分派；GLM-5.2 为 MoE+DSA 组合；Kimi K3 走 MLA+Delta 混合；而 Qwen3.6-27B 直接放弃 MoE 用 dense（17408）——规格定位差异明显。
  • 长上下文：262,144 原生、README 声明可扩展至 ~1,010,000 tokens（config max_position_embeddings=262144），配合 mRoPE interleaved [11,11,10] 与部分旋转 0.25；相比之下 DeepSeek-V4 用压缩 KV + top-k 稀疏来支撑超长序列，GLM/Kimi 各自依赖 MLA 低秩 KV——Qwen3.6 靠"线性层不存 KV + 每 4 层一次 GQA"实现。
  • 量化：Qwen3.6 的 HF 配置为 bf16（35B 显式 dtype=bfloat16），无 FP8 配置，线性注意力内核要求 fp32（mamba_ssm_dtype=float32）；DeepSeek-V4 则把 FP8/FP4 量化内建进 gemm 分派（linear() 按权重 dtype 派发 fp4/fp8_gemm）。
  • 推理优化：_is_stateful=True + FLA 内核 fallback（@use_kernel_func_from_hub_with_fallback，:249/:331）体现"内核优先"策略；MTP 权重随包发布供 vLLM qwen3_next_mtp / SGLang NEXTN 投机解码（README 部署章节），这是 Qwen3.5/3.6 相对其他三家在"训练目标与 serving 引擎联动"上的差异化卖点。

⚡ 低激活参数 / 高吞吐

🧠 复杂推理 / Agent

Kimi-K3（2.8T 规模 + 原生多模态）与 DeepSeek-V4-Pro（Think Max 模式 + DSpark 推测解码）在长程 Agent 任务上表现突出。

🎨 多模态输入

术语表

快速查阅
MLA

Multi-head Latent Attention，多头潜在注意力：把 Q/K/V 压缩进低维潜在空间再解压，KV cache 减少一个数量级。DeepSeek 系与 GLM、Kimi 使用。

DSA

DeepSeek Sparse Attention：轻量索引器为每个 query 选 top-k 个历史 token，主注意力只在子集上计算，O(L²)→O(L·k)。

CSA / HCA

DeepSeek-V4 的 Compressed Sparse Attention（压缩稀疏注意力，r=4/128）与 Heavily Compressed Attention（重度压缩注意力）。

IndexShare

GLM-5.2 的跨层索引复用：Shared 层直接复用最近 Full 层索引器的 top-k 结果，索引器计算减少 ~75%。

KDA

Kimi Delta Attention：基于门控 Delta 规则的线性注意力，固定大小状态矩阵 S 递归更新，单步 O(1) 成本。

GatedDeltaNet

Qwen3.6 的线性注意力：Gated Delta 规则 + 短卷积 + 输出门控（RMSNormGated）。

MoE

Mixture of Experts：多个 FFN 专家 + 路由门控，每 token 只激活 top-k 个专家，扩大容量而不等比增加计算。

LatentMoE

Kimi-K3 的稳定化 MoE：对专家中间状态做归一化等处理，提升大规模稀疏训练稳定性。

Hyper-Connections

DeepSeek-V4 的 mHC：同时维护 hc_mult 份隐藏状态，用学习到的混合与组合矩阵替代单一残差，增强深层信号传播。

AttnRes

Kimi-K3 的 Attention Residuals：块级前缀和 + 学习式加权合并，缓解 93 层深网络的梯度衰减。

MTP

Multi-Token Prediction：主模型之外再预测未来多个 token，既是训练正则，也为推测解码提供草稿模型。

RoPE

Rotary Position Embedding：把位置编码为旋转角，与内容向量相乘注入位置信息；支持外推。

YaRN

YaRN 频率插值：只对低频维度做插值（除以 factor），让模型外推到数倍于训练长度的上下文。

mRoPE

Qwen 的多维 RoPE：文本/图像/视频按各自维度旋转，天然支持多模态位置编码。

FP8 / FP4

8 位 / 4 位浮点量化。FP8 用 E4M3 精度 + 按块缩放；FP4 专家权重进一步压缩显存与带宽。

absorb 吸收式注意力

MLA 的一种实现：打分与加权全程在压缩态（低秩空间）完成，避免先解压 KV 再打分带来的额外算力。

Sinkhorn

矩阵双随机化算法，DeepSeek-V4 用它把 hc_pre 的混合系数分解为 pre/post/comb 三组。

Speculative Decoding

推测解码：小模型/草稿模块先快速生成多 token，大模型并行验证，提升生成吞吐。

DSpark

DeepSeek 的推测解码框架：半自回归草稿 + 置信度调度验证，部署于 V4 服务系统。

KV Cache

推理时缓存历史 K/V，避免重复计算；其大小决定长上下文推理的显存上限。
