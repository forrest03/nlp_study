# 大模型结构演进补充调研：Llama 4 与 MiniMax-Text-01

## 1. 调研范围

课程材料已经重点介绍了以下模型及其代表性技术：

- Qwen3.6：`Gated DeltaNet + Gated Attention + MoE` 的混合结构；
- Kimi K3：`KDA + Gated MLA + AttnRes + Stable LatentMoE`；
- DeepSeek-V4：`CSA + HCA + mHC + MoE`；
- GLM-5.2：`DSA + IndexShare + MTP`。

因此，本文不再重复这些模型，而是补充两个具有不同结构思路的开放权重模型：

1. Llama 4：早期融合多模态、MoE 与 iRoPE；
2. MiniMax-Text-01：Lightning Attention 与 Softmax Attention 混合。

严格来说，“代码开源”“权重开放”和“OSI 定义下的开源”不是同一个概念。本文沿用业界常见说法，将可下载权重、可本地推理的模型统称为“开放模型”，并在各节注明许可情况。

## 2. Llama 4：将 MoE、多模态和长上下文放进同一骨干

### 2.1 基本结构

Llama 4 Scout 和 Llama 4 Maverick 是 Meta 首批采用 MoE 的 Llama 模型：

- Scout：总参数约 109B，每个 token 激活约 17B，包含 16 个专家；
- Maverick：总参数约 400B，每个 token 激活约 17B，包含 128 个专家；
- Scout 支持最高 10M 上下文，Maverick 支持 1M 上下文；
- 两者都采用原生多模态的自回归解码器结构。

Scout 和 Maverick 的 FFN 布局并不相同：

- Scout 的每个 FFN 层都是 MoE，使用 16 个 routed experts 和一个 shared expert；
- Maverick 每隔一层放置一个 MoE，其余层使用 Dense FFN；MoE 层使用 128 个 routed experts 和一个 shared expert。

Maverick 通过 Dense FFN 与 MoE FFN 交错，既保留 dense 层稳定的通用变换能力，又利用 routed experts 扩大参数容量；Scout 则选择更彻底的全 MoE 路线。

简化后的层结构可以表示为：

```text
输入
  ├─ RMSNorm → Self-Attention → 残差连接
  └─ RMSNorm → MoE FFN（Scout）
               或 Dense/MoE 交错 FFN（Maverick）→ 残差连接
```

### 2.2 iRoPE：位置编码层也可以混合

Llama 4 没有在所有注意力层上使用完全相同的位置编码，而是交错使用：

- 大部分层使用 RoPE；
- 部分全局注意力层不使用显式位置编码，即 NoPE；
- 推理时对注意力分数进行 temperature scaling。

Meta 将这种设计称为 iRoPE，其中 `i` 表示 interleaved。其目标是减少模型对训练长度范围内绝对位置模式的过拟合，提高超长上下文外推能力。

这一设计说明，混合架构不仅可以发生在 Attention 与 FFN 之间，也可以发生在不同位置编码策略之间。

### 2.3 原生多模态的早期融合

Llama 4 采用 early fusion：

1. 图像先经过基于 MetaCLIP 改进的视觉编码器；
2. 视觉特征被映射到语言模型的表示空间；
3. 图像 token 与文本 token 一起进入统一的模型骨干；
4. 在预训练阶段就联合学习文本、图像和视频数据。

这种方案不同于“语言模型训练完毕后再外挂视觉模块”的晚期融合。优点是跨模态信息可以在更深层充分交互，代价是多模态数据配比、训练稳定性和推理调度更加复杂。

### 2.4 结构评价

Llama 4 的核心特点不是某一个单独的新算子，而是把三种扩展方式组合起来：

- 用 MoE 扩展参数容量；
- 用 early fusion 扩展输入模态；
- 用 iRoPE 扩展上下文长度。

它仍然保留了较多标准 Transformer 组件，因此相比彻底改用线性注意力或 SSM，生态适配成本较低。不过，Llama 4 使用自定义 Llama 4 Community License，准确说属于开放权重模型，而不是标准宽松开源许可证模型。

## 3. MiniMax-Text-01：以线性注意力承担大部分长序列计算

### 3.1 基本结构

MiniMax-Text-01 是一个 456B 参数的 MoE 模型，每个 token 激活约 45.9B 参数。主要配置包括：

- 80 层；
- hidden size 为 6144；
- 每层包含 32 个专家，采用 top-2 路由；
- 每个专家的中间维度为 9216；
- 每个注意力模块包含 64 个 head，head dimension 为 128；
- 训练上下文达到 1M，推理时可外推到 4M。

模型最有代表性的设计是按 `7:1` 混合 Lightning Attention 与 Softmax Attention：

```text
7 × Lightning Attention Block
        ↓
1 × Softmax Attention Block
        ↓
重复上述组合，共 80 层
```

### 3.2 Lightning Attention 的作用

标准 Softmax Attention 需要显式计算 token 两两之间的相关性，序列长度为 \(n\) 时，其时间和注意力矩阵空间复杂度通常为 \(O(n^2)\)。

Lightning Attention 属于线性注意力路线。它通过重排计算和分块算法，避免构造完整的 \(n \times n\) 注意力矩阵，使长序列计算更接近 \(O(n)\)。MiniMax 还配套使用 LASP+ 等并行策略，以降低超长序列训练中的通信开销。

但纯线性注意力可能损失精确的 token-to-token 检索能力。因此模型每经过 7 个 Lightning Attention 层，就插入一个标准 Softmax Attention 层，让模型周期性地恢复全局、精确的内容寻址能力。

### 3.3 MoE 与长上下文的正交扩展

MiniMax-Text-01 同时从两个维度控制成本：

- Lightning Attention 主要降低随序列长度增长的计算成本；
- MoE 主要降低随模型总参数量增长的单 token 计算成本。

也就是说，Attention 稀疏化解决“序列太长”，专家稀疏激活解决“模型太大”。这两个方向可以叠加，而不是相互替代。

### 3.4 结构评价

与 Qwen3.6 的 Gated DeltaNet 混合结构相比，MiniMax-Text-01 更早展示了“大多数层使用线性注意力、少数层保留 Softmax Attention”的工程化路线。它的价值在于证明数百 B 参数 MoE 与百万级上下文可以同时训练。

其局限也很明显：

- Lightning Attention 需要专门 kernel 和序列并行实现；
- 4M 是外推上下文，不等同于所有任务上都具备稳定的 4M 有效上下文；
- 模型权重使用 MiniMax Model License，代码仓库使用 MIT License，两者不能混为一谈。

## 4. 两个模型放在一起看

这两个模型分别代表两种结构扩展思路。

### 4.1 Llama 4：在标准 Transformer 骨干上组合扩展

- 参数容量：MoE；
- 长上下文：iRoPE；
- 多模态：early fusion；
- 特点：改动相对模块化，容易复用 Transformer 生态。

### 4.2 MiniMax-Text-01：以注意力层比例换取超长上下文

- 主要计算：Lightning Attention；
- 精确检索补偿：周期性 Softmax Attention；
- 参数容量：MoE；
- 特点：同时降低序列维度和参数维度的计算成本。

## 5. 与课程模型的联系

把本文模型与课程中的 Qwen3.6、Kimi K3、DeepSeek-V4 和 GLM-5.2 放在一起，可以观察到三个共同趋势。

### 5.1 “纯 Transformer”正在变成“少量精确注意力 + 大量高效模块”

不同模型使用的高效模块不同：

- Qwen3.6 使用 Gated DeltaNet；
- Kimi K3 使用 KDA；
- DeepSeek-V4 使用 CSA/HCA；
- GLM-5.2 使用 DSA；
- MiniMax-Text-01 使用 Lightning Attention。

Llama 4 则选择保留标准 Attention，改用 iRoPE 和外推策略支撑超长上下文。

但共同目标都是减少标准全量 Softmax Attention 在超长上下文中的二次复杂度和 KV Cache 压力，或至少降低模型对训练长度范围内绝对位置模式的过拟合，同时保留足够的精确注意力作为能力兜底。

### 5.2 MoE 与高效注意力解决的是不同问题

MoE 让总参数量增长时，每个 token 只激活少部分专家；高效注意力则让上下文增长时，单层序列计算不再快速膨胀。因此近年的前沿模型经常同时使用两者。Llama 4 与 MiniMax-Text-01 都采用了 MoE，但只有后者把线性注意力作为主干。

可以用一个粗略表达式理解单 token 成本：

\[
\text{Cost} \approx \text{序列混合成本} + \text{激活专家的 FFN 成本}
\]

优化 Attention 主要降低第一项，优化 MoE 路由和专家规模主要降低第二项。

### 5.3 “混合”正在从模块选择演进为系统设计

混合架构的粒度越来越丰富：

- 层级混合：不同层使用 Lightning Attention 或 Softmax Attention；
- FFN 混合：Dense FFN 与 MoE FFN 交错；
- 专家混合：shared experts 与 routed experts 共存；
- 模态混合：视觉 token 与文本 token 进入统一骨干；
- 位置编码混合：RoPE 层与 NoPE 层交错。

因此，下一阶段的大模型结构竞争很可能不再是“Transformer 与非 Transformer 二选一”，而是如何在质量、显存、吞吐、通信和部署复杂度之间找到更好的组合。

## 6. 结论

两个补充模型给出了两种不同答案：

- Llama 4 证明传统 Transformer 骨干可以通过 MoE、iRoPE 和 early fusion 继续扩展；
- MiniMax-Text-01 证明线性注意力与 MoE 可以共同支撑百万级上下文和数百 B 参数。

从结构演进看，未来更值得关注的不是某个新算子能否完全替代 Attention，而是模型能否根据任务和硬件，在不同计算机制之间进行更细粒度、更稳定的分工。
