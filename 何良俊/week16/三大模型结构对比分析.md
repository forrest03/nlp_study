# 开源大模型结构对比分析：Hy3 / MiniMax-M3 / Qwen3.8-27B

> 结构特点 · 横向对比 · Transformer 架构演进总结
> 资料来源：各模型官方 GitHub / HuggingFace / ModelScope 仓库 `config.json` 及 MiniMax MSA 技术报告（arXiv:2606.13392）｜ 整理日期：2026-08-20

**一句话定位：** 三个模型均于 2026 年开源，但代表了 2026 年大模型结构的**三条不同演进路线**——

- `Hy3` 用「超大 MoE + MTP 投机解码」追求性价比与推理速度；
- `MiniMax-M3` 用「块稀疏注意力 MSA」直接攻克百万级长上下文的算力瓶颈，并原生多模态；
- `Qwen3.8-27B` 用「线性注意力 + 全注意力混合（Hybrid）」把前沿能力压进 27B 稠密参数，主打本地/端侧可部署的多模态。

---

## 一、Hy3 结构特点分析

**来源：** 腾讯混元团队，2026-07-06 正式开源（Apache 2.0）。权重与配置发布于 GitHub、HuggingFace、ModelScope、GitCode。官方推荐以 **vLLM / SGLang** 部署（含 MTP 投机解码配方），仓库本身**不随权重发布建模源码**，因此结构信息来自官方 `config.json` 与发布说明。

### 1.1 基本信息

| 维度 | 取值 |
|---|---|
| 架构类型 | MoE（混合专家） |
| 总参数 / 激活参数 | 295B / 21B（另有 MTP 层 3.8B） |
| 层数 | 80（不含 MTP 层） |
| 隐藏维度 | 4096 |
| 上下文长度 | 256K（262144） |
| 词表 | 120832 |
| 精度 | BF16 |
| 模态 | 纯文本（config 中无 vision 配置） |
| 许可 | Apache 2.0 |

### 1.2 关键结构配置（来自 config.json）

| 配置项 | 值 | 含义 |
|---|---|---|
| `num_attention_heads` / `num_key_value_heads` | 64 / 8 | GQA，每组 8 个查询头共享 1 个 KV 头 |
| `head_dim` | 128 | 注意力头维度 |
| `num_experts` / `num_experts_per_tok` | 192 / 8 | 192 个专家，每 token 激活 8 个 |
| `num_shared_experts` | 1 | 每个 token 额外经过 1 个共享专家 |
| `moe_intermediate_size` / `expert_hidden_dim` | 1536 | 每个专家 FFN 中间维度 |
| `first_k_dense_replace` | 1 | 第 1 层为稠密 FFN，其余为 MoE |
| `moe_router_use_sigmoid` / `moe_router_enable_expert_bias` | true / true | sigmoid 路由 + 专家偏置（负载均衡） |
| `router_scaling_factor` | 2.826 | 路由 logits 缩放 |
| `qk_norm` / `route_norm` | true / true | QK 归一化 + 路由归一化，稳定训练 |
| `rope_theta` | 11158840（≈1.12e7） | RoPE 旋转基频，支撑长上下文 |
| `num_nextn_predict_layers` | 1 | MTP（Multi-Token Prediction）层，用于投机解码加速 |

### 1.3 架构特点与创新

- **容量与算力解耦（MoE）：** 295B 总参数仅激活 21B，用 8 张显存较大的卡即可服务，把「大模型能力」与「推理成本」拆开——这是 2026 年旗舰开源模型的主流范式。
- **细粒度路由 + 负载均衡：** 采用 `sigmoid` 路由（而非 softmax top-k）+ 专家偏置（expert bias），配合 `route_norm`，缓解专家坍缩、提升路由稳定性；192 专家 / top-8 属于「细粒度 MoE」，每专家更小更专。
- **MTP 投机解码：** 额外的 nextn-predict 层（3.8B）可在 vLLM/SGLang 下做多 token 草稿预测，显著提升解码吞吐，是「训练时多 token 预测、推理时投机加速」思路的工程落地。
- **训练稳定性细节：** QK-Norm、RMSNorm、较大 `rope_theta`，均为长上下文 + 大 MoE 训练的成熟工程实践。
- **取舍：** 注意力仍是**标准全softmax+GQA**（非稀疏/线性），长上下文靠 RoPE 而非结构革新；且**非原生多模态**。它的差异化在「MoE 性价比 + MTP 速度」而非结构颠覆。

## 二、MiniMax-M3 结构特点分析

**来源：** MiniMax 团队，2026-06-01 开源。模型 `config.json` 显示 `model_type = minimax_m3_vl`，架构为 `MiniMaxM3SparseForConditionalGeneration`——一个**原生多模态**（文本/图像/视频）的稀疏注意力模型，配套 MSA 技术报告（arXiv:2606.13392）与开源推理内核 `MiniMax-AI/MSA`。

### 2.1 基本信息

| 维度 | 取值 |
|---|---|
| 架构类型 | MoE + MSA 稀疏注意力（原生多模态 VLM） |
| 总参数 / 激活参数 | 428B / 23B |
| 文本层数 | 60（前 3 层稠密，后 57 层 MoE） |
| 隐藏维度 | 6144 |
| 上下文长度 | 1M（1048576） |
| 词表 | 200064 |
| 模态 | 文本 + 图像 + 视频（CLIP 风格视觉编码器，32 层 ViT） |
| 许可 | MiniMax 自定义许可（非 Apache，权重开源，商用需确认条款） |

### 2.2 关键结构配置（来自 config.json）

| 配置项 | 值 | 含义 |
|---|---|---|
| `num_attention_heads` / `num_key_value_heads` | 64 / 4 | GQA，每组 16 个查询头共享 1 个 KV 头 |
| `head_dim` / `partial_rotary_factor` | 128 / 0.5 | 半维 RoPE（rotary_dim=64） |
| `num_local_experts` / `num_experts_per_tok` | 128 / 4 | 128 专家，每 token 激活 4 个 + 1 共享 |
| `n_shared_experts` | 1 | 共享专家 |
| `dense_intermediate_size` / `shared_intermediate_size` | 12288 / 3072 | 专家 FFN 中间维度 |
| `moe_layer_freq` | 前 3 层=0，后 57 层=1 | 浅层稠密、深层 MoE |
| `scoring_func` / `use_routing_bias` | sigmoid / true | 与 Hy3 类似的负载均衡路由 |
| `num_mtp_modules` | 7 | **7 个 MTP 模块**（比 Hy3 的 1 个更激进的投机解码） |
| `sparse_attention_config` | block_size=128, topk_blocks=16, index_heads=4, index_dim=128 | MSA 块稀疏注意力核心参数 |
| `hidden_act` | swigluoai（swiglu_alpha=1.702, limit=7.0） | 定制 SwiGLU 变体 |

### 2.3 架构特点与创新

- **MSA（MiniMax Sparse Attention）——核心突破：** 在 GQA 之上做**块级稀疏注意力**。一个轻量 **Index Branch** 对每个 KV 块打分，为**每个 GQA 组独立**选 Top-k 块；**Main Branch** 仅在选中块上做精确块稀疏注意力。从而把 softmax 注意力的平方复杂度，在长上下文下压成近似线性。
- **长上下文实测收益（论文）：** 在 1M 上下文、109B 研究模型上，MSA 与 GQA 质量持平，但**每 token 注意力计算降低 28.4×**；配合定制 GPU 内核（exp-free Top-k、KV-outer 稀疏注意力）实现 **prefill 14.2×、decode 7.6×** 墙钟加速（H800）。M3 因此把上下文直接拉到 **1M**。
- **更激进的 MTP：** `num_mtp_modules = 7`，相较 Hy3 的 1 个 MTP 层，投机解码深度更大，进一步提升长上下文 / Agent 场景的解码吞吐。
- **原生多模态：** 从预训练第一步即混合文本/图像/视频训练，视觉编码器（ViT，3D-RoPE）与语言模型深度融合，而非后接适配器。
- **取舍：** 结构最复杂（稀疏注意力 + MoE + 多模态 + 7×MTP），工程与内核耦合度高；许可非 Apache，商用约束需额外确认。

## 三、Qwen3.8-27B 结构特点分析

**来源：** 阿里巴巴通义千问团队，2026-08-14 开源（Apache 2.0）。`config.json` 显示 `model_type = qwen3_5`，架构 `Qwen3_5ForConditionalGeneration`——一个**稠密（Dense）、原生多模态**的 27B 视觉-语言模型，基于 Qwen3.5 架构基础。

### 3.1 基本信息

| 维度 | 取值 |
|---|---|
| 架构类型 | Dense（稠密）+ 混合注意力（线性 + 全注意力） |
| 参数 | 约 27B（稠密，无 MoE） |
| 文本层数 | 64（48 层线性注意力 + 16 层全注意力） |
| 隐藏维度 | 5120 |
| 上下文长度 | 262K 原生，YaRN 扩展到 1M |
| 词表 | 248320 |
| 模态 | 文本 + 图像 + 视频（ViT，27 层） |
| 许可 | Apache 2.0 |

### 3.2 关键结构配置（来自 config.json）

| 配置项 | 值 | 含义 |
|---|---|---|
| `num_attention_heads` / `num_key_value_heads` | 24 / 4 | GQA，每组 6 个查询头共享 1 个 KV 头 |
| `head_dim` | 256 | 注意力头维度较大 |
| `layer_types` / `full_attention_interval` | 每 4 层：3 线性 + 1 全注意力 | **Hybrid 混合注意力**，共 48 线性 + 16 全注意力 |
| 线性注意力（GatedDeltaNet） | linear_num_key_heads=16, linear_num_value_heads=48, linear_key/value_head_dim=128, conv_kernel=4 | 线性（递归）注意力，KV 缓存 O(1) |
| `attn_output_gate` / `output_gate_type` | true / swish | 门控输出，增强表达 |
| `rope_theta` / `partial_rotary_factor` | 1e7 / 0.25 | MRoPE（多模态旋转位置编码，section=[11,11,10]） |
| `mtp_num_hidden_layers` | 1 | 1 个 MTP 层 |
| MoE 字段 | 无 | 稠密模型，无专家结构 |
| 视觉编码器 | hidden=1152, depth=27, patch=16, spatial/temporal_merge=2 | 原生视觉塔，支持图像/视频 |

### 3.3 架构特点与创新

- **混合注意力（Hybrid Linear + Full）——核心突破：** 多数层用 **GatedDeltaNet（线性/递归注意力）**，KV 缓存为常数级、计算近似线性；每 4 层插入 1 个**全注意力（GatedAttention）**块以保留精确的全局依赖与复杂推理能力。这是「用线性注意力换效率、用少量全注意力保能力」的折中。
- **稠密小模型 + 本地可部署：** 27B 稠密、无 MoE 路由开销，量化后可在消费级/工作站显卡本地推理，是「端侧 AI 产业化拐点」的代表——把 Agent/代码/计算机操控能力收敛到可私有化部署的规模。
- **可控推理（reasoning_effort）：** 推理默认开启但可关闭，支持 xhigh/medium/low 三档调节，适配 Agent 长程任务的不同成本/质量需求。
- **原生多模态 + YaRN 长上下文：** 262K 原生窗口、YaRN 扩至 1M；视觉塔与语言模型一体训练，覆盖图表/文档/小时级视频。
- **取舍：** 放弃 MoE 的容量扩展性，靠「线性注意力 + 大模型训练数据/后训练」在 27B 上逼近更大模型；混合注意力对推理框架（vLLM/SGLang/llama.cpp）的适配要求更高。

## 四、横向对比

| 维度 | Hy3 | MiniMax-M3 | Qwen3.8-27B |
|---|---|---|---|
| 发布方 / 时间 | 腾讯混元 / 2026-07 | MiniMax / 2026-06 | 阿里通义 / 2026-08 |
| 模型范式 | MoE（文本） | MoE + 稀疏注意力（多模态） | Dense + 混合注意力（多模态） |
| 总 / 激活参数 | 295B / 21B | 428B / 23B | 27B（稠密） |
| 层数 | 80 | 60（前/后分层） | 64 |
| 隐藏维度 | 4096 | 6144 | 5120 |
| 注意力机制 | 全 softmax + GQA | 块稀疏 MSA（基于 GQA） | 混合：GatedDeltaNet 线性 + 全注意力 |
| 专家结构 | 192 专家 / top-8 + 1 共享 | 128 专家 / top-4 + 1 共享 | 无（稠密） |
| 上下文 | 256K | 1M | 256K（YaRN→1M） |
| 位置编码 | RoPE（θ≈1.12e7） | 半维 RoPE（θ=5e6, partial=0.5） | MRoPE（θ=1e7, partial=0.25） |
| 推理加速 | MTP ×1 层（3.8B） | MTP ×7 模块 | MTP ×1 层 |
| 路由策略 | sigmoid + 专家偏置 | sigmoid + 路由偏置 | —（无 MoE） |
| 模态 | 纯文本 | 文本+图像+视频（原生） | 文本+图像+视频（原生） |
| 许可 | Apache 2.0 | MiniMax 自定义 | Apache 2.0 |
| 核心卖点 | 性价比 / MTP 速度 | 百万级长上下文 / 原生多模态 | 本地可部署 / 混合注意力效率 |

> **对比要点：** 三者恰好覆盖 2026 年「效率三杠杆」——**参数效率（MoE）**、**注意力效率（稀疏/线性）**、**部署效率（小稠密+混合）**。Hy3 与 MiniMax 都走 MoE，但 Hy3 用「全注意力+大 MTP」换速度，MiniMax 用「稀疏注意力+7×MTP」换长上下文；Qwen 则放弃 MoE，用「线性+全注意力混合」在 27B 稠密上实现效率与能力的再平衡。

## 五、Transformer 架构演进总结

把三个模型放进时间线，可以清晰看到 Transformer 从「标准全注意力稠密」到「多杠杆协同」的演进路径：

1. **原始 Transformer：** 全 softmax 注意力 + 稠密 FFN。质量强，但注意力 O(n²)、容量靠堆参数。
2. **效率初改（GQA / RoPE / RMSNorm）：** KV 共享降低显存，旋转位置编码支撑长上下文，RMSNorm 稳定训练。三者均已沉淀为标配。
3. **容量解耦（MoE）：** Hy3 / MiniMax：总参数百亿级、激活仅 20 余 B，把能力与算力拆开。细粒度专家 + sigmoid/偏置路由成主流。
4. **注意力再突破（稀疏 / 线性）：** MiniMax MSA 块稀疏、Qwen GatedDeltaNet 线性：直接攻击 O(n²) 瓶颈，使 1M 上下文与端侧部署成为可能。
5. **推理加速（MTP）：** 多 token 预测层做投机解码，Hy3(1)/MiniMax(7)/Qwen(1) 均采纳，成为新标配。
6. **原生多模态：** MiniMax / Qwen 从第一步混合模态训练，视觉塔与语言模型深度融合，而非后接适配器。

### 5.1 四条贯穿性主线

1. **注意力复杂度的持续下探：** 全注意力 → GQA（KV 压缩）→ 块稀疏 MSA / 线性 GatedDeltaNet（近线性）。目标都是打破长上下文的平方成本。三模型分别代表「不改注意力」「稀疏改」「线性改」三种态度。
2. **容量与算力的解耦：** MoE 让「大总参、小激活」成为旗舰常态；Qwen 反其道用稠密小模型 + 混合注意力，证明「不靠 MoE 也能高效」的另一条路。两条路线在 2026 年并行。
3. **长上下文成为基线能力：** 256K 已是入门，1M 由 MSA / YaRN 实现。位置编码从全维 RoPE 走向部分旋转（partial_rotary_factor 0.25~0.5）与多模态 MRoPE。
4. **训练-推理协同设计：** MTP 层、sigmoid+偏置路由、QK/Route Norm 等，说明现代结构已不是「单点创新」，而是覆盖路由、归一化、位置编码、解码加速的系统工程。


> **结构研究的共同结论：** 2026 年的开源前沿已不再比拼「谁的注意力更原始」，而是比拼**如何在注意力、专家、位置编码、解码加速、多模态五个维度上同时做对权衡**。三模型是同一命题下的三种最优解。
