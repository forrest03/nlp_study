# 中文同步报告模板

最终报告必须使用下面的固定章节和字段。`CHANGE`、`MANUAL` 均从 001 连续编号。把全部待手测项同时复制到用户最终回复，不能只给本地报告链接。

```markdown
# PopularVideo → Windows 同步报告

## 版本范围与工作区

- 上游分支：`<branch>`
- 上次成功基线：`<完整 hash>` — `<subject>`
- 固定目标：`<完整 hash>` — `<subject>`
- 比较范围：`<base>..<target>`
- 远程新鲜度：`<结果>`
- Windows 起始版本：`<hash>`
- Windows 既有未提交改动：`<无或逐项路径>`

## 上游改动全量清单

### CHANGE-001：<单一功能或契约名称>

- 分类：`Mac 客户端 | 共享契约 | 服务端/API | 部署/文档 | 多端`
- 上游依据：`<完整 commit>`；`<关键路径和测试>`
- 改动前：<具体旧行为>
- 改动后：<具体新行为>
- Mac/共享变化：<具体变化；无则说明原因>
- 服务端变化：<具体变化；无则说明原因>
- 用户影响：<用户入口、状态、产物、错误或性能的可观察变化>
- Windows 结论：`已同步 | 已存在 | 不适用 | 仅服务端 | 阻塞`
- Windows 落点：`<文件/模块>`；<具体实现或无需实现原因>
- 自动测试：`<命令/测试名>`；<覆盖内容或无的原因>
- 手动测试：`MANUAL-001, MANUAL-002` 或 `无（具体原因）`

<!-- 继续列出 CHANGE-002...；一个独立行为一个条目。 -->
<!-- 没有上游改动时删除全部 CHANGE 示例，并保留下一行且填写具体原因。 -->
<!-- NO_UPSTREAM_CHANGES: <仅无上游改动时填写具体原因；有 CHANGE 时删除本行> -->

## Windows 同步结果

| CHANGE | Windows 文件 | 实际同步内容 | 状态 |
| --- | --- | --- | --- |
| `CHANGE-001` | `src/...` | <具体新增/修改/删除的行为> | 已同步/已存在/不适用/仅服务端/阻塞 |

## 手动测试清单

> 按 P0 → P1 → P2 排序。状态只能写“待用户手测”“Codex 已手测通过”“用户已手测通过”或“不适用”，不得把自动测试通过写成手测通过。

### MANUAL-001：<单一测试场景名称>

- 关联改动：`CHANGE-001`
- 优先级：`P0 | P1 | P2`
- 入口：<具体页面、按钮、菜单或提交方式>
- 前置条件：<环境、账号、设置、文件和已有数据>
- 测试数据：<文件类型、语言、时长、大小、字段或精确输入>
- 是否需要真实凭据：`否` 或 `是（具体类型）`
- 预计耗时：`<分钟>`
- 操作步骤：
  1. <明确操作>
  2. <明确操作>
- 预期结果：
  1. <与步骤对应的可观察结果>
  2. <与步骤对应的可观察结果>
- 异常/边界：<至少一个本次受影响的失败、取消、重试、空状态或边界输入及预期>
- 失败时记录：<需要保留的 conversation/message/request/run/task/tool-call/job ID、日志或截图>
- 自动覆盖：`<命令/测试名>`；<自动测试能覆盖什么、不能覆盖什么>
- 状态：`待用户手测`

<!-- 继续列出 MANUAL-002...。 -->
<!-- 确实没有手测项时删除全部 MANUAL 示例，并保留下一行且填写具体原因。 -->
<!-- NO_MANUAL_TESTS: <仅无手测项时填写具体原因；有 MANUAL 时删除本行> -->

## 自动验证

| CHANGE | 命令/检查 | 结果 | 未覆盖内容 |
| --- | --- | --- | --- |
| `CHANGE-001` | `npm run ...` | 通过/失败/跳过（原因） | <仍需 MANUAL 验证的内容> |

## 未同步项与剩余风险

- `CHANGE-xxx`：<未同步/阻塞原因、用户影响、需要服务端处理的中文建议、下一步>
- Electron 实机跟进：<需要/不需要及原因>
- 客户端 prompt 硬兜底：<未新增/不适用>

## 提交覆盖索引

| 上游 commit | CHANGE 映射或排除原因 |
| --- | --- |
| `<完整 commit>` | `CHANGE-001, CHANGE-002` 或 <明确排除原因> |

## 覆盖核对

- 审计提交数：`<整数>`
- 审计变更组数：`<整数>`
- 报告 CHANGE 条目数：`<整数>`
- 有 Windows 用户影响的 CHANGE 条目数：`<整数>`
- 有 MANUAL 映射的 CHANGE 条目数：`<整数>`
- 无需手测且已说明原因的 CHANGE 条目数：`<整数>`
- 未解释条目数：`0`

## 状态记录

- 本次成功后记录的上游 commit：`<完整目标 hash>`
- 状态文件：`<绝对路径>`
- 报告文件：`<绝对路径>`
- 推进条件：`sync_state.py complete 成功后以 state.json 为准`
```

报告若未完成或验证失败，要在标题后标注“未完成”，并且不得声称基线已推进。删除模板注释、占位符和示例行后再运行报告校验。
