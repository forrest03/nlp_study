## 1. 术语前置说明

| 术语 | 解释 |
|---|---|
| **Dense（稠密模型）** | 每次推理全部参数激活，算力开销固定，单卡部署友好；无专家路由 |
| **MoE（混合专家）** | 总参数量巨大；每个 token 仅由路由器激活少量专家子网；知识容量大、推理成本低；**总参数 ≠ 激活参数** |
| **激活参数（Active Parameters）** | 每个 token 前向传播时实际参与计算的参数量，决定推理成本 |
| **稀疏率** | 激活参数 / 总参数；越低表示每次推理跳过的参数越多 |
| **RoPE** | 旋转位置编码，长上下文外推行业主流方案 |
| **GQA** | 分组查询注意力，多 Query 头共享少量 KV 头，降低 KV 缓存 |
| **MLA** | 多头潜空间注意力（Multi-head Latent Attention），将 K/V 低秩压缩到共享潜向量，大幅降低 KV 缓存；DeepSeek 首创 |
| **KDA** | Kimi Delta Attention，线性循环注意力，KV 缓存大小恒定，不随序列长度增长 |
| **Gated DeltaNet** | 阿里研发的门控线性注意力变体，属状态空间/Mamba 家族路线，平衡速度与检索精度 |
| **CSA** | 压缩稀疏注意力（Compressed Sparse Attention），沿序列维度压缩 KV 缓存并结合稀疏检索 |
| **HCA** | 深度压缩注意力（Heavily Compressed Attention），更高倍率的 KV 压缩方案 |
| **DSA** | DeepSeek Sparse Attention，稀疏注意力，通过索引器只对部分 KV 做注意力计算 |
| **mHC** | 流形约束超连接（manifold-constrained Hyper-Connections），增强超深层网络信号传递 |
| **MTP** | 多 Token 预测（Multi-Token Prediction），训练目标，增强长生成连贯性 |
| **SiTU-GLU** | Sigmoid-Tanh-Unit 门控线性单元，Kimi K3 用于优化 MoE 路由负载均衡 |
| **YaRN** | 基于 RoPE 的长度外推技术，推理时扩展上下文窗口 |

## 2. 新一代旗舰模型单篇架构解析

### 2.1 Kimi K3（月之暗面 Moonshot，2026-07-27 全量开源）

> **定位**：全球参数规模最大的开源模型，主打超长上下文与 Agent 能力

#### 核心规格

| 项目 | 配置 |
|---|---|
| 架构类型 | **Stable LatentMoE** 稀疏混合专家，Decoder-Only 自回归 |
| 总参数 | 约 **2.78T**（标称 2.8T） |
| 单 Token 激活参数 | 约 **104B**（103B） |
| 网络层数 | **93 层**（其中 1 层稠密层） |
| 注意力组成 | **69 层 KDA + 24 层 Gated MLA** |
| 层排布规则 | `KDA × 3 → Gated MLA × 1` 循环，末尾额外 1 层 MLA |
| 专家配置 | **896 个路由专家**，每 token 激活 **16 个**，另有 **2 个共享专家** |
| 稀疏激活率 | 约 **1.79%**（目前开源旗舰最低稀疏度之一） |
| 激活函数 | **SiTU-GLU**（Sigmoid-Tanh-Unit），配合 Quantile Balancing 解决极稀疏 MoE 负载均衡 |
| 隐藏维度 | 3584 维 latent 空间（routed expert 所在空间） |
| 多模态 | **MoonViT-V2** 视觉编码器（约 401M 参数），原生图文视频统一编码 |
| 上下文窗口 | **1,048,576（1M）Token** |
| 权重格式 | **MXFP4** 权重 / **MXFP8** 激活 |
| 优化器 | — |
| 商用协议 | **Kimi K3 License**（类 MIT 但含商用/MaaS 限制条款，需单独确认） |

#### 架构核心思路

Kimi K3 的设计哲学是 **"用极高稀疏度换取缩放效率"**，相比 K2 整体缩放效率提升约 2.5 倍。两大架构创新：

1. **KDA（Kimi Delta Attention）线性循环注意力**：
   - 传统全注意力的 KV 缓存随序列长度线性增长，百万上下文显存压力巨大
   - KDA 采用循环记忆机制，KV 缓存大小**恒定**，不随序列长度增加
   - 负责长距离信息的高效传递，但线性注意力在精确检索上存在短板

2. **Gated MLA（门控多头潜空间注意力）**：
   - 标准 softmax 全局注意力，定期（每 4 层 1 次）召回全部上下文做精确信息检索
   - 弥补 KDA 线性注意力的检索精度短板
   - 承袭 DeepSeek MLA 的 KV 压缩设计，进一步降低全局注意力层的显存开销

3. **Stable LatentMoE**：
   - 将 routed expert 放在 3584 维 latent 空间中，专家数从 K2 的 384 暴增至 896
   - 每 token 激活 16 个专家（K2 为 8 个），但总参数池扩大近 3 倍
   - 用 RMSNorm、SiTU-GLU 和 Quantile Balancing 解决极稀疏 MoE 的激活爆炸和专家坍缩问题

> **一句话总结**：Kimi K3 = 极端稀疏 MoE（896 专家/1.79% 激活率）+ KDA 循环注意力（KV 恒定）+ 定期 Gated MLA 全局召回，是目前长上下文架构最激进的设计。

### 2.2 Qwen3.8-27B（阿里通义千问，2026-08-14 开源）

> **定位**：消费级显卡可跑的原生多模态稠密模型，主打本地私有化部署与 Agent 能力

#### 核心规格

| 项目 | 配置 |
|---|---|
| 架构类型 | **Dense 稠密** Transformer Decoder-Only（无 MoE，全部参数激活），带视觉编码器 |
| 总参数 | **27B**（计入视觉塔和填充词表后约 **27.8B**） |
| 网络层数 | **64 层** |
| 隐藏维度 | **5,120** |
| FFN 中间层维度 | **17,408** |
| 词表大小 | **248,320** |
| 注意力组成 | **48 层 Gated DeltaNet（线性注意力）+ 16 层 Gated Attention（全注意力）** |
| 层排布规则 | `16 × [3 × (Gated DeltaNet → FFN) → 1 × (Gated Attention → FFN)]` |
| 线性注意力头 | 48 V 头 / 16 QK 头，head_dim = 128 |
| 位置编码 | RoPE（YaRN 外推） |
| 多模态 | **原生图文视频**，视觉编码器与语言模型联合预训练 |
| 原生上下文 | **262,144（256K）Token** |
| 外推上下文 | YaRN 可扩展至 **1M Token** |
| 推理特性 | 支持 `reasoning_effort` 动态推理深度控制（思考/非思考模式切换） |
| 商用协议 | **Apache-2.0**（免费商用） |

#### 架构核心思路

Qwen3.8-27B 走的是 **"高性能稠密 + 混合注意力"** 路线，与 Kimi K3/DeepSeek V4 的 MoE 路线形成鲜明对比：

1. **Gated DeltaNet 线性注意力（48 层，占 75%）**：
   - 属于状态空间/Mamba 家族的线性注意力变体
   - 计算复杂度为 O(n)，KV 缓存不随序列长度线性增长
   - 负责高效处理长序列的大部分层，降低长上下文推理成本

2. **Gated Attention 全注意力（16 层，占 25%）**：
   - 标准 softmax 二次复杂度注意力
   - 每 4 层出现 1 次，负责精确的全局信息检索
   - 弥补线性注意力在需要精确定位信息时的精度损失

3. **纯稠密设计的取舍**：
   - 不采用 MoE，27B 参数全程参与运算
   - 优势：推理延迟稳定、部署简单、无专家负载均衡问题、4-bit 量化仅需约 16.4GB 显存（单张 RTX 4090/5090 可跑）
   - 劣势：知识容量上限受限于 27B，无法像 MoE 模型那样拥有万亿级参数池

> **一句话总结**：Qwen3.8-27B = 27B 纯稠密 + 3:1 混合注意力（Gated DeltaNet 线性 / Gated Attention 全局）+ 原生多模态，是目前单卡 24GB 可部署的最强开源模型之一。

### 2.3 GLM-5.2（智谱 AI / Z.ai，2026-06-13 开源）

> **定位**：编程与长程工程任务专家，MIT 协议开源的 MoE 旗舰  
> **注意**：GLM-5.2 是 **MoE 模型**，并非稠密模型

#### 核心规格

| 项目 | 配置 |
|---|---|
| 架构类型 | **MoE 混合专家**（glm_moe_dsa），Decoder-Only |
| 总参数 | 约 **744B**（含 MTP 块的 checkpoint 约 753B） |
| 单 Token 激活参数 | 约 **40B** |
| 网络层数 | **78 层** |
| 隐藏维度 | **6,144** |
| 词表大小 | **155,000** |
| 专家配置 | **256 个路由专家 + 1 个共享专家**，每 token 激活 **8 个路由专家** |
| 稀疏激活率 | 约 **5.4%** |
| 注意力机制 | **MLA（多头潜空间注意力）+ DSA（稀疏注意力）** |
| DSA 配置 | index_topk = 2048，lightning-indexer 头数 32，head_dim = 128 |
| 归一化 | **RMSNorm Pre-Norm**（Attention 前、MoE 前各归一化一次） |
| 上下文窗口 | **1M Token** |
| 商用协议 | **MIT**（完全宽松，免费商用） |

#### 架构核心思路

GLM-5.2 延续了 GLM-5 系列的 **"自研 DSA 稀疏注意力 + MoE"** 技术路线：

1. **MLA + DSA 双重注意力优化**：
   - MLA（多头潜空间注意力）：承袭 DeepSeek-V3 的设计，将 K/V 低秩压缩到共享潜向量，大幅降低 KV 缓存
   - DSA（DeepSeek Sparse Attention）：通过 lightning-indexer 对 KV 建立索引，每个 query 只对 top-2048 个 KV 条目做注意力计算，避免全量二次复杂度
   - 两者结合，在 1M 上下文下仍能保持较低的显存和算力开销

2. **中等规模 MoE**：
   - 256 专家 / 8 激活的配置，介于 DeepSeek-V3（256/8）和 Kimi K3（896/16）之间
   - 总参数 744B，激活 40B，稀疏率约 5.4%
   - 相比 Kimi K3 的极端稀疏，GLM-5.2 的 MoE 配置更保守、训练更稳定

3. **前 8 层稠密设计**：
   - 据架构分析，GLM-5.2 前若干层采用稠密 FFN，先建立稳定的通用表征基础，再在深层路由到专业专家
   - 这种"稠密前置 + MoE 后置"的设计有助于提升路由质量和整体稳定性

> **一句话总结**：GLM-5.2 = 744B MoE（256 专家/8 激活）+ MLA+DSA 稀疏注意力 + 1M 上下文，MIT 协议，是编程/Agent 场景的开源标杆。

### 2.4 DeepSeek V4-Pro / V4-Flash（深度求索，2026-08 开源）

> **定位**：百万级上下文高效推理，代码与数学推理强项  
> V4-Pro 于 2026-08-13 正式开源；技术报告 arXiv 于 2026-04-24 发布

#### 核心规格

| 项目 | V4-Pro | V4-Flash（0731） |
|---|---|---|
| 架构类型 | **DeepSeekMoE** 稀疏混合专家 | **DeepSeekMoE** 轻量化稀疏混合专家 |
| 总参数 | **1.6T** | **284B** |
| 单 Token 激活参数 | **49B** | **13B** |
| 保留架构 | DeepSeekMoE 框架 + MTP 多 Token 预测 | 同左 |
| 注意力机制 | **CSA（压缩稀疏注意力）+ HCA（深度压缩注意力）混合** | 同左 |
| 残差连接 | **mHC（流形约束超连接）** | 同左 |
| 优化器 | Muon | Muon |
| 后训练 | On-Policy Distillation（领域专家集成蒸馏）替代纯 RLVR | 同左 |
| 上下文窗口 | **1M Token** | **1M Token** |
| 推理深度 | 支持三档可调（Non-think / Think-High / Think-Max） | 同左 |
| 商用协议 | **Apache-2.0**（免费商用） | **Apache-2.0** |

#### 架构核心思路

DeepSeek V4 相比 V3.2 的三大架构升级，目标明确：**把"长上下文"做得既能用、又便宜**。

1. **混合注意力架构（CSA + HCA）—— V4 最核心的贡献**：
   - **CSA（Compressed Sparse Attention）**：
     - 沿序列维度压缩 KV 缓存：每 4 个 token 的 KV 合并成 1 个条目
     - 通过轻量索引器打分，每个 query token 只选 TOP-4 条目做注意力计算
     - 结合 DSA 稀疏检索，大幅降低计算量
   - **HCA（Heavily Compressed Attention）**：
     - 比 CSA 更高倍率的 KV 压缩
     - CSA 与 HCA 交替组成 hybrid attention
   - **实际收益**：在 1M token 上下文下，V4-Pro 仅需 V3.2 的 **27% 单 token 推理 FLOPs** 和 **10% KV 缓存**，算力开销下降约 73%

2. **mHC（流形约束超连接）—— 超深层网络的信号保障**：
   - 传统残差连接在万亿级超深层模型中会出现信号衰减/梯度消失
   - mHC 在流形空间中约束超连接（skip connection）的变换范围
   - 确保深层网络中信息能有效回传，是 1.6T 参数模型能稳定训练的关键

3. **保留并验证的成熟设计**：
   - DeepSeekMoE 框架（V2/V3 已验证）
   - MTP 多 Token 预测训练目标（增强长生成连贯性）
   - Muon 优化器

> **一句话总结**：DeepSeek V4-Pro = 1.6T MoE + CSA/HCA 混合压缩注意力（1M 上下文 KV 仅为 V3.2 的 10%）+ mHC 流形残差，是长上下文效率架构的工程标杆。

### 3.2 架构路线分化

新一代模型清晰地分化为两条技术路线：

**路线 A：超大 MoE + 新型长上下文注意力（云端高算力集群）**
- 代表：Kimi K3（2.8T）、DeepSeek V4-Pro（1.6T）、GLM-5.2（744B）
- 共性：总参数远超稠密模型，激活参数控制在 40B–104B；注意力层都做了针对长上下文的特殊改造
- 差异：
  - Kimi K3 最激进：896 专家 + KDA 循环注意力（KV 恒定），稀疏率仅 1.79%
  - DeepSeek V4-Pro 最工程化：CSA/HCA 压缩注意力（有明确的 10% KV / 27% FLOPs 量化收益）+ mHC 残差
  - GLM-5.2 最保守：256 专家 + MLA+DSA（承袭 DeepSeek-V3 路线），稀疏率 5.4%

**路线 B：高性能稠密 + 混合线性注意力（本地单卡私有化）**
- 代表：Qwen3.8-27B
- 特性：27B 全激活，无 MoE；75% 层用 Gated DeltaNet 线性注意力降低长序列成本；25% 层保留全注意力保证精度
- 优势：部署门槛极低（4-bit 约 16.4GB 显存），推理延迟稳定，无 MoE 路由抖动

### 3.3 注意力机制设计哲学对比

| 模型 | 设计哲学 | 线性/全局注意力配比 | KV 缓存策略 |
|---|---|---|---|
| **Kimi K3** | 循环记忆为主，定期全局召回 | 74% KDA 线性 / 26% MLA 全局 | KDA 层 KV 恒定；MLA 层低秩压缩 |
| **Qwen3.8-27B** | 线性注意力处理大部分层，全注意力每 4 层精确检索一次 | 75% DeltaNet 线性 / 25% 全注意力 | DeltaNet 层 O(n)；全注意力层标准 KV |
| **GLM-5.2** | 统一 MLA 压缩 + DSA 稀疏检索，不引入线性注意力 | 0% 纯线性 / 100% MLA+DSA | MLA 低秩压缩 KV；DSA 只算 top-K |
| **DeepSeek V4** | 压缩稀疏 + 深度压缩交替，不引入线性注意力 | 0% 纯线性 / 100% CSA+HCA | KV 压缩至 V3.2 的 10% |

> **关键观察**：Kimi 和 Qwen 选择了"线性注意力 + 定期全局注意力"的混合路线（类似 Mamba/Transformer 混合），而 DeepSeek 和 GLM 选择了"压缩/稀疏化标准注意力"的路线。前者更激进地改变了注意力计算范式，后者在标准 softmax 注意力框架内做优化，工程风险更低。

## 4. 前代基线模型架构回顾

### 4.1 Kimi K2（月之暗面，2025-07-11 发布）

| 项目 | 配置 |
|---|---|
| 架构类型 | MoE 混合专家（设计类似 DeepSeek-V3） |
| 总参数 | **1T** |

### 4.2 DeepSeek V3 / V3.2（深度求索，2024-12 发布）

| 总参数 | **671B** |
| 激活参数 | **37B** |

| 隐藏维度 | 7,168 |

### 5.1 核心技术点演进表

|---|---|---|---|
| **MoE 稀疏度** | DeepSeek-V3: 5.5%（37B/671B）；Kimi K2: 3.2%（32B/1T）；Llama 4 Maverick: 4.25% | Kimi K3: **1.79%**（104B/2.8T）；DeepSeek V4: ~3.1%；GLM-5.2: ~5.4% | 知识池扩大至万亿级，推理算力成本下降 |

## 6. 架构趋势总结

### 趋势一：云端旗舰全面走向"超稀疏 MoE + 新型长上下文注意力"

2026 年的旗舰开源模型不再无脑堆稠密参数，而是：
- **MoE 稀疏度持续下探**：从 V3 的 5.5% → K2 的 3.2% → K3 的 1.79%
- **专家数量持续增加**：从 256（V3）→ 384（K2）→ 896（K3）
- **注意力从"压缩标准注意力"走向"线性/循环注意力混合"**：Kimi KDA 和 Qwen Gated DeltaNet 代表了 Mamba/状态空间路线与 Transformer 的融合
- **1M 上下文成为标配**：不再是卖点而是及格线

### 趋势二：私有化本地路线深耕"高性能稠密 + 低显存门槛"

- Qwen3.8-27B 证明了 27B 稠密模型可以达到接近旗舰的能力
- 4-bit 量化仅需 16.4GB 显存，RTX 4090/5090 单卡可跑
- 混合线性注意力（75% DeltaNet）让 27B 模型也能高效处理 256K–1M 上下文
- 趋势：**不再追求更大的稠密模型，而是追求"更小但更强"的稠密模型**

### 趋势三：注意力机制呈现"两条路线并行"

| 路线 | 代表 | 核心思想 | 优势 | 风险 |
|---|---|---|---|---|
| **线性/循环注意力混合** | Kimi K3（KDA）、Qwen3.8（DeltaNet） | 大部分层用 O(n) 线性注意力，少部分层保留 O(n²) 全局注意力 | 长序列计算效率极高，KV 缓存可恒定 | 线性注意力检索精度有短板，需精心设计混合比例 |
| **压缩/稀疏化标准注意力** | DeepSeek V4（CSA+HCA）、GLM-5.2（MLA+DSA） | 在 softmax 注意力框架内，通过 KV 压缩和稀疏检索降低成本 | 不改变注意力计算范式，工程风险低，精度有保障 | 压缩/稀疏会引入信息损失，需在压缩率和精度间权衡 |

### 趋势四：原生多模态成为新模型标配

- Kimi K3（MoonViT-V2）、Qwen3.8-27B、Llama 4（Early Fusion）都从预训练阶段就联合训练视觉编码器
- 不再是"语言模型 + 外接视觉编码器"的拼接方案
- 图文视频统一编码，跨模态理解更深入

### 趋势五：推理深度动态调节成为新接口

- Qwen3.8 的 `reasoning_effort`、DeepSeek V4 的三档推理深度
- 同一模型可以在"快速回答"和"深度思考"之间切换
- 用户可以根据任务复杂度和延迟要求灵活选择
