# ARCHITECTURE.md — 企业信息调查 Agent

## 1. 项目定位

面向求职者的企业信息调查 Agent。用户输入企业名称，并可补充意向岗位、城市和关注点；系统并行收集企业的基础主体、规模业务、财务/运营、发展与岗位稳定性、薪酬福利、风险/负面信息，最后给出有证据边界的求职推荐值。

推荐值是“公开信息下的企业就业吸引力”评分，不代替对具体岗位、直属团队或个人匹配度的判断。

## 2. 流水线

```text
企业名称 + 可选求职关注点
            ↓
主 Agent ReAct（单一事实检索 / 企业尽调派发）
            ↓
六个并行子 Agent
  ├─ 基本信息与工商主体
  ├─ 规模与主营业务
  ├─ 财务与运营指标
  ├─ 发展前景与岗位稳定性
  ├─ 薪酬福利与工作体验
  └─ 司法、监管与权威媒体风险核验
            ↓
主 Agent 生成带来源、信息缺口和评分依据的尽调报告
```

明确的单一事实提问可直接使用 `web_search`。其他企业名称、企业调查、公司评价或求职参考请求都会由运行时编排保护强制调用一次 `dispatch_subagents`，不依赖模型是否遵守提示词；若拆题不足六项，`build_company_subtopics` 会回退到六个必查维度，防止遗漏薪酬福利或风险核验。

## 3. 核心模块

| 模块 | 职责 |
| --- | --- |
| `src/agents.py` | 企业调查提示词、六维拆题回退、并行调度、失败降级和报告评分规则 |
| `src/react_loop.py` | 主/子 Agent 共用 ReAct 循环与 trace 捕获 |
| `src/tavily_search.py` | Tavily 检索、查询校验和带 URL 的来源证据格式化 |
| `src/llm_client.py` | 延迟初始化的 DeepSeek OpenAI 兼容客户端及重试 |
| `src/config.py` | 自动加载项目根目录 `.env`，并保持系统环境变量优先 |
| `src/serve.py` | FastAPI + SSE，传递主从步骤、派发事件和最终报告 |
| `static/index.html` | 企业调查输入、动态拓扑、实时 trace 与最终报告展示 |
| `tests/test_company_agent.py` | 六维覆盖、输入边界、来源 URL 和派发统计单元测试 |

## 4. 证据、风险和评分原则

1. 优先公司官网、年报/招股书、交易所公告、监管/法院、招聘官网及可信媒体。
2. 每条关键结论应带来源编号和 URL，并说明披露或访问时间。
3. 非上市、未披露企业的营收、利润、现金流必须明确“公开信息未披露”；融资、招聘、门店等只能作为代理指标。
4. 风险信息区分生效处罚/判决、进行中的案件和待核验报道；传闻和单方投诉不得被描述为事实。
5. 求职推荐值满分 100：经营稳健性 30、业务与成长性 20、薪酬福利 20、雇主体验 15、合规与风险 15。信息不足时保守给分并标注无法判断。

## 5. 可观测性与容错

- 每个 ReAct 步骤记录 Thought、Action、Action Input 和 Observation，前端可按节点查看。
- 主 Agent 将并行核验摘要以 4,800 字符上限回灌模型，确保六个维度都能参与综合，同时避免无限增长的上下文。
- 通过 `ThreadPoolExecutor` 并行运行独立维度；返回 `wall_clock`、`serial_sum` 和 `speedup` 供演示与基准测试使用。
- 子 Agent 失败时只标记该维度未完成，其余维度仍会汇总；服务和外部请求日志只记录关联 ID、长度、数量和错误类型，不记录密钥或原始调查内容。
- 页面在写入模型与检索返回文本前进行 HTML 转义，避免把外部文本作为页面标记执行。

## 6. 已知边界

公开搜索不能保证信息完整、实时或适用于某个团队。薪资、加班、团队氛围和岗位稳定性应在面试中向招聘方和未来直属负责人进一步核实；负面信息应回到原始公告、裁判文书或权威报道确认。
