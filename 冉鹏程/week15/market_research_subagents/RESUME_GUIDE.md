# RESUME_GUIDE.md — 项目表述参考

## 项目名称

**企业信息调查 Agent（求职参考）** ｜ 手写 ReAct · DeepSeek · Tavily · FastAPI · SSE

## 算法/Agent 方向

> 设计企业信息调查多 Agent 系统：主 Agent 按问题自主路由，单一事实直接检索，企业尽调派发六个子 Agent 并行核验工商主体、规模业务、财务/运营、发展稳定性、薪酬福利和风险信息。建立带 URL 的来源证据链、未披露信息标记和风险事件分级规则，并以经营稳健性、成长性、薪酬福利、雇主体验、合规风险五项合成 100 分求职推荐值；完整保存节点级 ReAct trace 供可观测性分析。

## 后端/AI 应用方向

> 基于 FastAPI + SSE 构建企业调查服务，实时推送主从 Agent 的步骤、派发拓扑、子任务状态和最终尽调报告。使用 ThreadPoolExecutor 并行执行独立核验任务，支持串行基准模式；针对外部输入加入长度校验，来源文本保留 URL，并在前端对模型和检索返回内容进行 HTML 转义，避免未受信任文本直接进入 DOM。

## 面试提示

**为什么企业调查必须区分“已证实”和“待核验”？**

公开网络信息存在时间差、转述误差和单方叙述。系统优先使用官方、监管、法院和交易所来源；对于投诉、传闻、未决案件或无原始来源的媒体转载，报告只描述其待核验状态，不将其作为扣分事实。

**推荐值能否替代求职决策？**

不能。它只总结公开信息下的企业层面参考，无法覆盖直属团队、具体岗位薪资、业务优先级和个人偏好。报告会同时输出面试中需要确认的问题。
