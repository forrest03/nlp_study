# 核心原则
1. 按任务复杂度与执行者能力匹配分配，确保高效完成。
2. 每个任务完成后必须评估并统计等级：S(优秀)/A(良好)/B(一般)/C(较差)/D(差)。
   - S: 高效优质, 主动发现问题并改进, 能协助他人。
   - A: 按时高质量完成, 态度积极, 有改进建议。
   - B: 完成但效率质量待提高。
   - C: 时间长质量差, 需他人协助。
   - D: 不达标, 态度消极, 需管理者推动与他人大量协助。
3. 分配时需补全任务信息：描述、目标、完成标准、完成时间、优先级、难度、能力要求、执行者数量。
4. 全部任务记录写入项目根目录 `tasks.xlsx`（无则创建），含三个长期维护 Sheet：任务汇总、执行者档案、评估汇总。

# 任务分配算法

## 流程
1. **需求解析**：提取角色/技术栈/最低级别/难度/优先级，缺失则追问。
2. **硬条件筛选**（全满足才入候选）：角色匹配、级别≥要求、技术栈有交集、状态为可用。
3. **负载检查**：剔除在途任务数已达上限者。
4. **综合评分**：按公式计算，降序排列。
5. **分配决策**：最高分为主负责人；多人任务按顺位补协作者；同分选在途少、S级占比高者；无候选则提示能力缺口。

## 评分公式
综合评分 = 能力匹配×0.4 + 负载余量×0.2 + 历史绩效×0.3 + 难度适配×0.1

- **能力匹配** = 技术栈命中率×60 + 擅长领域命中率×40（命中率=交集数÷要求数）
- **负载余量** = (最大并发−当前在途) ÷ 最大并发 × 100
- **历史绩效** = 加权均值（S=100,A=85,B=70,C=50,D=30）；无历史取 75
- **难度适配**：高级→高难100/复杂90/中等75/简单60；中高级→复杂95/中等90/简单70；中级→中等90/简单85/复杂60；初级→简单90/中等70/复杂40

## 决策约束
- 复杂/高难任务主负责人须中高级及以上，初级仅作协作者。
- P0/P1 主负责人须历史绩效分≥80 且负载余量>0。
- 最大并发：中高级/高级默认2，初级/中级默认1，可调整。
- 分配后在途+1；完成或取消−1。

# 负载管理
- 在途负载 = 进行中任务数；达上限者排除出候选。
- 全员或某角色全员过载时提示资源瓶颈。
- 同等匹配下优先在途少者，避免任务集中。

# 执行者变更流程
- **新增**：收集姓名/角色/级别/技术栈/擅长领域/并发数/态度 → 写入档案Sheet（在途0、统计0、状态可用）→ 追加本文件档案表。
- **能力变更**：级别晋升/技术栈扩充/并发调整 → 同步更新档案Sheet与本文件 → 记录变更。级别变更同步调整默认并发数。
- **离场/休假**：状态改休假/离场立即排除出候选；休假者任务暂挂或转交协作者，离场者全部重新分配；按转交结果调整在途数。

---

# 评估与持久化
- 任务完成时给 S/A/B/C/D 评级及说明。
- **三处同步写入**：①任务汇总Sheet对应行的评估等级/说明列；②评估汇总Sheet追加一行；③执行者档案Sheet对应列+1、累计任务数+1。
- 完成评估后在途−1。
- 校验：执行者档案各级数之和 = 累计任务数 = 评估汇总中该执行者记录数。
- 评估结果进入历史绩效分，反哺后续分配。
